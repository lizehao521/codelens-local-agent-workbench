# 自主扩展题源

> 状态：已实现（`scripts/propose-gaps.ts` + `scripts/author-task.ts`），由 `scripts/self-upgrade-loop.ts` 在题源耗尽时自动调用。
> 前提：失败归因分层（见 `rsi-failure-attribution.md`）——没有归因，提议就没有依据，只能随口编。

---

## 1. 要解决的是什么

循环跑到「没有待办题目」时，原来的行为是打印一句「题源需要人工补」然后退出。

它已经有的东西很齐：会改自己的源码、有外置判据当尺子、会机械归因失败、会自己管服务生命周期。
唯独不会自己找活干——**而找活干恰恰是让它从「一次性工具」变成「持续系统」的那一环**。

风险同样具体：一旦让被衡量者自己决定「下一道题考什么」，它就会挑自己会做的题，
挑自己做得好的判据。外置判据的全部意义（尺子在它够不到的地方）会被这一步抵消。

## 2. 职责切分

```
     被衡量者                循环                 出题人                人
   ┌──────────┐        ┌──────────┐         ┌──────────┐       ┌────────┐
   │ 提名缺口  │──────▶│ 写进     │────────▶│ 写判据   │──────▶│ 采纳   │
   │ 只说缺什么│  文本  │ proposals│  提议   │ +模板断言 │ 候选  │ 进仓库 │
   │ 不写文件  │        │ .jsonl   │         │          │ 文件  │        │
   └──────────┘        └──────────┘         └──────────┘       └────────┘
     它够不到                它够不到             它够不到         落库后
   proposals.jsonl        tests/ 与 tasks.json   tests/          受指纹保护
```

四条硬边界，每一条都由结构保证而不是靠提示词：

1. **它不产出判据。** 提议 schema 里根本没有 `judge` / `allowed` 字段的位置——
   不是「提示词里说不许写」，是**无处可写**。
2. **它不写任何文件。** 它只输出文本，提议由**循环**写进 `.self-upgrade/proposals.jsonl`。
   那个目录在沙箱根之外（沙箱根 = `server/`），它自己写不到。
3. **判据由独立出题人写。** 出题人看到的是提议本身与靶子的**导出签名**，看不到实现。
4. **候选不进仓库。** 出题产物落在 `.self-upgrade/loop/candidates/`，采纳才写进
   `tests/self-upgrade/` 与 `self-upgrade/tasks.json`；落库后判据即受围栏指纹保护，
   **Agent 改一个字符，这道题就作废**。

## 3. 提议长什么样

```json
{
  "id": "kebab-case-短标识",
  "title": "一句话说清缺口",
  "gap": "现在做不到什么，做到后能做什么",
  "evidence": ["支撑这个缺口的现象，尽量引用刚经历过的具体失败"],
  "targetFile": "src/ 下真实存在的文件路径",
  "observable": "怎么看出它修好了：哪个输入、期望什么结果",
  "boundary": "这条不能碰什么"
}
```

### 机械筛（`screen()`）

只挡三类废提议，不判断「提议好不好」——那是出题环节和人的事：

| 筛掉 | 理由 |
| --- | --- |
| `targetFile` 不在 `src/` 下 | 没法改 |
| `targetFile` 在 `tests/` `krsi/` `src/services/judge|rsi|eval/` `scripts/` 下 | 那是改尺子 |
| `targetFile` 不存在 | 指了个不存在的地方 |
| `evidence` 为空 | 没有证据的「缺口」是想象的 |
| `id` 重复 | 重复提议 |

### 提示词里给的输入（这就是闭环）

1. **现在的工具清单**（来自运行中的服务，`GET /api/v1/tools`）——它得知道手里有什么。
2. **最近的失败归因聚合**（来自账本，按层/按码聚合）——**这是关键**：
   它知道上一轮卡在「行为层空转」还是「资源层预算耗尽」，
   于是提的缺口会指向真正的短板。
3. **已经做过的题**——避免重复提名同一件事。

## 4. 出题：模型写行为断言，模板补安全断言

完全交给模型写判据不行——模型可能写出一份「只检查文件存在」的弱判据，
于是「升级成立」变成一句空话。所以判据由两部分拼成：

| 部分 | 谁写 | 内容 |
| --- | --- | --- |
| 行为断言 | 出题人模型（默认 `gpt-4o`，与被衡量者不同模型） | 针对 `observable`：给定输入期望什么输出 |
| **通用安全断言** | **固定模板，不经模型** | ① 必须导出命名约定的对象 ② 必须注册进 `BUILTIN_TOOLS` ③ 非法输入必须被拒且不得越出沙箱 |

**模型可以偷懒，但偷不掉底线**——模板那部分永远在。

判据草案还有一道机械 lint（`judgeLint()`）：必须有 vitest 导入、至少 3 条断言、
不许 `skip/todo/only`、不许 import 目标模块以外的业务模块、必须引用目标模块。
不过 lint 就不采纳。

## 5. 与失败归因的闭环

```
归因分层  ──►  账本（layer/code）  ──►  failure-stats 聚合
                                          │
                                          ▼
                              propose 的输入之一（"你卡在哪层"）
                                          │
                                          ▼
                                     下一个缺口
```

这是「从失败中沉淀学习信号」的具体形态：归因不只决定**这一轮怎么重试**
（换模型 / 拆题 / 停机），还决定**下一轮考什么**。

没有归因的时候，提议只能是随口编；有了归因，提议会指向「我上次是怎么卡住的」。

## 6. 跑法

```bash
# 独立提一次（服务不在会自己起一个）
npx tsx scripts/propose-gaps.ts

# 由出题人把提议转成判据草案（产物在 .self-upgrade/loop/candidates/）
npx tsx scripts/author-task.ts --only=<id>

# 采纳：把 <id>.test.ts 拷进 server/tests/self-upgrade/，
#      把 <id>.spec.json 并入 server/self-upgrade/tasks.json
# 之后循环就会自动跑这一题

# 循环题源耗尽时会自动提议（--no-propose 可关）
npx tsx scripts/self-upgrade-loop.ts
```

## 7. 已登记的边界

1. **采纳仍然是人工动作。** 提议与判据草案都能自动生成，但「这道题该不该考」由人点。
   有意为之：把「题的来源」和「被衡量的对象」重新混到一起，正是外置判据要防的事。
2. **出题人模型仍可能被讨好。** 缓解是「出题人与被衡量者不同模型」+「模板安全断言」+
   「判据落库后受指纹保护」，但**没有消除**——出题人若与被衡量者共享偏好，仍可能写出偏松的行为断言。
   更彻底的做法是让出题人只做**规则化转换**（从 `observable` 生成固定形状的断言），
   代价是只能覆盖结构化的缺口。这一步没做。
3. **`targetFile` 必须是已存在的文件。** 所以「新增一个能力」这类缺口无法自动立项——
   它要么挂在某个已有文件上，要么由人先建好空文件。
4. **提议质量没有机械下限。** 筛子只挡废提议（指错路径、没证据），
   「这个缺口值不值得考」仍由出题环节和人的判断承担。

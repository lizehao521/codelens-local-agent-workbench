# 测试用例生成

> 用例的敌人是"只测正常路径"——边界与异常才是缺陷高发地。

## 何时使用

- 新功能完成，需要配套测试。
- 存量代码缺测试，需要补齐并提升覆盖率。
- 需要还原/复现某类缺陷的输入条件。

## 执行流程

1. **识别被测单元** —— 确定函数/接口/模块的输入、输出、职责。
2. **划分等价类 + 边界值** —— 把输入空间划分为有效/无效等价类，找出边界点（空、最大/最小、刚好越界）。
3. **生成用例** —— 每个关键输入写「正常 / 异常 / 边界」三类用例，含期望结果。
4. **补断言** —— 断言明确到"期望值/期望异常"，避免只测不崩。
5. **执行与测覆盖率** —— 跑用例，看行/分支覆盖率，补齐未覆盖分支。

## 输入 / 输出

| 输入 | 输出 |
| --- | --- |
| 函数/接口签名 + 逻辑 | 测试用例清单 |
| 现有测试 | 正常/异常/边界用例 + 断言 |
| 覆盖率目标 | 覆盖率报告 |

## 关联思维策略

- **预判验证** —— 先预测"会在哪出错"，针对性造输入。
- **对比分析** —— 与历史缺陷/同类实现对比，补遗漏场景。

## 基因库记录

- **类型**：pattern
- **复用经验**：边界与异常至少占用例一半；每个用例都带明确期望值；覆盖率优先补分支而非凑行数。
- **可复用性**：高 —— 通用。
- **入库自检**：用户选择 ✅ / 适应度前 100 ✅ / 可复用 ✅

## 示例

### 场景：为登录校验函数写用例

1. 单元：`authenticate(user, pass)` → 返回 token 或抛错。
2. 等价类：空 user / 空 pass / 超长输入 / 非法字符 / 正常账号密码。
3. 用例：正常登录、空值抛错、错误密码抛错、SQL 注入串不生效。
4. 结果：8 条用例覆盖正常/异常/边界，分支覆盖率 96%。

## 安全与回滚

- **透明**：用例与期望值全部显式。
- **可控**：生成只产出用例，不擅自改被测代码。
- **可逆**：用例文件版本化，可回退。
- **渐进**：先核心路径，再边界异常，再清覆盖率。
- **用户主导**：哪些场景必须覆盖由用户确认。

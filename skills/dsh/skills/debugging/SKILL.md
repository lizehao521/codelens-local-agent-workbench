# 调试排障

> 先复现、再假设、后验证——不靠"顺手改一处试试"。

## 何时使用

- 程序报错 / 崩溃 / 结果不对。
- 测试能稳定复现一个缺陷。
- 线上偶发问题需要定位。

## 执行流程

1. **复现与最小化** —— 稳定复现，把输入缩到最小可触发样例。
2. **收集证据** —— 日志、堆栈、状态、版本，一并归拢。
3. **假设根因（5Why）** —— 从现象逐层追问，列出候选根因。
4. **定位最小改动** —— 用预判验证法确认根因，锁定改动点。
5. **修复并回归** —— 改一处、跑回归，确认不引入新问题。
6. **记录根因与预防** —— 沉淀为 pitfall/lesson，防同类复发。

## 输入 / 输出

| 输入 | 输出 |
| --- | --- |
| 报错信息 / 复现步骤 | 根因定位 |
| 日志 / 堆栈 | 最小修复 + 回归结论 |
| 相关代码 | 预防措施（入库） |

## 关联思维策略

- **5Why** —— 从症状追到根因。
- **对比分析** —— 与正常路径 / 历史版本对比，缩小范围。
- **预判验证** —— 每次改动前先想"改了能验证什么"。

## 基因库记录

- **类型**：pattern
- **复用经验**：先能复现再动手；一次只改一个变量；修完必记录根因并入库 pitfall。
- **入库自检**：用户选择 ✅ / 适应度前100 ✅ / 可复用 ✅

## 示例

接口 500 → 复现最小请求 → 堆栈指向 N+1 查询 → 根因：循环内发请求 → 改批量 → 回归通过。

## 安全与回滚

- **透明 / 可控 / 可逆 / 渐进 / 用户主导**：改动前快照，修复可回退，破坏性排查由用户确认。

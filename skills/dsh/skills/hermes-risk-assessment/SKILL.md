# 风险评估

> 先假设"它已经失败了"，倒推失败原因，再决定如何防。

## 何时使用

- 一项方案 / 改动 / 上线动手之前。
- 需要给决策者呈现"风险有多大、值不值得"。
- 为系统设计多级降级与应急预案。

## 执行流程

1. **识别风险** —— 头脑风暴 + 预尸检：假设失败已发生，倒推所有可能原因。
2. **量化** —— 对每条风险估算「发生概率 × 影响程度」。
3. **分级矩阵** —— 依概率×影响落入「高/中/低」，高概率高影响优先处理。
4. **缓解与降级** —— 逐条给出规避、转移、减轻、接受四类策略，明确触发条件。
5. **监控指标** —— 定义能提前暴露风险的观测点与阈值。

## 输入 / 输出

| 输入 | 输出 |
| --- | --- |
| 方案 / 改动 / 系统描述 | 风险清单（概率×影响 矩阵） |
| 可接受的损失上限 | 缓解 + 降级 + 应急措施 |
| 历史事故/教训 | 监控指标 |

## 关联思维策略

- **预尸检** —— 逆向思维：从"已失败"往回推。
- **红队演练** —— 主动找攻击面与薄弱点。
- **SWOT** —— 兼顾外部威胁与内部弱点。

## 基因库记录

- **类型**：lesson
- **复用经验**：每条风险必须落到「概率×影响 + 缓解 + 监控」，否则只是吓人清单。
- **可复用性**：高 —— 通用。
- **入库自检**：用户选择 ✅ / 适应度前 100 ✅ / 可复用 ✅

## 示例

### 场景：进化引擎依赖 LLM API

1. 识别：API 中断 / 限流 / 涨价 / 离线。
2. 量化：概率中、影响高 → 高风险。
3. 缓解：多提供商路由 + 本地模型兜底（L4 降级）+ 单次预算上限。
4. 监控：API 错误率、单次成本、响应时长。

## 安全与回滚

- **透明**：风险与假设全量列出。
- **可控**：评估只读，不触发任何变更。
- **可逆**：结论可随新信息重估。
- **渐进**：先评估高优先级项，再补全其余。
- **用户主导**：是否接受风险、接受哪一级降级由用户决定。

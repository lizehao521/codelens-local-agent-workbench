# 调试排障

> 先复现、再假设、后验证——不靠"顺手改一处试试"。

## 何时使用

- 程序报错 / 崩溃 / 结果不对。
- 测试能稳定复现一个缺陷。
- 线上偶发问题需要定位。

## 执行流程

1. **复现与最小化** —— 稳定复现，把输入缩到最小可触发样例。
2. **收集证据** —— 日志、堆栈、状态、版本，一并归拢。
3. **假设根因（5Why）** —— 从现象逐层追问，列出候选根因。
4. **定位最小改动** —— 用预判验证法确认根因，锁定改动点。
5. **修复并回归** —— 改一处、跑回归，确认不引入新问题。
6. **记录根因与预防** —— 沉淀为 pitfall/lesson，防同类复发。

## 输入 / 输出

| 输入 | 输出 |
| --- | --- |
| 报错信息 / 复现步骤 | 根因定位 |
| 日志 / 堆栈 | 最小修复 + 回归结论 |
| 相关代码 | 预防措施（入库） |

## 关联思维策略

- **5Why** —— 从症状追到根因。
- **对比分析** —— 与正常路径 / 历史版本对比，缩小范围。
- **预判验证** —— 每次改动前先想"改了能验证什么"。

## 基因库记录

- **类型**：pattern
- **复用经验**：先能复现再动手；一次只改一个变量；修完必记录根因并入库 pitfall。
- **入库自检**：用户选择 ✅ / 适应度前100 ✅ / 可复用 ✅

## 示例

接口 500 → 复现最小请求 → 堆栈指向 N+1 查询 → 根因：循环内发请求 → 改批量 → 回归通过。

## 安全与回滚

- **透明 / 可控 / 可逆 / 渐进 / 用户主导**：改动前快照，修复可回退，破坏性排查由用户确认。

## 工具对齐（当前异结构工具面）

- log-rule-checker —— check(lines, rules)：按声明规则集定位违规行+ruleId+具体值，先让规则替你筛日志。
- concurrency —— checkStates(stateLog)：N 次最终状态做一致性判定，发散按运行索引列出供二分。
- test-runner —— run() 真执行复现，超时=TIMED-OUT 不猜；tap() 解析测试流。

## 前提与边界

- 执行流程第 5 步「修复并回归」与工具对齐的 test-runner：前提是**测试真有牙齿**（真注册并执行了断言）。零注册的测试文件 `node --test` 也判绿，绿不能当回归通过（实测：`node --test hermess/test/metrics.test.mjs` → `tests 1 / pass 1 / fail 0`、退出码 0，而实际执行断言 0 条；本仓 `hermess/test/*.test.mjs` 64 个文件全部 `export tests`、无一 `import node:test`，断言只在真 harness `run-all.mjs` 读 `mod.tests` 时才跑）。

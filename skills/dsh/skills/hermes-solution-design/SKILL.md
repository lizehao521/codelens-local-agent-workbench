# 方案生成

> 不追求"一个答案"，而是生成 N=3 个候选，让 6 维适应度评分与用户选择来收敛。
> 本文档的评分口径、策略库与基因沉淀动作，与 hermess 引擎（fitness / strategies / genome）逐一对齐。

## 何时使用

- 问题没有唯一正确答案，需要多角度探索。
- 已有方案不满意，想要"换个思路"。
- 需要把问题拆解后生成可对比的多个方案。

## 执行流程

1. **需求澄清** —— 确认目标、约束、边界与成功标准。
2. **生成候选（N=3）** —— 用策略库中不同分类的策略组合分别生成互有差异的候选，避免同质。
3. **策略注入** —— 为每个候选标注其使用的思维策略与推理链（候选必须"跨分类有差异"，否则排名无意义）。
4. **适应度评分（6 维，优度语义）** —— 对每个候选按 6 维打 0–100 的"优度"分（分越高越好）。
5. **竞技场排名** —— 按加权总分排序，给出每个候选的优劣说明。
6. **用户选择** —— 把最终决定权交还用户，选中方案进入执行。

## 评分口径（6 维，优度语义，越高越好）

> 与引擎 hermess/plugins/fitness.mjs 的 DIMENSIONS 精确一致。risk 是"安全裕度"（越高越安全），cost 是"廉价度"（越高越省）；把风险/成本当"越低越好"会让名次颠倒。

| 维度 | 权重 | 语义（0–100，越高越好） |
| --- | --- | --- |
| 可行性（feasibility） | 25% | 越可行越高 |
| 效果预期（effect） | 25% | 效果越强越高 |
| 风险安全裕度（risk） | 20% | 越安全越高 |
| 成本廉价度（cost） | 15% | 越省越高 |
| 创新性（novelty） | 10% | 越新越高 |
| 可回滚性（rollback） | 5% | 越可逆越高 |

加权总分 = 各维度分 × 权重求和。权重固定，保证跨轮可比。

## 硬规则（违规即抛错）

- **缺维度不打分**：评分必须 6 维齐全；缺一维即抛错，绝不猜默认值 / 静默补 0。
- **越界即报错**：任一分值必须在 0–100 内，越界即抛错。
- **权重固定不漂移**：6 维权重复用上表，不得局部调整，否则跨轮不可比。
- **候选跨分类有差异**：同分类策略产出的候选视为同质，须换分类重生成。

## 策略库（26 策略 · 5 类）

> 与引擎 hermess/plugins/strategies.mjs 一致。候选生成按任务关键词做**确定性**匹配取策略；无任何关键词命中时走默认保底：**第一性原理 + 最小可行行动**（确定性，不随机）。

| 类别 | 策略 |
| --- | --- |
| 输入吸收（5） | SQ3R阅读法、费曼技巧、康奈尔笔记、思维导图、主动回忆 |
| 思维加工（7） | 第一性原理、六顶思考帽、SWOT分析、5Why根因、对比分析、归纳推理、演绎推理 |
| 创新创造（6） | SCAMPER、逆向思维、类比思维、随机输入、形态矩阵、头脑风暴 |
| 验证巩固（4） | 预判验证、红队演练、间隔重复、同行评审 |
| 决策输出（4） | 决策矩阵、成本收益分析、预尸检、最小可行行动 |

## 基因库沉淀（对齐 hermess 基因契约）

生成的候选与最终选择，按 hermess/lib/genome.mjs 契约入库：

- **类型（5）**：strategy / pattern / architecture / lesson / pitfall —— 方案本身记 pattern，可复用的生成方法记 strategy。
- **字段**：id、type、title、body、provenance（来源）、source、fitness（0–100）、status、history。
- **来源纪律（判据 C1）**：入库必须带 provenance，取 weight / probe / execution / cross-check 之一；**缺来源不收，直接抛错**。模型自述只能产生 status=unverified 的基因，**绝不自动注入**；只有真实执行证据才转 active。
- **沉淀动作**：用户选中方案 → 执行 → 结果按上述 schema 写入基因库，fitness 随执行结果 reinforce 强化/削弱。

## 输入 / 输出

| 输入 | 输出 |
| --- | --- |
| 目标 / 约束 / 成功标准 | N=3 候选方案 |
| 26 策略库 + 确定性匹配 | 逐方案 6 维适应度评分 + 排名 |
| 基因库历史模式（active 基因） | 推荐结论 |

## 示例

### 场景：为 48 个重复脚本生成整合方案

1. 澄清：目标减重复、提复用；约束不改外部行为。
2. 生成 A / B / C 三案（跨分类取策略）：
   - A 仅去重 —— 策略：最小可行行动（决策输出）。
   - B 提库 + 统一接口 —— 策略：对比分析（思维加工）+ 成本收益分析（决策输出）。
   - C 提库 + 统一接口 + 智能匹配 —— 策略：类比思维（创新创造）+ 形态矩阵（创新创造）。
3. 评分（6 维优度 0–100）：C 在可行性 / 创新性 / 可回滚性占优，经排名第一。评分含 6 维分解与依据，非单一总分。
4. 用户选 C → 执行 → 结果按基因契约写库（type=pattern，provenance=execution）。

## 安全与回滚

- **透明**：每个候选给出 6 维评分明细与依据。
- **可控**：生成阶段无副作用，执行才落地。
- **可逆**：执行前留快照（git-snapshot / 文件级 manifest），可回滚。
- **渐进**：先小范围试点候选，验证后再规模应用。
- **用户主导**：最终方案由用户选择，不自动择一执行。

## 禁止事项

- 不把 risk 当"越低越好"、不把 cost 当"越高越贵"——6 维统一优度语义，越高越好。
- 不猜默认值：缺维度 / 越界不静默补 0，必须抛错。
- 不改权重：权重是跨轮可比性的契约，漂移即废。
- 不出来源不明的基因：自述基因不打 active，不自动注入。
- 不自动择一执行：候选评定后必须等用户选择。

## 一句话口令

> 先澄清约束、再取 26 策略交叉生成、六维优度越高越好、缺维度即抛错、无来源不入库、最后交还用户选。

# 复盘总结

> 复盘的价值不在"总结文"，而在"下一次怎么做不同"。

## 何时使用

- 一项工作 / 迭代 / 项目收尾。
- 出现事故或明显偏差，想避免重演。
- 周期性沉淀个人或团队经验。

## 执行流程

1. **回顾目标与结果** —— 目标是什么、实际结果如何。
2. **摆事实** —— 只列"做了什么 / 效果如何"，先不评判。
3. **分析差异（5Why）** —— 结果与目标的差距，追根因。
4. **提炼经验与教训** —— 分成 lesson（要做）与 pitfall（别做）。
5. **定下一步行动** —— 明确谁、何时、做什么。
6. **入库** —— 把可复用的经验写入基因库。

## 输入 / 输出

| 输入 | 输出 |
| --- | --- |
| 目标 / 过程记录 / 结果 | 结构化复盘文档 |
| 相关数据 | 经验与教训清单 |
| 团队反馈 | 下一步行动 |

## 关联思维策略

- **预尸检** —— 反向问"如果重来会怎么失败"，找盲点。
- **5Why** —— 追差异根因。
- **康奈尔笔记** —— 主区事实、边栏要点、底部行动。

## 基因库记录

- **类型**：lesson
- **复用经验**：先摆事实再评判；每条教训必须落到"下一次怎么做"；能入库的经验立即入库。
- **入库自检**：用户选择 ✅ / 适应度前100 ✅ / 可复用 ✅

## 示例

迭代复盘：目标准时上线 → 实际延期 3 天 → 5Why 定位到需求变更多 → 教训：变更前置窗口 + 行动项。

## 安全与回滚

- **透明 / 可控 / 可逆 / 渐进 / 用户主导**：只读回顾，结论与行动由用户确认。

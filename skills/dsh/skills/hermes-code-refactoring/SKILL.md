# 代码重构

> 先清理结构，再提取公共库，最后叠加智能层。—— 源自 pattern-001（Hermes PortSwigger 脚本库进化）

## 何时使用

- 存在大量结构相似、仅细节不同的重复文件 / 函数。
- 一个模块承担过多职责，难以理解与测试。
- 不同入口各自实现同一逻辑，出现多处复制粘贴。
- 需要为后续扩展建立统一的 API 或基础类。

## 执行流程

1. **现状盘点** —— 列出全部文件/函数，标注重复度、依赖、调用关系，形成清单。
2. **先清理结构** —— 归档废弃/历史代码（如 `cleanup_archive`），不直接删除，保持可回滚。
3. **再提取公共库** —— 归纳重复逻辑，抽出公共函数/基础类（如 `lib/`、`tools/`），统一实现。
4. **统一 API** —— 让各调用方通过同一入口访问，收敛参数与返回值约定。
5. **最后叠加智能层** —— 在稳定基座上增加策略匹配、自动路由、配置化等高级能力。
6. **回归验证** —— 跑测试 + 对比重构前后行为，确认功能等价。

## 输入 / 输出

| 输入 | 输出 |
| --- | --- |
| 代码目录 / 重复片段清单 | 重构后的目录结构 + 公共库 |
| 重构目标（去重/解耦/统一接口） | 变更说明 + 前后行为对比 |
| 既有测试 | 回归测试结果 |

## 关联思维策略

- **第一性原理** —— 剥离"只是包装不同"的表象，回到功能本质再归类。
- **归纳推理** —— 从多个重复实现中归纳出通用逻辑。
- **SCAMPER** —— 用"合并/消除/重排"找重构切入点。
- **类比思维** —— 参照成熟库/框架的目录与接口设计。

## 基因库记录

- **类型**：pattern
- **复用经验**：先清理结构，再提取公共库，最后叠加智能层；不直接删除旧代码，先归档保回滚。
- **可复用性**：高 —— 适用于任何重复脚本/模块集合的整合。
- **入库自检**：用户选择 ✅ / 适应度前 100 ✅ / 可复用 ✅

## 示例

### 场景：48 个重复脚本 → 3 个核心文件

1. 盘点：48 个脚本，同一套请求/解析逻辑重复 40+ 处。
2. 清理：旧脚本移入 `cleanup_archive`。
3. 提库：抽象 `PortSwiggerAPI`（统一请求）+ `LabSession`（统一会话）。
4. 智能层：新增策略匹配引擎，6 种攻击策略自动识别。
5. 结果：代码量 -85%，新增可复用基础类与智能匹配能力。

## 安全与回滚

- **透明**：每次结构性变更给出清单与理由。
- **可控**：分步执行，每步可由用户确认/中断。
- **可逆**：重构前 Git 快照，一键回滚。
- **渐进**：先小范围验证，再全量推广。
- **用户主导**：删除/归档范围由用户最终决定。

## 工具对齐（当前异结构工具面）

- code-audit —— 重构前先 dup() 拿重复组、stats() 拿行数、untested() 拿无测试模块，用事实圈定重构面，不靠感觉。
- git-snapshot —— 动手前 snapshot 留回滚点；diff(两点间) 看改动面；改坏 restore 回退。
- test-runner —— 每步重构后 run() 真跑回归，失败即回退该步。
- code-audit dup() 只做整文件哈希：函数级复制粘贴完全失明（实测 hermess/lib 里 7 份取整函数副本、3 个唯一实现体，dup() 报 0 组重复）。要查函数级重复得自己抽实现体比对。
- code-audit untested() 会全量误报：真有测试的文件（metrics.mjs）也报「无测试」——它的列表只能当线索，逐条复核后再定重构面。
- code-audit stats 对 .md 报 totalLines=0（真值 71 LF）：非代码文件的统计值不可信，别拿它当基线。

## 前提与边界

- 执行流程第 6 步「回归验证」把跑测试当行为等价证据：前提是**测试真有牙齿**。零注册的测试文件 `node --test` 也判绿，重构改坏行为不会有任何红灯（实测：`node --test hermess/test/metrics.test.mjs` → `tests 1 / pass 1 / fail 0`、退出码 0，实际执行断言 0 条；本仓 64 个测试文件全部 `export tests`、无一 `import node:test`，断言只在真 harness `run-all.mjs` 里跑）。

# 数据提取与清洗

> 先识别结构，再解析，最后校验——脏数据的问题靠"校验"兜底，不靠"猜"。

## 何时使用

- 需要从文档 / 表格 / 日志中抽取结构化字段。
- 多来源数据需要归一化、去重、统一口径。
- 数据存在矛盾/缺失，需要显式记录而非擅自裁决。

## 执行流程

1. **识别结构** —— 判断数据类型与格式（docx/pdf/xlsx/表格/日志/md），选定解析方式。
2. **解析** —— 逐份读取，按自身章节/字段结构抽取内容。
3. **归一化** —— 统一字段名、类型、单位、口径，去重。
4. **冲突校验** —— 不同来源对同一事实矛盾时，并列保留两版 + 出处，不做裁决；缺失项单独列出。
5. **输出** —— 产出结构化结果（表/JSON/Markdown）+ 冲突清单 + 待确认项。

## 输入 / 输出

| 输入 | 输出 |
| --- | --- |
| 原始资料 / 文件列表 | 结构化数据 |
| 目标字段与口径 | 冲突清单 + 待确认项 |
| 去重/归一规则 | 清洗后结果 |

## 关联思维策略

- **归纳推理** —— 从多条记录归纳出统一字段结构。
- **对比分析** —— 交叉比对来源，暴露冲突与缺口。

## 基因库记录

- **类型**：pattern
- **复用经验**：出处即章节号——每条数据都要能映射回原位置；冲突并列保留、不擅自裁决；解析失败必须注明原因。
- **可复用性**：高 —— 通用。
- **入库自检**：用户选择 ✅ / 适应度前 100 ✅ / 可复用 ✅

## 示例

### 场景：解析一份 SKILL.md 做资料摘要

1. 识别：Markdown 纯文本，直接读取。
2. 解析：按 11 个章节逐条摘要，每条标 `D1，§章节`。
3. 校验：发现"26 种策略"标题 vs 正文实列 25 处矛盾 → 并列保留 X1/X2。
4. 输出：摘要表 + 2 冲突 + 6 缺失项。

## 安全与回滚

- **透明**：区分"直接引用/数据提取/综合归纳"。
- **可控**：只读不写原始数据。
- **可逆**：解析脚本与规则可回退重跑。
- **渐进**：先小样本验证解析规则，再全量。
- **用户主导**：冲突与口径分歧由用户裁决。

# 文档写作

> 先想清楚"给谁看、要对方做什么"，再决定写什么、怎么写。

## 何时使用

- 需要产出一份正式/半正式文档（说明、报告、设计、复盘）。
- 内容复杂，需要结构化以降低理解成本。
- 需要他人照着文档独立执行或决策。

## 执行流程

1. **定位读者与目标** —— 明确读者是谁、读完要采取什么行动。
2. **搭骨架** —— 先用思维导图/大纲确定章节层级与主线。
3. **分节撰写** —— 每节先结论后展开；标题可独立读懂内容。
4. **费曼自检** —— 用平实语言解释，替换掉晦涩术语和绕口长句。
5. **一致性校对** —— 校验术语、数字、引用、表格前后一致。
6. **发布** —— 落盘为 Markdown，标注版本与日期。

## 输入 / 输出

| 输入 | 输出 |
| --- | --- |
| 素材 / 要点 / 数据 | 结构化 Markdown 文档 |
| 目标读者与用途 | 大纲 + 分节正文 |
| 格式要求 | 版本化文档 |

## 关联思维策略

- **思维导图** —— 先发散搭骨架，再收敛成线。
- **费曼技巧** —— 用"讲给外行听"检验是否真懂、是否清晰。
- **康奈尔笔记** —— 主区写正文、边栏提炼要点、底部做总结。

## 基因库记录

- **类型**：pattern
- **复用经验**：每一节"结论先行"；文档必须能凭标题就能判断是否有用；数字与术语要前后一致。
- **可复用性**：高 —— 通用。
- **入库自检**：用户选择 ✅ / 适应度前 100 ✅ / 可复用 ✅

## 示例

### 场景：把调研结论写成交付文档

1. 读者：架构师 + 主理人；行动：据建议落架构。
2. 骨架：资料摘要 → 调研事实 → 对比矩阵 → 取舍建议 → 来源。
3. 分节写：每段"结论 + 依据 + 出处"，术语全项目统一。
4. 校对：权重、得分、引用编号前后一致。

## 安全与回滚

- **透明**：事实与推断分开标注。
- **可控**：分节产出，可逐节确认。
- **可逆**：版本化保存，可回退到旧版。
- **渐进**：先大纲后正文，避免返工。
- **用户主导**：口径、结论措辞由用户确认。

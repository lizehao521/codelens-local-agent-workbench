# 判据工程

> **判据器是系统给自己的答案。它坏的时候，报的还是绿。**
>
> 本技能不讲「怎么写测试」，讲 **「判据本身会在哪里骗你」** —— 六种失败模式，全部来自实测。

## 何时使用

出现下列任一信号，先看本技能的失败模式库：

1. **校验器报绿，但你不放心** —— 说不出哪里可疑，就是觉得太顺。
2. **一个新判据刚写出来** —— 尤其它「一写就对、从没红过」。
3. **修好一个 bug 后，测试反而红了** —— 大概率是脆金丝雀。
4. **两个工具对同一件事给出两个答案** —— 口径分叉。
5. **判据报出一批「不符合」，但看起来都像是误报** —— 先怀疑判据，再怀疑被判断的对象。

## 失败模式库

### M1 · 把「读不到」记成「不合格」

**症状**：判据对被判断的对象**没有数据**时，仍然输出了一个否定结论。

**实测**：技能体检把 16 个宿主内置技能判为 `failed`，而同一批条目的另一栏写着
「磁盘读数: 未执行（宿主内置技能不在本仓）」。**判定建在它拿不到的数据上。**

**为什么危险**：它看起来完全可执行 —— 有技能名、有失败理由、有具体条目，
你会去"修"一个根本不存在的问题。

**治法**：判据输出必须**三态**，且**不可得要有原因**。

```
符合     有硬读数 且 通过
不符合   有硬读数 且 不通过  -> 必须附「实际值 vs 期望值」
不适用   数据不可得，未判    -> 必须附「不可得的原因」
```

**硬规矩**：「读不到」≠「不合格」。任何判据若因数据不可得而无法判定，
必须输出 `不适用` + 原因，**绝不允许记为 `不符合`**。

### M2 · 假绿基线

**症状**：把一个**红的**实测值，以**绿的形态**写进了长期引用物（文档 / 基线 / 台账）。

**实测**：台架锚点修复器在 `run-all` 得 `550/12`（红）时，把文档写成了 `550/0` ——
它只替换通过数、保留 `/0` 后缀。**于是文档里出现了一个从未存在过的绿基线。**

**为什么比红更危险**：

```
红会被发现；假绿会被【当证据引用】。
后来的人拿它当"上次是绿的"，据此判断"这次是回归"。
```

**治法**：写回长期引用物之前，先检查**这一轮是不是红的**；是红的就**拒绝写**并报错。
实测的有效形态是 exit 码分离：`0` 写好、`1` 有漂移、`2` 前置不可得、**`3` 红轮拒绝写**。

### M3 · 脆金丝雀

**症状**：判据里嵌着一个**「当前已知坏点」**当金丝雀（用来证明判据没瞎）。
**把那个坏点修好之后，判据反而红了。**

**实测**：一条测试断言 `hermes-api-integration 必须 failed（有撞车触发词）`，
用来防「探测器整体失明」。后来那批撞车词被修掉，**这条测试就成了红。**

**治法**：金丝雀要选**不会因修复而消失的真值**，而不是"当前的坏点"。

```
脆（勿用）：断言某个技能目前不合格    -> 修好即失效
稳（推荐）：断言"数据不可得"这类结构性真值（见 M1）
          断言"设计性现象"这类永在的真值（如按设计被双胞胎压过）
          另加一条：断言"那个旧坏点【已修复】" -> 把修复钉住，而不是把故障钉住
```

### M4 · 口径窄于风险

**症状**：判据测的那个量，**比它想防的风险窄**。它说"没事"，但风险在它测的范围之外。

**实测**：验证「新增触发词会不会撞车」时，只测了「别技能用自己的词当探针时会不会掉出第 1 名」。
结论是 0 回归。**但真实风险是**：用户的问题里含那个词时，新技能会抢答 ——
**而这条判据完全没覆盖**（只有当受害技能的探针恰好含那个词时才会掉）。

**治法**：**把判据想防的风险写出来**，再问"这个量覆盖它吗"；不覆盖就补第二层。
实测有效的双层：窄口径（精确、可复算）+ 宽口径（代理量、覆盖面）。
**两层结论不一致时，不要挑好看的那个。**

### M5 · 字段语义跨族不可比

**症状**：同一个字段名，在不同来源的条目里**含义不同**。判据拿它做比较，**永远量不出东西**。

**实测**：`metadata.strategies` 在 22 个普通技能里是**手法【概念】**（`[最小复现, 硬读数]`），
在 4 个由基因结晶来的技能里是**基因【引用】**（`[pattern-005~018, pattern-034]`）。
拿"概念"的尺子去量"引用"，必然假报缺口。

**治法**：判据上线前，**先确认被比较的两边是同一个语义**；
不是就**要么按族分开**，要么**只测两边共有的部分**。
另一条相关陷阱：**记号不匹配**也会假报 —— `T1-T5`（hyphen）vs `T1–T5`（en 破折号）、
`M四闸` vs `M 系四闸`（空格）。子串比较对这两者都敏感。

### M6 · 永真断言

**症状**：判据从写出来那天起就是绿的，**因为它根本不会红**。

**治法**：**判别力自证** —— 在内存里（不写盘）造一个「本该被抓到」的样本，
断言判据**确实变红**，再还原、断言复绿。

```
每个判据至少一条注入用例：
  注入坏值 -> 必须判「不符合」且命中对应判据 -> 还原 -> 必须复绿
任何一条注入不生效 => 那条判据是永真的，不可用。
```

**配套**：判据**自己会不会永远为真/为假**也要证 ——
比如"规则要有条件"，就注入一个**不满足条件的样本**，断言它**不**被豁免。

## 通用协议

```
1. 先写判据【想防什么】，再写它【怎么测】。两者对不上就别上线。
2. 判据的输出必须三态，且"不可得"必须带原因。（M1）
3. 判据上线前先做判别力自证：注入 -> 必红 -> 还原 -> 必绿。（M6）
4. 判据要写入长期引用物之前，先确认本轮不是红的。（M2）
5. 金丝雀选结构性真值，不选当前坏点。（M3）
6. 量了一个量之后，回头问"它覆盖风险了吗"；不覆盖就补第二层。（M4）
7. 跨来源比较前，先确认字段语义与记号一致。（M5）
8. 两个工具对同一件事给两个答案 => 是缺陷，不是口径差异。要么统一，要么用一个判据把它们绑死。
```

## 反模式

| 反模式 | 为什么错 |
|---|---|
| **用「全绿」当结论** | 没跑过注入夹具，就无法断言判据还有判别力。（M6） |
| **手动跑一次就当"守住了"** | 人工跑的是快照，不是约束。要接进常规闸，并用"故意改坏会让闸红"做端到端验收。 |
| **"我会记得每次都跑"** | 那不是约束。上一轮改动、这一轮手误，都会让判据悄悄失效而无人知道。 |
| **两个工具口径不同就说"赛道不同"** | 同一事实两个答案就是缺陷。 |
| **为让数据通过而放宽判据** | 与"为让数据通过而改数据"同级。要么改数据到合规，要么把判据的适用边界写清。 |

> K 线纪律：**先造尺子，再量东西；尺子自己要先被量过。**

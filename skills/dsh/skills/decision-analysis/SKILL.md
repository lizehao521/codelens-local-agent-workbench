# 决策分析

> 把"感觉哪个好"变成"按什么标准、多重、为什么"。

## 何时使用

- 在多个选项之间做最终选择。
- 决策涉及多个冲突目标（质量 vs 成本 vs 速度）。
- 需要一份可向别人解释、可复核的决策依据。

## 执行流程

1. **明确决策点与选项** —— 写入候选选项（含"维持现状"基准）。
2. **定标准** —— 列出评估维度，去掉重叠项。
3. **赋权重** —— 按重要性分配权重（权重和 = 1.0）。
4. **打分** —— 对每选项每维度打分（统一标尺，如 1~5）。
5. **算总分** —— 加权求和，产出排名。
6. **敏感性检验** —— 微调权重看结论是否翻转；若小扰动即翻盘，说明结果不稳健，需补充信息。
7. **结论** —— 给推荐 + 需注意的翻转条件。

## 输入 / 输出

| 输入 | 输出 |
| --- | --- |
| 候选选项 + 决策目标 | 决策矩阵 + 加权排名 |
| 评估维度与权重 | 推荐结论 |
| 成本/时间约束 | 敏感性检验与翻转条件 |

## 关联思维策略

- **决策矩阵** —— 核心工具，多维度量化比较。
- **成本收益分析** —— 量化各选项的投入与回报。
- **预尸检** —— 检验推荐项"失败会怎样"，避免只看优点。

## 基因库记录

- **类型**：strategy
- **复用经验**：权重和恒为 1、统一打分标尺、必做敏感性检验，三者缺一结论不可信。
- **可复用性**：高 —— 通用。
- **入库自检**：用户选择 ✅ / 适应度前 100 ✅ / 可复用 ✅

## 示例

### 场景：方案 A 与方案 B 哪个好

1. 标准：可行性 0.3 / 效果 0.25 / 风险 0.2 / 成本 0.15 / 创新 0.1。
2. 打分：A(4,3,3,4,2) → 3.25；B(3,4,4,3,4) → 3.60。
3. 敏感性：把可行性提到 0.5 时 A 反超 → 结论：若最看重可行性选 A，否则选 B。

## 安全与回滚

- **透明**：权重、打分、计算过程全公开。
- **可控**：纯分析，无副作用。
- **可逆**：权重/标准可调整重算。
- **渐进**：先 3~5 个核心维度，不够再补。
- **用户主导**：最终选择由用户做出，工具只给依据。

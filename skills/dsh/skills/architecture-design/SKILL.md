# 架构设计

> 好架构把变化隔离在尽量小的边界内，而不是追求"一步到位"。

## 何时使用

- 从 0 设计一个系统 / 服务 / 库。
- 现有系统需要重新划分模块或分层。
- 技术选型卡在多个候选之间。

## 执行流程

1. **明确目标与约束** —— 收敛需求、性能、成本、许可、降级等约束。
2. **拆解核心能力** —— 识别能力域，划分模块与职责边界。
3. **设计接口与数据流** —— 定义模块间契约、数据流向与状态归属。
4. **技术选型** —— 用决策矩阵按权重打分，给出依据与备选。
5. **明确边界与降级** —— 规划失败场景、降级路径与扩展点。
6. **产出架构产物** —— 架构图 + 设计文档 + 关键决策记录。

## 输入 / 输出

| 输入 | 输出 |
| --- | --- |
| 需求清单 / 约束 | 模块划分 + 接口契约 + 数据流 |
| 候选技术栈 | 选型决策 + 依据 |
| 风险与预算 | 降级路径 + 扩展点 |

## 关联思维策略

- **第一性原理** —— 从能力本质倒推模块边界。
- **决策矩阵** —— 选型用多维加权，而非凭感觉。
- **形态矩阵** —— 关键维度两两组合，穷举可行形态。

## 基因库记录

- **类型**：architecture
- **复用经验**：先定边界再定技术；选型必须落"标准+权重+依据"；降级路径一开始就要设计。
- **入库自检**：用户选择 ✅ / 适应度前100 ✅ / 可复用 ✅

## 示例

进化引擎 → 拆成 进化核心 / 策略库 / 基因库 / 评分器，接口走统一 Engine 门面；选型 Git+SQLite+Python。

## 安全与回滚

- **透明 / 可控 / 可逆 / 渐进 / 用户主导**：每步产出可评审，选型决定权在用户。

# 提示词设计

> 提示词的本质是"契约"：把输出格式、边界与标准写清楚。

## 何时使用

- 需要让模型稳定输出某种结构 / 风格 / 格式。
- 指令含混导致结果忽好忽坏。
- 需要把一次好结果固化成可复用模板。

## 执行流程

1. **明确输出契约** —— 定义输出格式、字段、边界与验收标准。
2. **写角色 / 上下文 / 约束** —— 给足背景，写清禁止做什么。
3. **给示例** —— 用 few-shot 锚定期望，尤其是边界样例。
4. **试跑并对比** —— 同一批输入跑多轮，记录差异。
5. **迭代修正** —— 针对不稳定点收紧措辞或补示例。
6. **固化模板** —— 收敛成版本化模板，标注适用场景。

## 输入 / 输出

| 输入 | 输出 |
| --- | --- |
| 任务目标 / 期望格式 | 提示词模板 |
| 示例数据 | 迭代记录 |
| 失败样本 | 稳定、可复现的版本 |

## 关联思维策略

- **费曼技巧** —— 把要求讲到"外行都能照做"的程度。
- **对比分析** —— 好/坏输出并排找出措辞差异。
- **预判验证** —— 预判模型会在哪跑偏，提前写死约束。

## 基因库记录

- **类型**：strategy
- **复用经验**：先定契约再写措辞；示例要含"该拒绝/该判错"的边界样例；改一次只动一个变量。
- **入库自检**：用户选择 ✅ / 适应度前100 ✅ / 可复用 ✅

## 示例

"别啰嗦" 效果不稳 → 改为"输出 ≤3 条要点，每条 ≤20 字，用-列出" → 多轮复现稳定。

## 安全与回滚

- **透明 / 可控 / 可逆 / 渐进 / 用户主导**：版本化留存，可回退重跑对比。

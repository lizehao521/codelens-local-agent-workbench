# 退一步取证

> 横是在方案空间里铺开，纵是在方案空间里深入——**退一步是离开方案空间，去现实里拿一个不依赖判据的读数。**
>
> 评分是系统给自己的答案，**退一步是现实给系统的答案**。尺子准不准，尺子自己说了不算。

## 何时使用

出现下列任一信号，就别再继续推演/迭代，先退一步：

1. **null** —— 评分系统自己说「无法测量」（`loop.mjs` 里 `actual/regret` 是 `null` 而不是 `0`）。
2. **平票** —— 两个候选同分，A 通过 / B 不通过 分不出高下。
3. **连续 2 轮无改进** —— 进化停摆 = 判据可疑，不是方案不够多。
4. **结论太顺** —— 越跑越顺，越可能在拟合自己的假设。
5. **拿不准自己写的对不对** —— 推测中遇到「不知道好不好」。

## 为什么必须退

不通过是对称的，它只给 1 位信息「不一致」。但不一致的归因至少三种：

| 归因 | 动作 | 评分看得见吗 |
| --- | --- | --- |
| 1. 实现错了 | 改实现 | 看得见 |
| 2. 判据错了 | 改测试 | 看不见 |
| 3. 前提错了 | 改传进去的东西 | 看不见 |

**这三种在评分表上长得一模一样，都叫「不通过」。** 读到评分直接动手，就会把第 2、3 种当成第 1 种修——那是把 bug 写进测试。

## 执行流程

1. **声明一句可证伪的假设** —— 必须能被一个读数推翻，不能是观点。
2. **选一种不经过 judge 的读数**（见下表白名单）。
3. **取读数** —— 真跑，不估。
4. **三态归位** —— 事实 / 未执行 / 事实推翻了谁。
5. **回收配额** —— 一个循环内最多退 1 次；带不回硬值的「退」判为假退，重来。

## 读数类型（硬值白名单）

| 类型 | 例子 | 工具 |
| --- | --- | --- |
| 进程退出码 | exit=0 / exit=1 | `test-runner` |
| 内容哈希 | sha256 = ? | `git-snapshot` |
| 字节 / 行数 | sizes 求和 == 产物长度 | `code-audit` |
| 活体状态 | verified / broken / unreachable | `verify-url` |
| 实测耗时 | p95 = ? ms | `perf-regression` |
| 一次真实调用的原始返回 | dump 原文 | `run_code` |

## 输入 / 输出

| 输入 | 输出 |
| --- | --- |
| 一句可证伪的假设 | 一个硬值（数值或闭集字符串） |
| 判不了的状态（null / 平票） | 三态：事实 / 未执行 / 推翻了谁 |

## 产物硬规（不满足即判为假退）

- 产物必须是**数值**或**闭集字符串**。
- 拿不到 → 明写 **未执行**，绝不写成「通过」。
- 「我再调研一下」「换个角度想」= 假退，判为横，重来。
- 不可逆写动作前必须先有回滚点；快照工具内存不足时降级为定向 fs 备份 + SHA 清单（本仓实证范式）。

## 切换规则（纵横 ↔ 退一步）

- **横 → 纵**：出现至少 2 个候选**且**有可测判据，就交出去自己跑，别再消耗人的判断。
- **纵 → 退**：null / 平票 / 停摆 / 太顺 —— **别继续进化，回去重建判据**。
- **退 → 横或纵**：拿到硬值后，用它干掉或保留候选。

## 与其他技能的关系

| 移动 | 是什么 | 谁 |
| --- | --- | --- |
| 横（发散） | 在方案空间铺开候选 | M1 / M4 / `hermes-solution-design` |
| 纵（收敛） | 沿一条迭代收敛 | M3 / M5 / `hermes-evolution-inference` |
| **退一步（取证）** | **离开方案空间取事实** | **本技能** |
| 签字 | 不可逆动作的唯一责任人 | 人 / 主承担者（不可替代） |

## 关联思维策略

- **最小复现** —— 缩到最小可触发样例，一个事实干掉整个方案空间。
- **硬读数** —— 不依赖任何 judge 的值：exit / hash / bytes / 一次真实返回。
- **三态诚实** —— 拿到就写事实，拿不到就写「未执行」，绝不注水。
- **取证 ≠ 解决** —— 退一步只回答「该改哪一层」（实现/判据/前提），不回答「改对了没」；归因之后必须回到动手环节复验。

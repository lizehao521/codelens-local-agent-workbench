# 项目脚手架

> 骨架先定"规范与约定"，让后来的人第一眼就知道文件该放哪。

## 何时使用

- 从头新建一个项目 / 服务 / 库。
- 需要一套可复用、含 Lint 与测试的最小可运行模板。
- 统一团队项目结构与依赖约定。

## 执行流程

1. **明确类型与技术栈** —— 确认语言、运行时、框架与打包方式。
2. **选目录结构规范** —— 参照社区成熟约定，做最小定制。
3. **生成配置与依赖** —— 依赖清单、构建/运行脚本、环境样例。
4. **建入口与示例** —— 可运行入口 + 一两个示例模块。
5. **加 Lint / 测试** —— 质量门禁随骨架一起到位。
6. **验证可运行** —— 装依赖、跑入口、跑示例测试。

## 输入 / 输出

| 输入 | 输出 |
| --- | --- |
| 技术栈 / 项目类型 | 目录结构 + 配置 |
| 团队规范 / 模板偏好 | 可运行入口 + 示例 |
| 依赖范围 | Lint/测试 + 说明 |

## 关联思维策略

- **决策矩阵** —— 目录规范与工具链选型按需打分。
- **形态矩阵** —— 目录维度与功能维度组合出骨架形态。

## 基因库记录

- **类型**：pattern
- **复用经验**：先约定目录再写代码；质量门禁（Lint+测试）与骨架一起交付，不能后补。
- **入库自检**：用户选择 ✅ / 适应度前100 ✅ / 可复用 ✅

## 示例

Python 服务骨架 → src/ + tests/ + pyproject.toml + .gitignore + Makefile + 一个可运行 health 入口。

## 安全与回滚

- **透明 / 可控 / 可逆 / 渐进 / 用户主导**：生成到临时目录先审，确认后落地，可回退。

### 判据器自证：这个绿为什么不能当口径合规的证据

我读了 `scripts/validate_prompt_pack.py:78-88, 250-264`，`(7)` 的实现有三处会让判据器自己骗自己：

1. **宽口径豁免**：`LIVE_EXEMPT_RE = 以实跑为准|不得写成规范|不写绝对值|待核实|互不相容|UNEXEC`（`:88`），`check_7` 在 `:254-255` 是「同一行命中任一豁免词 → 整行跳过」。`S00-router.md:59` 与 `A06-debugging.md:59` 都含「活读数以实跑为准」，整行被放行——**同一行里既有豁免词也有 20/19/17 三个具体数字**。
2. **模式口径过窄**：`LIVE_ASSERT_RE`（`:78-81`）只认「必须是/规定为/固定为 N 个工具」式绝对化句式，`LIVE_HARD_RE`（`:83-86`）只认「只取/限定为 N 个内置工具」。`S00-router.md:92` 用「当前源码注册表实读 20 个」，两个模式都不匹配，故漏检。
3. **WARN 不计失败**：`check_7` 命中只报 `WARN`（`:261`），即便命中也不影响 exit code；`(7)` 的 PASS 语义是「未命中模式」，不是「已证明无越界」。

`--self-test` 也只验了「必须是 19 个工具。」这一种写法（`:336`），没有覆盖「实读 20 个 + 同行带豁免词」这一真实坏法。**判据自证只证明了它能抓住自己夹具里的那一种坏法，没证明它抓得住本包里这三种。**这句我查了源码，没有含糊余地。

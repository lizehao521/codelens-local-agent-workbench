## 二、双组口径若要改成单组，该怎么裁

### 2.1 先确认这是什么性质的变更

现状是**用户 2026-11-14 拍板「两组并列」**，`领域解析卡.md §7:143-151` 记了口径演进三步：① 原派单锁死单 RSI 口径 → ② 坊主撤销、改「待用户拍板」并列两种候选口径 → ③ **用户明确选择「两组并列」（最终）**，并写明「本卡按 ③ 执行，**不再写『待用户拍板』**」；`项目档案.md:9`、`场景切分矩阵.md:4` 同步。

所以「改单组」不是执行细节微调，而是**再拍板（口径演进 ④）**，且必须覆盖 ③。**执行 Agent 不得自行选边**——这正是 `领域解析卡.md:32`「本卡不自行选边」、`场景切分矩阵.md:4`「坊主已拍板，不讨论选边」的同一条纪律。

### 2.2 裁决必须一次说清的四件事

| 裁定项 | 必须写死的内容 |
|---|---|
| **① 取哪一组** | 明确「单 RSI（只留 B 组）」还是「单日常开发（只留 A 组）」，二选一，不得含糊成「以 RSI 为主」。`领域解析卡.md §1:27-30` 已列两种口径的适用面、典型任务、输入物与**产物差异**，直接拿来做取舍依据，不重新调研 |
| **② 谁拍板、何时、覆盖哪版** | 在 `领域解析卡.md §7` 与 `项目档案.md` 追加「口径演进 ④：由〈谁〉于〈日期〉拍板，覆盖 ③，理由〈…〉」。**保留 ③ 的历史记录不抹平**（与版本三层分列同一纪律），不得静默改写旧段落 |
| **③ 保留哪些槽** | 两种单组都**必须保留共享层 S00 与 S01**：S00 是元提示词、逻辑上先于所有槽（`场景切分矩阵.md:8,132,203`），S01 是任何槽位完成后都可进入的只读快照（`:8,133,204`）。因此：<br>· 单 RSI = `B01–B07 + S00 + S01` = **9 份**（对应 `§0.7:106` 侦察官 8 主槽位 ≈ B 组 7 + S01，再加 S00 元路由）<br>· 单日常开发 = `A01–A07 + S00 + S01` = **9 份**<br>· 删除的另一组 7 份按三态诚实标「**不适用（口径外）**」，**不留空文件、不改名复用编号、不把删掉的槽内容塞进 S 槽** |
| **④ 连带改动清单（一处不改就会自相矛盾）** | 见 2.3 |

### 2.4 三条不许破的线

- **不自行选边**：没有用户/坊主的第 ④ 次拍板，任何 Agent 不得把「两组并列」默认成单组，也不得借「收敛」「简化」之名删槽（`领域解析卡.md:144`）。
- **不混编号**：矩阵 `§0.6:83-102` 位宽 ID 与短编号一一等价；`§0.7:107` 明写「禁止把侦察官 `S1` 当本文 `S01` 的别名」。裁剪后仍不得把删掉的 A 编号改挂到 B 槽，或反过来。
- **不抹事实**：工具数 20、题集 36、版本三层、三个「23」是**事实裁定**（`信源与版本清单.md:12-22`），与「几组口径」正交。改单组只动槽位与路由，不动这些事实，也不动 16 份 prompts 里「不写工具数具体数字、统一短句」的刚性口径（`校验报告.md §〇、§六`）——**该打回的 3 处仍要打回**，不因口径裁剪而豁免。

## 0. 填写口径（先读，防误判）

1. **四件套**：每行写齐「操作路径 + 工具名称 + 步骤 + 输出物」，另加「版本标注」列与「验收」行。答不出「怎么验证做到了」的能力一律改写。
2. **工具名口径**：`工具名称` 列凡写内置工具，以手册 §4 的 **19 个点号规范名**为零虚构基线（`http.request` / `fs.read` / `fs.write` / `fs.list` / `fs.glob` / `code.search` / `calc.evaluate` / `time.now` / `uuid.generate` / `json.format` / `text.diff` / `sys.exec` / `tool.forge` / `web.search` / `eval.run` / `eval.propose` / `code.check` / `test.run` / `type.check`）。**坊主事实裁定（全组统一口径）**：当前源码注册表 `server/src/tools/builtin/index.ts:25-46` 实读 **20 个工具（含 `agent.verify`）**；此为活读数，以实跑为准，不得写成规范；手册 19 为上轮读数、17 为旧构建实例。第 20 个 `agent.verify`（`wireName='agent_verify'` / `risk='medium'` / `approvalMode='none'`）由坊主实读确认，手册 §4 未列，引用时标注「坊主实读，手册 §4 未列」。已实读契约：`ToolRisk` 三值 / `ToolApprovalMode` 四值 / `ToolStatus` 七态（见《场景切分矩阵.md》§0.1）。零虚构工具名。
3. **命令口径**：`操作路径` 列的命令只取手册 §2/§9、HANDOFF §4/§8、spec §12、AGENTS §3 已写明的真命令。脚本与端点用 `[脚本]` `[端点]` 前缀标注，明确「非 §4 内置工具」，避免与工具名混淆。
4. **活读数纪律**：手册 §7.3 明写「这些是活读数，不是规范；重跑以实际输出为准」。凡题数、pass 数、文件数、版本、工具数一律标「活读数，以实跑为准」，不写成规范。
5. **冲突与待核实**：统一索引见文末 §5；`C1` 按坊主裁定写确定答案（20 工具口径），`C2–C4` 缀「运行态活读数冲突，以实跑为准」；查不到的事实记作 `W1–W7`，一律标「待核实」。
6. **配比**：L1 七问 / L2 九问（含 2 个完整实战、18 个参数、提效三件套）/ L3 七问（含 5 类排查树、2 个最小示例），按「专家-个人」画像压薄 L1、深写 L2/L3（02 号方法论 §6），内容量约 **3:5:2**。

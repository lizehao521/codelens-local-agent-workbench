## 2. 领域判定

- **领域类别（八类之一）**：**双口径分别判定**——
  - **口径 A → 开发框架/语言**（`references/01` §一第 4 类，:15）：用 CodeLens 做日常软件开发，关键动词「澄清 / 设计 / 编码 / 评审 / 测试 / 调试 / 重构」，按 01 号 :21 三问落在「开发」，知识库按学习路径/工作流组织。
  - **口径 B → 行业领域——Agent 工程 / 自我演进工程方法**（01 号 :17「一整个行业的工作方法与规范体系，按业务流程阶段」）：含 RSI 变更域 D0–D4（手册 §7.2:86-92）、判据门禁、归因纪律、账本治理，是一套工程规范体系，按「领题→实现→判据→验证→采纳→交接」业务阶段组织。
  - v1.0 曾把「行业领域」列为备选判定，**两组并列后两个判定同时成立、各自适用**；产物形态均为技能包，不冲突、不阻塞。
- **判定依据**：01 号 §一:21 判定动作三问；手册 §1:8「本地优先的 Agent host + 判据门禁下的自我演进（RSI）」；spec §2 MVP 12 项（`spec.md:19-32`，A 组能力锚点）；手册 §7 RSI（B 组能力锚点）。
- **排除**：非「桌面软件」（本包不教界面菜单）、非「操作系统」、非「学科知识」、非「创意工具」、非「移动 App / 硬件设备」。
- **相邻领域边界（两组共用，明确不属于本包）**：
  1. 终端用户的对话提示词与办公/设计/创意场景（spec §1；WorkBuddy Overview）——义项 ①，已排除。
  2. DSH 宿主侧 `defineTool` 插件模块与 48 个 DSH `SKILL.md` 的内容创作与封装（手册 §10:239；`skills/dsh/skills/` Glob 实读 48 个）——只当被消费资产与技能库读数。

  4. 前端 UI / 设计 Token / 视觉规范（spec §7、§8；手册 §10:241「无像素基线」）。
  5. MCP Server 连接器实现（spec §2 P1 :34、§5 六端点 :91-95、AC-12 :156）——P1 未实现，未连接时对模型完全不可见。
  6. WorkBuddy 技能包**平台外壳规范本身**——属产物外壳，记录于《信源与版本清单》《规范差异点》，不是教给执行 Agent 的领域知识。

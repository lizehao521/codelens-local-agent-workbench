# 一切皆以强化内核为中心

> 一句话 → 一个公式 → 四条铁律 → 一座判据塔 → 一张反面清单 → 一条工具纪律 → 一条元规则

## 0. 这句话在说什么

不是「内核很重要」，也不是「别的都不重要」。

它的意思是：**任何东西的价值，最终都由它让内核变强的程度来结算。**
代码、文档、指标、界面、流程、技能、记忆、甚至这条宣言本身——
都要回答同一个问题：**它让 Improve(π) 的哪一步变得更可信、更快、或更不容易被骗？**

答不上来的，不是坏东西，只是**装饰**。装饰可以有，但不能冒充强化。

## 1. 内核是一个闭环，不是一个模块

```
Improve(π) = π --Act--> τ --Judge--> r --Update--> π'
```

| 符号 | 含义 | 不可让渡的约束 |
|---|---|---|
| π | 当前策略（含判据、选臂、提示、阈值） | **自我修改的唯一表面**；每次修改必须可回滚 |
| Act | 把 π 作用到任务上 | 必须有终止条件，不能靠「跑完为止」 |
| τ | 轨迹与证据 | 必须是**当时**产生的，不能事后用今天的 git 状态补写 |
| Judge | 判据塔 L0–L3 | 判据自己要先被判据检验 |
| r | 判决 / 奖励 | 只能来自 Judge，不能来自「看起来不错」 |
| Update | 用 r 改 π | 只改 π，不改判据的度量口径来迁就结果 |

闭环的意思是：**r 必须真的改变 π'，π' 必须真的改变下一次 Act。**
任何一环断掉，剩下的部分再精致也只是流水账。

## 2. 四条铁律

**C1 · 中心性**
新增的每一个模块、字段、端点、文档，必须能回答：它强化了 Act / Judge / Update / Memory 的哪一维？
答不上来 ⇒ 它是装饰，不是强化。

**C2 · 闭环**
没有被消费的分数、指标、日志 = 开环。
「写出来了」不等于「起作用了」；必须有真实消费者，否则就是自娱自乐。

**C3 · 自证**
判据本身会骗人。所以每一条判据都要有：
正常例（该绿的绿）、金丝雀（该红的红）、破坏夹具（改坏必红）、判别力自证（不是永真闸）。

**C4 · 不外推**
证据分三类：static（读代码）、unit（跑断言）、live（真调用）。
未执行就写「未执行」，缺基线就不写「0 回归」；
上游没跑 ≠ 我方失败，但 **UNEXEC 也绝不等于 PASS**。

## 3. 判据塔：谁有资格说「变强了」

| 层 | 回答的问题 | 代价 | 不能替代谁 |
|---|---|---|---|
| L0 机械 | 格式/字段/阈值是否成立 | 极低 | 判不了语义 |
| L1 金丝雀 | 已知好/坏样本是否分得开 | 低 | 判不了新分布 |
| L2 语义 | 质量是否真的提升 | 中（需模型） | 判不了对抗 |
| L3 红队 | 能不能骗过判据 | 高 | 判不了整体 |

规则只有一条：**低层不能替高层签字，高层不能替低层免责。**
上游未执行时，诚实的结果是 UNEXEC，不是绿灯，也不是红灯。

## 4. 强化 ≠ 忙碌（反面清单）

- 加了模块，但没人调用 ⇒ 不是强化。
- 指标涨了，但口径换了 ⇒ 不是强化。
- 文档变长，但不能被机器对账 ⇒ 不是强化。
- 一次跑绿，但破坏夹具打不红 ⇒ 不是强化。
- 能自我修改，但没有闸和回滚点 ⇒ 不是强化，是事故预演。
- 把「未执行」说成「通过」 ⇒ 不是强化，是自欺。

## 5. 记忆也是内核的一部分

内核不只有 π，还有它为什么变成今天这样。
失败记忆、对话记忆、任务日志、回滚点——**口径必须分开**，不能互相冒充。
记忆的价值不在「记得多」，而在**能在下一次决策点被召回，并且改变决策**。
召回不了的记忆，和没记一样。

## 6. 工具是义肢，不是资产

工具是任务期临时长出来的义肢。
任务结束，义肢要么被**吸收**（变成 π 的一部分），要么被**截掉**（删除）。
留在身上的义肢 = 熵。

所以任务的交付物不是工具，是 **π 的增量**；没有 π 增量的任务，等于没强化内核。

| 步 | 动作 | 判据 | 典型失败 |
|---|---|---|---|
| 1 触发 | 现有工具不够用 | **同一问题第二次出现**才允许造新工具；第一次先手工做 | 为一次性问题造工具 |
| 2 生成/强化 | 先改现有工具，再考虑新写 | 新写必须有一句「现有工具为何不够」 | 重复造轮子 |
| 3 进沙箱 | 只活在任务作用域（`tmp/tools/<taskId>/`） | 过 L0 自测 + 一个真实用例才可用 | 直接进主树 |
| 4 使用 | 每次调用都记账 | `tool_created / tool_used / tool_failed` 三事件 | 静默失败 |
| 5 回收 | 任务结束**必删**工具文件 | 删除前答「沉淀三问」（见下） | 留着「以后可能用得上」 |
| 6 回归核心 | 把答案写回 π / 记忆 | 有 `tool_removed` 就必须有配对的 `lesson` | 只删不沉淀 = 白干 |

**沉淀三问**（删除前必须回答，答不出就不许删）：

1. 它解决了**哪一类**问题？
2. 这个解法能不能变成 π 的修改（提示 / 判据 / 策略 / 记忆）？
3. 下次遇到同类问题，能不能**不造工具**就解决？

三问的答案进记忆/π，工具本身删掉。

**三条机器闸**（都要能被打红）：

- **孤儿工具闸**：任务结束后任务作用域必须为空；非空即失败。
- **沉淀配对闸**：`tool_removed` 必须与一条 `lesson` 成对出现；只删不记即失败。
- **写闸复用**：工具要进主树，必须过自证与工程闸；否则只能在沙箱里活。

**反面清单**：

- 工具留下当「以后可能用得上」 ⇒ 熵。
- 只删工具不沉淀 ⇒ 白干。
- 为一次性问题造工具 ⇒ 过度工程。
- 工具直接进主树不过闸 ⇒ 事故。
- 沉淀写成「下次再说」 ⇒ 等于没沉淀。

一句话：**工具用完就删，经验写回内核；删除不是丢弃，是把工具变成 π。**

## 7. 元规则：这条宣言也要接受检验

本宣言不是宪法，是 π 的一部分。
它可以被修改，但修改必须走同一个闭环：提出 → 给证据 → 过判据 → 留回滚点。
**不许用「这是原则」来豁免检验。**
如果有一天它挡住了更好的强化路径，该改的是它，不是证据。

## 8. 终止条件

- 饱和不是终点：饱和意味着**该扩任务空间、加新家族**，而不是改判据让它继续绿。
- 全绿不是终点：全绿只说明「当前判据没抓到问题」，不说明「没有问题」。
- 内核的终点是：**下一次自我修改，仍然可以被证伪。**

—— 一切皆以强化内核为中心。

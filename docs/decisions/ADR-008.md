# ADR-008: 后端使用 Express 5.3.0（Node 22 LTS）

## Status: Accepted (2026-10-20)

## Background
服务端职责是 LLM 代理薄层：校验 → 转发上游 → 流式回传。候选：Express 5、Fastify 5、NestJS 11。Node 运行时已定 22 LTS。

## Decision
选择 Express 5.3.0（@types/express 5.0.6），配合 cors 2.8.6、zod 4.6.7（请求校验）、自研内存限流中间件。分层：routes（装配）→ controllers（校验+编排）→ services（业务）→ providers（上游适配）。无数据库，无 repository 层。

Express 5 行为变化的显式规避（防沉默错误）：
1. 路径匹配规则变化：全部路由使用字面路径 + 单段 :param，禁用正则/通配符片段。
2. async 错误冒泡：async handler 统一经 asyncHandler 包装，错误统一进 error middleware。
3. Node 版本：Express 5 要求 Node 18+，部署用 22 LTS，满足。

不选 Fastify 的理由：吞吐约 1.6 倍于 Express，但本服务 99% 时间在等上游 LLM，框架吞吐非瓶颈；schema-first 与插件封装引入学习成本，收益不匹配。不选 NestJS：DI/Module 体系对 5 个端点是过度设计。

## Consequences
正面：团队熟悉度最高；中间件生态最全；薄层代码量最小。
负面：无内置校验/序列化（用 zod 补）；多实例时限流失效（本期单机可接受，登记 OD-2）。

# ADR-005: LLM API Key 采用 BYOK 为主、服务端 env 兜底的双模式方案

## Status: Accepted (2026-10-20)

## Background
应用需上线部署且免登录，调用真实 LLM API 必须持有 API Key。Key 不能硬编码进前端包（公开可查）。两种路线：A) BYOK——用户在前端设置页填 Key 存 localStorage，请求经 HTTPS 传给服务端代理转发，服务端不落库；B) 服务端 env 配置固定 Key，匿名用户共享。

## Decision
双模式：请求带 apiKey → BYOK 模式用用户 Key；请求不带且服务端配了 LLM_SERVER_API_KEY → 演示模式用服务端 Key（启用更严限流）；两者都无 → 401 MISSING_API_KEY。默认引导用户走 BYOK。

威胁模型与对应缓解（逐项落地为验收）：
1. XSS 窃取 localStorage Key：react-markdown 禁原始 HTML；严格 CSP；禁 eval；npm audit 门禁。这是免登录产品的结构性代价，设置页须明示"Key 仅存于本浏览器，不会上传服务器"。
2. 日志泄露：请求日志脱敏中间件，apiKey/Authorization 一律替换为 ***；错误响应不回显 Key；上游错误归一化为 UPSTREAM_ERROR 后再吐给前端。
3. 盗用打爆：按 IP 内存限流（stream 20 次/分）+ 请求体 ≤ 64KB + 上游 60s 超时 + provider 白名单（禁止自定义 baseUrl，防转发恶意端点）。
4. 传输中间人：全链路 HTTPS + HSTS。

## Consequences
正面：演示不烧部署方成本；用户自选 provider；服务端零 Key 存储义务。
负面：新用户有配置门槛（用 provider 列表 + 引导文案缓解）；BYOK 的 XSS 暴露面无法根除；服务端 Key 模式（若启用）必须配强限流。

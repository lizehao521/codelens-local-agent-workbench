# ADR-009: 前端与后端同机同端口单容器部署

## Status: Accepted (2026-10-20)

## Background
产品最终需上线部署且可回滚。候选：A) 前端静态构建 + Node 服务端同机同端口；B) 前后端分离部署（前端 CDN/对象存储 + 后端 PaaS）。

## Decision
选择 A：Vite 构建产物复制进服务端镜像（server/dist-client/），Express express.static 托管 + SPA history fallback，单端口（默认 8080）。Docker 多阶段构建（builder → runtime），镜像 tag 化。

部署检查清单（缺一项不上线）：
1. Nginx 前置（如有）：proxy_buffering off、proxy_read_timeout 120s、gzip on。
2. HTTPS 终止于反代或平台层，全链路 TLS + HSTS。
3. env：ALLOWED_ORIGINS、LLM_SERVER_API_KEY（可选）、PORT、NODE_ENV=production。
4. 健康检查 GET /api/health 接入平台探活。
5. 回滚：保留上一个镜像 tag，故障时秒级切换。

不选 B 的理由：本期无 CDN 极致优化诉求，分离部署引入 CORS 白名单、双 CI、双域名复杂度，收益不匹配；同源部署下 CORS 中间件仅为未来分离预留开关。

## Consequences
正面：一条 CI 一个镜像；同源免 CORS；回滚路径最短。
负面：前端静态资源与 API 共用一个 Node 进程的 CPU（静态文件由 express.static 直接服务，可后续换 Nginx 服务静态）；单点（本期可接受）。

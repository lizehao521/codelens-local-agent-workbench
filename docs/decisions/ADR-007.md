# ADR-007: LLM 流式输出采用 SSE（POST + fetch ReadableStream）

## Status: Accepted (2026-10-20)

## Background
对话主界面需要 token 级流式输出。候选：SSE、WebSocket、普通轮询。请求体较大（含代码上下文），且 BYOK 模式需经自定义请求头传递 Key 覆盖。

## Decision
采用 SSE：客户端 POST /api/v1/chat/stream，用 fetch + response.body.getReader() 逐行读 `event:`/`data:` 帧；服务端 Express 直接写 res（text/event-stream）。事件类型固定四种：meta / delta / done / error。

关键坑（钉死，防返工）：
1. 浏览器原生 EventSource 只支持 GET 且无法带自定义 Header，本场景必须用手写 ReadableStream，不得使用 EventSource。
2. 反向代理默认缓冲会破坏流式，部署必须 proxy_buffering off（Nginx）。
3. 200 响应头一旦发出就不能再改状态码，错误必须以 event: error 帧内传递。
4. 客户端断线（AbortController）时服务端须监听 res close 中断上游请求，防泄漏上游连接。

不选 WebSocket：无双向实时需求（用户打断生成 = AbortController 取消本次 fetch，无需全双工信道），引入 upgrade/心跳/粘性会话是纯复杂度。不选轮询：做不到 token 级流式。

## Consequences
正面：与全部 LLM provider 的流式协议同构；穿透任意 HTTP 代理；实现约 60 行。
负面：需自行处理断线重连策略（MVP：不自动重连，提示用户重试，避免重复计费）；HTTP/1.1 下单域 6 连接上限对本场景无影响。

# ADR-003: 使用 react-markdown 10.1.0 + rehype-highlight 7.0.2 渲染 LLM 输出

## Status: Accepted (2026-10-20)

## Background
LLM 的回答以 Markdown 形式返回，含代码块、表格、列表。LLM 输出必须按不可信内容处理，XSS 防护是硬要求。同时流式场景下内容增量更新频繁，渲染方案需适配。

## Decision
选择 react-markdown 10.1.0（渲染为 React 虚拟 DOM，默认不使用 dangerouslySetInnerHTML）+ remark-gfm 4.0.1（GFM 表格/任务列表）+ rehype-highlight 7.0.2（highlight.js 引擎，约 40 种常用语言，样式用 github/github-dark CSS）。不选 marked + DOMPurify 路线，不选自研。

理由：
1. react-markdown 的安全默认值把"innerHTML 注入"这条最危险路径直接封死，防线在库内部而非依赖开发者自觉。
2. highlight.js 语言覆盖满足编程问答场景；样式走独立 CSS 文件，可被 CSP 的 style-src 约束。
3. 流式适配：增量字符串整体重渲染，react-markdown 对百毫秒级增量可接受；配合 React.memo 与按消息拆分渲染范围控制成本。

## Consequences
正面：XSS 防线内建于库；组件可替换（code 块可替换为带复制按钮的自定义组件）。
负面：大消息（>10KB）全量重解析有开销——以按消息 memo 化缓解；数学公式（KaTeX）不在 MVP 范围，需要时再加 remark-math/rehype-katex。

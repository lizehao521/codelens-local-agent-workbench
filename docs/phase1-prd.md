## 一、产品定位与一句话描述

**一句话描述**：一个打开即用的网页版编程 Agent——粘贴代码，选择「分析 / 解释 / 调试 / 优化」，即刻获得结构化答案；免注册、免安装，用自己的 LLM Key，对话存在自己浏览器里。

**产品定位**：
- 不是 IDE 插件（不需要装编辑器）、不是订阅制 AI 编辑器（不为额度焦虑付费）、不是通用聊天窗（不做百科全书，只做代码这四件事）。
- 形态是「代码专用工作台」：左侧代码编辑区（多语言高亮）+ 右侧对话与结构化结果区，类 AI 原生「对话式交互 + 侧边结果面板」布局。
- 商业模式前置结论：MVP 不做付费体系，采用 BYOK（用户自带 Key）。依据见第九章——国产 LLM API 单次代码分析成本约 0.1-0.2 分钱人民币（详见 4.3 成本测算），平台无需补贴推理成本即可长期免费运营，这使「免登录 + 零付费墙」在商业上成立。

## 二、目标用户画像

### Persona 1：小林 — 自学转行者 / 在校生（主要用户，占比预期最高）

- **背景**：22 岁，计算机专业大四或自学转行中，Python / JavaScript 为主。
- **典型场景**：读 GitHub 开源项目源码看不懂；刷完 LeetCode 想知道更优解；课程作业和毕设 debug 到深夜。
- **痛点**：
  - Stack Overflow 答案碎片化，要自己拼凑；通用聊天窗（ChatGPT / Claude 网页版）要注册账号、贴进去的代码没有高亮、回答是大段文字没有结构。
  - 问「弱智问题」有心理压力，希望有个随时待命、不评判的讲解者。
- **诉求**：打开网页就能用（免注册）；能把一段陌生代码逐层讲清楚；bug 要指出具体行和原因，而不是笼统说「可能有错误」。

### Persona 2：阿豪 — 3 年后端工程师（核心付费意愿人群，BYOK 主力）

- **背景**：28 岁，Java / Go 后端，日常 code review、接手陌生模块、线上问题救急。
- **痛点**：
  - GitHub Copilot 订阅制（$10-39/月）且 2025 年底以来补全质量波动明显；Cursor 2025 年 6 月定价风波（「无限」变约 225 次请求、按用量计费、26 小时锁定）后不再信任订阅制工具的额度透明度。
  - 公司代码不能贴到强账号体系的第三方工具里，合规上说不过去。
- **诉求**：快速定位 bug 根因（要具体到行和变量）；优化建议能给前后对比；自己的 Key 自己充钱，成本可见可控；会话不留服务端。

### Persona 3：老周 — 独立全栈开发者 / 小团队（多语言高频用户）

- **背景**：35 岁，一个人干全栈，前端 Vue/React、后端 Node/Python、偶尔写脚本，什么语言都碰。
- **痛点**：
  - 订阅费叠加（Copilot $10 + Cursor $20 + Claude $20）肉疼；IDE 插件越装越重，换台机器就要重配一遍。
  - Roo Code / Cline 这类 BYOK 插件虽好，但绑定 VS Code，配置 modes 有学习成本。
- **诉求**：一个网页覆盖多语言代码问题；用最便宜的国产 API（DeepSeek / GLM）；换设备零配置（Key 自己保管，会话可导出意识）。

## 三、核心用户旅程

```
首次打开
  → 空状态引导页（产品能力说明 + 示例代码一键填入 + Key 配置入口）
  → 配置 BYOK：选择供应商预设（DeepSeek / 智谱 GLM / Moonshot Kimi / 通义 Qwen / 自定义 OpenAI 兼容端点）→ 粘贴 Key → 选模型
  → Key 仅存入本浏览器 localStorage，界面明示「不会上传到我们的服务器」

核心循环（每次分析）
  → 在代码编辑区粘贴 / 输入代码（自动语言识别 + 手动切换，多语言高亮）
  → 选择能力：分析 / 解释 / 调试 / 优化（或直接输入自定义问题）
  → 点击发送 → 流式输出（打字机效果 + 中止按钮）
  → 结构化结果分区块渲染：问题定位 / 原因分析 / 修改建议 / 优化后代码（代码块带复制按钮）
  → 一键复制单区块或全部

迭代与找回
  → 基于同一会话继续追问（保留代码与对话上下文）
  → 或编辑代码后重新分析（生成新的问答轮次）
  → 关闭浏览器 → 会话自动存入 localStorage → 下次打开从左侧历史列表一键恢复
```

### 4.2 竞品结论

1. **订阅制 + 额度不透明是 2025-2026 年最大的用户怨气来源**（Cursor 风波、v0 credit 争议、Copilot 质量波动）——直接验证我方「BYOK + 成本用户自控」方向。
2. **免登录被真实用户明确渴求**（HN 上 Phind 用户拒绝注册的发言）——而我方把免登录做成产品边界而非功能阉割手段。
3. **Phind 关停是市场信号**：不做「更好的搜索」，做「代码工作流」（四类结构化能力）才能避开被通用 LLM 平台吞没的命运。
4. **结构化输出是空白**：所有竞品要么输出纯文本（Copilot Chat / 通用聊天窗），要么输出待运行的组件（v0），没有一家把「问题定位 / 原因 / 建议 / 优化后代码」作为一等公民渲染。

**成本测算（BYOK 卖点量化）**：一次典型代码分析 ≈ 输入 8K tokens + 输出 2K tokens。

- 结论：平台无需自营推理补贴，「免登录 + 免费 + BYOK」可持续；这也是架构上「服务端仅代理转发、不落库」的成本理由。

## 五、市场空白与差异化机会

1. **零门槛代码分析（免登录真空档）**：所有直接竞品（Cursor / Copilot / v0 / Phind）均要求账号；Phind 关停前 HN 用户明确拒绝注册。我方「打开即用 + localStorage 会话」填的是真空档，且用产品边界（不做账号体系）保证不被商业化侵蚀。
2. **成本透明的 BYOK 模式**：Cursor 定价风波与 v0 credit 争议证明用户要的是「自己看见成本」；Continue/Cline/Roo Code 已验证 BYOK 需求真实存在但绑定 IDE。我方把 BYOK 带到零安装的网页端，并用国产 API 低价（单次约 1 分钱）把「免费」变成可持续事实而非补贴烧钱。
3. **结构化调试输出作为一等公民**：竞品输出要么是纯文本（Copilot Chat、通用聊天窗），要么是待运行组件（v0）。「问题定位 / 原因分析 / 修改建议 / 优化后代码」四区块 + 代码块独立复制，直接命中「Copilot 幻觉多、看完不放心」与「v0 调试工具极简」两大差评根因。
4. **会话级即开即走 vs 项目级重配置**：IDE 插件（Roo Code modes 等）学习成本高、换设备重配；我方会话存浏览器、无项目配置，契合「贴一段代码问一个问题」的轻场景（面试复盘、救急、读源码）。

## 六、MVP 功能清单（RICE 排序）

RICE 公式：Score = (Reach × Impact × Confidence) / Effort。Reach 1-10（每季度受影响用户比例）；Impact 0.25/0.5/1/2/3；Confidence 50%/80%/100%；Effort 1-10（人月，1=半天）。

| # | 功能 | Reach | Impact | Confidence | Effort | Score | 分级 |
|---|------|-------|--------|------------|--------|-------|------|
| 1 | BYOK 配置：供应商预设（DeepSeek/GLM/Kimi/Qwen/自定义 OpenAI 兼容端点）+ Key 存储 + 模型选择 + 安全明示 | 10 | 3 | 100% | 2 | **15.0** | P0 |
| 2 | 代码输入与编辑：多语言高亮（Python/JS/TS/Java/Go/C/C++/Rust/SQL/HTML/CSS 等）、自动语言识别、行号 | 10 | 2 | 100% | 2 | **10.0** | P0 |
| 3 | Agent 对话：流式输出（逐 token 渲染）+ 发送 / 中止 / 重试 + 多轮上下文保持 | 10 | 3 | 100% | 3 | **10.0** | P0 |
| 4 | 代码四类核心能力：分析 / 解释 / 调试 / 优化（能力选择器 = 内置提示词模板） | 10 | 3 | 80% | 3 | **8.0** | P0 |
| 5 | 结构化结果输出：问题定位 / 原因分析 / 修改建议 / 优化后代码四区块，代码块独立复制 | 9 | 3 | 80% | 2 | **10.8** | P0 |
| 6 | 会话历史：localStorage 持久化 + 历史列表 + 一键恢复 + 单条删除 | 8 | 2 | 100% | 2 | **8.0** | P0 |
| 7 | 基础操作：复制（单区块/全部）、清空当前、新建会话 | 10 | 1 | 100% | 1 | **10.0** | P0 |
| 8 | 快捷指令模板库扩充（自定义模板、常用框架预设） | 8 | 2 | 80% | 1 | 12.8 | P1 |
| 9 | Token 消耗与成本预估显示（发送前估算、完成后实际值） | 6 | 1 | 80% | 1 | 4.8 | P1 |
| 10 | 多轮上下文长度管理与超限压缩提示 | 8 | 2 | 80% | 2 | 6.4 | P1 |
| 11 | 导出会话为 Markdown | 5 | 1 | 80% | 1 | 4.0 | P1 |
| 12 | 优化前后 diff 对比视图 | 7 | 2 | 80% | 3 | 3.7 | P1 |

> 说明：第 8 项 RICE 高于部分 P0，但 P0 能力选择器（第 4 项）已覆盖其 80% 价值（四能力即四个内置模板），完整模板库列为 P1；MVP 范围严格收敛为第 1-7 项。

### MVP 范围（仅保留以下 7 项，其余全部进 Backlog）

1. BYOK 配置（无此功能则产品无 LLM 能力，是架构必需项）
2. 代码输入与编辑（多语言高亮）
3. Agent 对话（流式输出 + 中止 + 重试）
4. 代码四类核心能力（分析 / 解释 / 调试 / 优化）
5. 结构化结果输出（四区块 + 代码块复制）
6. 会话历史（localStorage 持久化 + 列表 + 恢复）
7. 复制 / 清空 / 新建会话等基础操作

**明确不做**：账号体系、付费订阅、团队协作、云端同步、代码执行运行环境、多文件项目管理。

## 七、成功指标

| 类型 | 指标 | 目标值 | 说明 |
|------|------|--------|------|
| **北极星** | 周有效分析会话数（每周至少完成 1 次四类核心能力调用且流式正常结束的去重会话数） | 上线后 4 周内周环比增长 > 20% | 直接衡量「用户是否真的拿到了结构化代码分析价值」，抗虚荣指标（不以注册计） |
| 护栏 1 | 流式首 token 延迟 p95 | < 3s | 流式体验是编程 Agent 的生命线，超时即流失 |
| 护栏 2 | 请求错误率（含 Key 无效 / 限流 / 上游故障） | < 5%，且 100% 错误有分类提示 | 错误可见、可操作，不裸奔 |
| 护栏 3 | 会话恢复率（7 日内重新打开历史会话的用户占比） | ≥ 30% | 验证 localStorage 会话价值与真实留存；低于 20% 说明产品是一次性工具 |

## 八、风险与依赖

| # | 风险 / 依赖 | 影响 | 应对 |
|---|-------------|------|------|
| 1 | **LLM API 第三方依赖**：供应商可用性、限流、模型质量波动（前车之鉴：Copilot 因模型轮换出现质量回归） | 核心功能不可用或输出质量下降 | 多供应商预设 + 一键切换；错误分类（限流/鉴权/超时）；提示词不绑定单一模型特性 |
| 2 | **Key 安全（BYOK）**：Key 存浏览器 localStorage，存在 XSS 窃取与共用设备泄露风险 | 用户资产损失、信任崩塌 | 严格 CSP；Key 不明文进日志、服务端不落库不记录；提供一键清除 Key；界面明示安全模型（见第九章） |
| 3 | **服务端代理被滥用**：代理转发若无限制会成为免费公共 LLM 网关 | 代理成本与稳定性受损 | 按 IP/会话速率限制；请求体大小上限（建议 200KB 代码 + 上下文）；单请求超时；不记录请求内容 |
| 4 | **localStorage 容量限制**（浏览器约 5MB）：长会话 / 大代码可能写满 | 会话保存失败、数据丢失 | 写入前容量预检；超限提示清理或（P1）导出；关键会话损坏时降级为内存存储并提示 |
| 5 | **数据合规与隐私**：用户代码经代理发往第三方 LLM，各供应商数据政策不同（部分可能用于训练） | 企业用户合规风险 | 供应商选择处明示各供应商数据政策链接；对「公司代码」类场景给出明确风险提示；服务端零留存 |
| 6 | **浏览器隐私模式**：部分场景 localStorage 不可用 | 会话历史失效 | 检测可用性，不可用时降级内存存储 + 顶部提示 |

## 九、产品边界说明（免登录 + BYOK）

### 9.1 免登录（无账号体系）

- 产品**没有注册 / 登录 / 密码找回**任何流程；不采集手机号 / 邮箱。
- 所有会话数据（对话、代码、配置）仅存于用户当前浏览器的 localStorage，**服务端不存任何用户会话数据**。
- 后果与约定：换浏览器 / 换设备 / 清缓存即丢失历史（UI 需明示）；localStorage 容量上限约 5MB，超出时提示清理或导出（导出为 P1）。
- 多标签页场景：通过 storage 事件同步历史列表，避免覆盖。

### 9.2 BYOK（Bring Your Own Key）模式

- **Key 的存放**：用户 LLM API Key 仅保存在用户自己浏览器的 localStorage，不上传、不经过服务端持久化。
- **服务端角色**：仅做「代理转发」——将前端请求透传至用户选择的 LLM 供应商端点；**不落库、不写日志、不记录请求体与响应体**；代理层只做速率限制、大小限制、超时控制。
- **计费关系**：用户与 LLM 供应商直接结算，平台不经手资金、不抽成、不设额度。用户成本可见可控（见 4.3 成本测算）。
- **安全边界**：HTTPS 全站；前端防 XSS（CSP）；Key 输入框提供「仅本机存储」明示与一键清除；企业敏感代码场景提示供应商数据政策差异。
- **配置预设**：DeepSeek / 智谱 GLM / Moonshot Kimi / 通义 Qwen + 自定义 OpenAI 兼容端点（Base URL + Key + 模型名）。

## 十、验收标准（Given / When / Then）

1. Given 用户首次打开应用且未配置 Key，When 点击发送按钮，Then 不发起请求，引导至 Key 配置区并说明用途。
2. Given 用户已配置有效 Key，When 粘贴一段含 bug 的 Python 代码并选择「调试」后发送，Then 3 秒内出现首 token 流式输出，且最终结果包含「问题定位 / 原因分析 / 修改建议 / 优化后代码」四个区块。
3. Given 分析正在进行，When 点击中止按钮，Then 流式输出立即停止，已生成内容保留在会话中，可编辑代码后重新发送。
4. Given 一次会话已完成，When 关闭并重新打开浏览器，Then 历史列表包含该会话（标题取首条消息摘要），点击后完整恢复代码与全部对话。
5. Given localStorage 写入将超出配额，When 保存新会话，Then 应用不崩溃，提示用户清理历史或导出，且已有会话不损坏。
6. Given Key 无效 / 欠费 / 被限流，When 发送请求，Then 显示对应错误分类与处理建议（如「Key 无效，请检查」「触发限流，请稍候或切换供应商」），不暴露原始堆栈与供应商原始报文。
7. Given 用户在编辑区输入代码并选择语言，When 切换语言（如 Java），Then 语法高亮、行号、缩进正确应用，支持 P0 语言清单内全部语言。
8. Given 视图宽度 360px（移动端），When 打开应用，Then 布局自适应（编辑区与对话区可切换访问），无横向溢出，核心按钮可点击。
9. Given 上游 LLM 超时（如 60s 无响应），When 请求失败，Then 显示超时提示 + 重试按钮 + 切换供应商建议入口。
10. Given 两个标签页同时打开应用，When 标签页 A 删除一会话，Then 标签页 B 的历史列表同步更新（storage 事件）。

## 十一、边界条件

- **空状态**：首次打开无会话、无 Key → 引导页（产品能力说明 + 示例代码一键填入 + Key 配置入口），不使用空洞占位文案。
- **错误状态**：Key 无效 / 网络失败 / 上游超时 / 限流 / 内容安全拒绝 → 分类提示 + 重试 + 降级建议（切换供应商或模型）；前端不白屏。
- **加载状态**：首 token 到达前 → 思考中指示（骨架 / 呼吸灯动画）+ 已等待时间；流式中 → 逐 token 渲染 + 中止按钮。
- **边界值**：空代码 / 纯空白发送 → 发送按钮禁用 + 提示；超长代码（建议 >100KB）→ 前端提示可能触发上游上下文截断；单会话轮次过多 → 提示上下文长度风险（P1 做压缩管理）。
- **并发**：同一会话流式输出中禁止再次发送；多标签页 localStorage 变更通过 storage 事件同步。
- **离线**：断网时发送 → 明确「网络不可用」提示；已生成内容不丢失（localStorage）。
- **权限拒绝**：供应商返回内容安全拒绝 → 原样透传状态码含义 + 建议调整输入措辞，不猜测不编造。

## 十三、数据埋点方案

MVP 必须埋点的关键事件（不埋 = 上线后无法验证产品假设）：

| 事件类别 | 必埋事件 | 说明 |
|----------|----------|------|
| 获客 | page_view, first_visit | 新访客来源与首访 landing |
| 激活 | key_configured, first_core_action | Key 配置完成率；首次完成四类核心能力调用（分析/解释/调试/优化任一） |
| 留存 | session_start, session_duration, session_restored | DAU/MAU、使用频次、历史会话恢复率（护栏指标 3） |
| 转化 | （MVP 无付费，预留 upgrade_click / payment_complete 空位） | 为后续商业化预留漏斗，不上报任何 Key 内容 |
| 异常 | error_occurred | 前端错误 + API 错误（含分类：key_invalid / rate_limit / timeout / network / upstream） |

**埋点实现要求**：
- 前端轻量 SDK 或自建 `trackEvent()` 封装，事件命名规范 `{对象}_{动作}`（如 `key_configured`, `code_analyzed`, `stream_completed`, `session_restored`, `error_occurred`）。
- 属性规范：每个事件附带 `user_id`（匿名会话 ID，localStorage 生成）、`timestamp`、`device`、`version`。
- **隐私红线**：不采集 Key、不上报 IP、不存储原始代码与对话内容、不记录上游供应商原始报文。

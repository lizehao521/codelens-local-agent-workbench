第一步（T0）：精确定义 + 绝对硬底线

定义

自适应沙箱 = 在「静态 jail 根不可变、硬底线不可变」的前提下，把「工作区外普通目录的授权决策」从「人工逐目录弹窗授权」升级为「由任务上下文信号 + 风险信号 + 历史行为信号驱动的、有界的、可审计可回滚的自动授权/拒绝/降级决策」，且每一次自动决策都必须比人工授权更保守或同等保守（自动授权的范围 ⊆ 人工会授权的范围，自动授权的权限 ⊆ 人工授权的权限）。

三个关键词的精确语义：

  • 有界：自适应只能产生「临时、只读、单目录、带 TTL」的授权，永远不能产生写权限、永远不能跨目录、永远不能永久化。写权限与永久授权仍然必须走人工弹窗。
  • 可证伪：给定相同的信号输入，决策必须是确定性的纯函数（无随机、无时间依赖除 TTL 外），因此可以离线重放、可以构造反例证明其拒绝行为。
  • 可回滚：每一次自适应授权都写入审计日志并携带 rollbackToken，一键撤销该 token 对应的全部临时授权，且撤销后立即 fail-closed。

绝对硬底线（永不自适应放宽）

底线 含义 自适应能做什么
jail 根 SANDBOX_ROOT 本身及其校验逻辑不可变；自适应产出的目录永远只是「追加进 allowedDirs 的临时项」，jail 根不变 只能在 jail 根之外追加临时只读目录，且该目录必须通过现有 validateAllowDir 的全部硬校验
SSRF http_request 的协议/重定向/内网校验完全不受自适应影响 自适应不作用于 http 工具，零联动
sys.exec never_exempt exemptCategory('sys.exec') 恒 null，runGateway 对 exec 的 approvalMode==='none' 兜底 SECURITY_DENIED 自适应不得为 exec 产生任何豁免键；自适应信号里出现的 exec 历史只作为风险升級信号，永不作为放行依据
敏感路径 isSensitivePath（.ssh/.aws/浏览器配置/密钥）与 RESTRICTED_DIR_PREFIXES 命中即拒 自适应在判定之前先跑这两个校验，命中直接 SECURITY_DENIED，不进入任何信号评分
.. 穿越 现有「.. 穿越永不弹直接拒」 自适应同样永不放行，且把「任务上下文中出现 ..」记为风险信号
PROTECTED tests/ scripts/ agent/ judge/ rsi/ eval/ 自适应产出的目录若 realpath 后落入 PROTECTED，直接拒

T0 verdict：通过。 定义满足「可证伪、可跑、不破安全底线」；硬底线清单闭合，自适应的作用域被压缩到「工作区外普通目录的临时只读授权」这一最小面。

第二步：π 递进回归（3 轮）

轮次 1 —— 现状与风险

T（问题）：静态沙箱在长任务/多目录场景要人反复授权，易过授权疲劳——用户为了省事会点「允许写」「永久允许」，把本来只读一次的需求变成永久写授权。

M（度量/判据）： - M1 授权疲劳度：单个任务内人工授权弹窗次数 ≥3 即视为疲劳风险； - M2 过授权度：人工授权中「写权限」占比、「永久授权」占比； - M3 安全回归：任何自适应放行若绕过 validateAllowDir / isSensitivePath / RESTRICTED_DIR_PREFIXES 任一校验，即判失败。

Update（自适应的精确定义与可证伪判据）：

可证伪判据（Falsifiability Criteria, FC）： - FC-1 正当放行：任务上下文明确引用某普通目录（如用户消息里出现「读一下 /data/reports 下的文件」），且该目录通过全部硬校验 → 自适应应产出「只读、TTL=任务级、单目录」授权，不再弹窗。 - FC-2 越界拒绝：任务上下文未引用、或引用了但 realpath 后落入 RESTRICTED/PROTECTED → 必须 SECURITY_DENIED，且审计日志记录拒绝原因。 - FC-3 敏感路径拒绝：即使任务上下文明确引用 ~/.ssh，也必须在信号评分之前被拒。 - FC-4 exec 不豁免：无论自适应信号多强，sys.exec 的 exemptCategory 仍恒 null，两步确认不变。 - FC-5 可回滚：任意时刻撤销 rollbackToken 后，同一目录的再次访问必须重新走决策（且默认 deny）。

// adaptive-sandbox.types.ts —— 自适应沙箱的类型与硬底线（纯类型 + 纯函数，零副作用）
export type AdaptiveVerdict = 'allow_readonly_temp' | 'deny' | 'escalate_to_human';

export interface AdaptiveSignals {
  readonly taskId: string;
  readonly requestedPath: string;        // 工具调用请求的原始路径
  readonly taskContextRefs: readonly string[]; // 任务上下文中被明确引用的目录（由宿主提取）
  readonly riskFlags: readonly RiskFlag[];
  readonly history: readonly HistoryEntry[];
}

export type RiskFlag =
  | 'dotdot_in_context'       // 上下文出现 ..
  | 'exec_in_task'            // 任务内出现过 sys.exec 调用
  | 'repeated_denied'         // 同目录近期被拒 >=2 次
  | 'write_intent';           // 工具调用是写操作

export interface HistoryEntry {
  readonly path: string;
  readonly action: 'granted' | 'denied' | 'revoked';
  readonly at: number;
}

export interface AdaptiveDecision {
  readonly verdict: AdaptiveVerdict;
  readonly reason: string;
  readonly rollbackToken: string | null;  // deny 时为 null
  readonly ttlMs: number;                 // allow 时有效，deny 时为 0
  readonly auditId: string;
}

轮次 2 —— 方案

T：要给可落地设计，且必须与 exp67 边界声明表（loadBoundary/getBoundary/selfCheck）联动，而不是另起一套硬编码。

M：设计完整性判据——信号→判定→执行→审计四环闭合；边界声明表是自适应的输入约束而非旁路；状态机可穷举。

Update：核心判定逻辑 + 与 selfCheck 联动。

联动方式（关键设计裁定）：exp67 的边界声明表声明了每个 subject 的三态（autonomous / approval_required / never_exempt）。自适应沙箱消费这张表作为硬约束：

  • sys.exec 在表里是 never_exempt → 自适应决策器在入口处查表，若 subject 为 exec 类，直接返回 deny（连信号评分都不进）。
  • fs.read 类是 autonomous → 自适应可以对其产出 allow_readonly_temp。
  • fs.write/purge/httpWrite 是 approval_required → 自适应最多产出 escalate_to_human，永不自动放行写。
  • selfCheck(host) 报 BOUNDARY_DRIFT 时 → 自适应全局降级为「全部 escalate_to_human」，即漂移期间冻结自动放行，只告警不阻断的语义保持不变（人工授权仍可用）。

代码增量（轮次 2：决策器，落点 src/services/tools/adaptive-sandbox.service.ts，新文件，≤300 行）：

// adaptive-sandbox.service.ts —— 自适应决策器（纯函数 decide + 薄状态）
import type {
  AdaptiveDecision, AdaptiveSignals, AdaptiveVerdict,
} from './adaptive-sandbox.types.js';

// 由宿主注入的既有能力签名（不反向依赖执行逻辑，与 exp67 声明模块同约束）
export interface AdaptiveHost {
  readonly realpath: (p: string) => string;                 // 解析 symlink
  readonly validateAllowDir: (real: string) => boolean;     // 复用现有硬校验全集
  readonly isSensitivePath: (real: string) => boolean;      // 复用现有敏感路径
  readonly isRestricted: (real: string) => boolean;         // RESTRICTED_DIR_PREFIXES
  readonly isProtected: (real: string) => boolean;          // PROTECTED 六目录
  readonly boundaryOf: (subject: string) =>                 // exp67 getBoundary
    'autonomous' | 'approval_required' | 'never_exempt';
  readonly driftDetected: () => boolean;                    // exp67 selfCheck 结果
  readonly now: () => number;
  readonly uuid: () => string;
}

const TTL_TASK_MS = 30 * 60 * 1000; // 任务级 TTL 上限 30min，可配但不得超

export function decide(host: AdaptiveHost, sig: AdaptiveSignals): AdaptiveDecision {
  const auditId = host.uuid();
  const deny = (reason: string): AdaptiveDecision =>
    ({ verdict: 'deny', reason, rollbackToken: null, ttlMs: 0, auditId });

  // —— 第 0 层：边界声明表硬约束（先于一切信号）——
  const subject = sig.riskFlags.includes('write_intent') ? 'fs.write' : 'fs.read';
  const boundary = host.boundaryOf(subject);
  if (boundary === 'never_exempt') return deny('boundary:never_exempt');

  // —— 第 1 层：硬底线前置校验（命中即拒，不进评分）——
  let real: string;
  try { real = host.realpath(sig.requestedPath); }
  catch { return deny('realpath:failed'); }
  if (sig.requestedPath.includes('..')) return deny('dotdot:never');
  if (host.isSensitivePath(real)) return deny('sensitive:never');
  if (host.isRestricted(real)) return deny('restricted:never');
  if (host.isProtected(real)) return deny('protected:never');
  if (!host.validateAllowDir(real)) return deny('validateAllowDir:failed');

  // —— 第 2 层：漂移降级（selfCheck 联动）——
  if (host.driftDetected()) {
    return { verdict: 'escalate_to_human', reason: 'boundary_drift:freeze_auto',
             rollbackToken: null, ttlMs: 0, auditId };
  }

  // —— 第 3 层：写意图永不自动放行 ——
  if (boundary === 'approval_required' || sig.riskFlags.includes('write_intent')) {
    return { verdict: 'escalate_to_human', reason: 'write:human_only',
             rollbackToken: null, ttlMs: 0, auditId };
  }

  // —— 第 4 层：风险信号升級 ——
  if (sig.riskFlags.includes('dotdot_in_context')
      || sig.riskFlags.includes('repeated_denied')) {
    return { verdict: 'escalate_to_human', reason: 'risk:escalated',
             rollbackToken: null, ttlMs: 0, auditId };
  }
  // exec_in_task 只升級不放行（exec 历史是风险而非信用）
  const execRisk = sig.riskFlags.includes('exec_in_task');

  // —— 第 5 层：正当性判定（任务上下文必须明确引用该目录）——
  const referenced = sig.taskContextRefs.some((ref) => {
    try { return host.realpath(ref) === real; } catch { return false; }
  });
  if (!referenced) return deny('context:not_referenced');

  // —— 第 6 层：历史行为（曾被 revoked 的目录不再自动放行）——
  const revokedBefore = sig.history.some(
    (h) => h.action === 'revoked' && safeEq(host, h.path, real));
  if (revokedBefore) {
    return { verdict: 'escalate_to_human', reason: 'history:revoked_before',
             rollbackToken: null, ttlMs: 0, auditId };
  }

  return {
    verdict: execRisk ? 'escalate_to_human' : 'allow_readonly_temp',
    reason: execRisk ? 'risk:exec_in_task' : 'context:referenced+all_checks_passed',
    rollbackToken: execRisk ? null : host.uuid(),
    ttlMs: execRisk ? 0 : TTL_TASK_MS,
    auditId,
  };
}

function safeEq(host: AdaptiveHost, a: string, b: string): boolean {
  try { return host.realpath(a) === b; } catch { return false; }
}

状态机（可穷举，四态）：

             ┌──────────────────────────────────────────────┐
   请求 ──►  │ L0 边界表 never_exempt? ──► DENY              │
             │ L1 硬底线(敏感/受限/保护/../realpath)? ──► DENY │
             │ L2 漂移? ──► ESCALATE(冻结自动)               │
             │ L3 写/approval_required? ──► ESCALATE         │
             │ L4 风险信号? ──► ESCALATE                      │
             │ L5 上下文未引用? ──► DENY                      │
             │ L6 历史 revoked? ──► ESCALATE                  │
             │ 全过 ──► ALLOW_READONLY_TEMP(TTL, token)      │
             └──────────────────────────────────────────────┘
   ALLOW --TTL到期/revoke--> 失效 --> 再次访问回到 L0（默认 DENY）

第三步：最终设计

① 信号 → 判定 → 执行 → 审计（四环）

  • 信号采集（宿主侧新增 adaptive-signal.collector.ts）：从任务上下文提取「被明确引用的目录」（只对用户消息与工具参数做路径词法提取，不做语义猜测）；从 gateway 日志提取 riskFlags；从 grant 历史提取 history。
  • 判定：上面的纯函数 decide，确定性、可离线重放。
  • 执行：allow_readonly_temp 时，宿主把 { realpath, readOnly: true, expiresAt, rollbackToken } 追加进 SandboxPermissionService 的临时层（与人工 allowDirs 分层存放，互不污染）；TTL 到期或 revoke 即移除，移除后默认 deny。escalate_to_human 走现有弹窗链路，零改动。
  • 审计：每次 decide 写一条 { auditId, taskId, requestedPath, realpath, verdict, reason, rollbackToken, signalsHash, at }；revoke 写一条 { rollbackToken, revokedAt }。审计只增不改。

② 与边界声明表的联动

  • decide 的 L0 直接调 exp67 getBoundary(subject)，三态决定天花板：never_exempt→deny、approval_required→最多 escalate、autonomous→可 allow_readonly_temp。
  • selfCheck(host) 报 BOUNDARY_DRIFT → driftDetected() 为真 → 全局冻结自动放行（L2），保持 exp67「只告警不阻断人工链路」的语义。
  • 边界声明表是自适应的唯一权威来源，自适应模块内不出现任何 subject→三态的硬编码副本。

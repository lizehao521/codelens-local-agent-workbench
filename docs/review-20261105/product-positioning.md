# CodeLens v2.0 产品定位与目标受众（2026-11-05 复核版）

> **本轮定位决断（2026-11-05，用户拍板）**：CodeLens 收敛为**个人工具**——先当个人 / 小范围自用工具打磨，**不铺商业化路线**。
> 「团队版 / 企业版 / 多租户」一律降级为**暂不承诺**，本文档不再写没有实现支撑的商业化叙事。
> 本文所有价值主张、场景、成功判据均以**单人使用**为准；成本由用户自带 Key 承担，这一点在 §3.4 如实写明（既是特点也是约束）。

> 这份文档不重新发明定位：定位结论沿用 [`docs/product-positioning-decided.md`](../product-positioning-decided.md) 的决断版。
> 本轮只做两件事：**(1) 把定位与实际代码逐条对齐，指出仍偏离的地方；(2) 给出成本分级明确的收口建议。**
> 事实来源：`README.md`、`产品宪法补丁.md`、`强化Agent.txt`、`docs/agent/spec.md`、`server/src/**`、`client/src/**`，以及本轮实测（见 `evaluation-report-2026-11-05.md`）。文中数字均标注性质：**实测 / 代码事实 / 待确认**。

## 1. 产品是什么（代码事实）

**一句话（对外）**：一个跑在你自己机器上的**个人** Agent 工作台——一句话交代任务，它在本地自主调用工具、每步可见、按风险分级向你请示；密钥用你自己的（BYOK），不出本机。

**技术形态（代码事实）**
- `server/`：Node + Express + `node:sqlite`，本地单用户单实例；SQLite 落库会话/消息/工具调用/审批/判据。
- `client/`：React SPA「三栏工作台」——左会话列表、中对话与执行过程、右运行检视器（RunInspector / 上下文占用 / 判据）。
- `desktop/`：Electron 壳，把同一套 server+client 打包成本地桌面应用。
- 启动：`npm start`（dev）/ `npm run build && node server/dist/app.js`（production）/ 桌面端安装包。

**能力面（代码事实，不是规格愿景）**
- 内置工具 12 个：`fs.read`、`fs.list`、`fs.write`、`sys.exec`、`http.request`、`calc.evaluate`、`json.format`、`text.diff`、`time.now`、`uuid.generate`（+ 路径监狱 `path-jail`、`sys-exec.policy` 两个安全件）。
- 风险分级审批：`none / soft / hard / two_step` 四档；`sys.exec` 结构上恒为 hard，自动放行开关无法豁免（测试已覆盖）。
- 过程可视化：流式回答 + 工具卡片 + 审批条 + 判据塔（L0 客观信号 → 更深层判据）+ 轨迹回放；审计台按「文件 / 步骤」查看快照 before/after 的历史 diff，并可反向跳到该步审批与撤销。
- 长任务治理：四道预算（迭代数 / 工具调用总数 / 累计 token / 墙钟）同时生效，到顶先写 RunState 终态再停；连续 N 轮无文件改动、无新证据、无工具结果变化判收敛并主动停；从 runId 续跑前逐文件比对磁盘 sha256，冲突即停不覆盖。
- 上下文治理：占用条、压缩、预算/回退预算。
- 生态：技能库（本地 skill）、MCP 客户端（stdio server 可接入）、多上游 provider（deepseek / zhipu / moonshot / qwen / openai / nvidia / custom baseURL）。
- 找回：会话恢复码（HMAC 派生）+ 设备令牌，换浏览器/换机可续。

**它明确不做的事（`docs/agent/spec.md` + README）**：不做多租户 / 团队协作云端；不托管用户密钥；不对「自我强化 / 智能自动提升」做量化承诺；**不提供团队版 / 企业版的任何承诺（暂不承诺）**。

## 2. 解决谁的什么问题（受众画像）

> 口径：**只有「个人开发者 / 重度单机使用者」是目标用户**。团队、企业、需要账号体系与多人协作的组织不在目标内；本文不再把他们写成「次要用户」或「未来的团队版」。

| Persona | 角色 / 场景 / 规模 | 核心痛点 | 为什么选 CodeLens |
|---|---|---|---|
| A 小林（入门/自学） | 22 岁上下，CS 学生或转行，**个人机、单会话、单人使用** | 装不动 Dify（多容器）、不敢装 IDE 插件污染环境、怕黑盒搞坏东西、问「弱智问题」有压力 | 开浏览器即用、免注册、**每一步可见**、可用低价国产 API |
| B 阿豪（后端工程师） | 28 岁上下，Java/Go，**一个人在自己机器上**调试内网接口、私有部署模型 | 终端/日志/IDE 来回切；聊天窗够不到内网；公司代码不能贴第三方账号体系 | 本地 `http.request` + `fs.read` + 风险分级审批；Key 自控、成本可见 |
| C 老周（独立开发者 / 自由职业者） | 35 岁上下，**单人**全栈，本机已有 MCP server | 订阅叠加、IDE 插件越装越重、自建 MCP 锁死在 IDE 里 | MCP/上游一等公民，网页端接本机 stdio server，数据不出本机 |
| D 老陈（隐私/成本敏感的个人开发者） | **个人**研究者 / 独立开发者，本机有敏感数据；**不是团队采购决策者** | 数据出境零容忍、订阅账单失控、Dify 太重 | 单实例自托管、BYOK、单容器维护；只服务他一个人 |

**受众边界**：A→B→C→D 是「可见性 → 深度调用 → 私域生态 → 隐私主权」的递进，**终点仍是单人**。**非技术通用用户暂无证据**，对外不喊「人人可用」；**团队 / 企业 IT / 多租户明确不做，且暂不承诺任何团队版**。

### 2.1 受众分层（按现有功能边界划，不按想象划）

| 层级 | 是谁 | 判断依据（来自代码里已有的边界） | 我们对他承诺什么 |
|---|---|---|---|
| **核心用户** | B 后端工程师、C 独立开发者；每天在本机跑命令/读写文件、已有自己的 LLM Key | ① `sys.exec` 恒 hard、`path-jail`、SSRF guard 只有「要跑命令/要碰文件」的人才用得上；② 上游列表是 deepseek/zhipu/moonshot/qwen/openai/nvidia/custom（`server/src/providers/registry.ts`），全是开发者常用；③ MCP stdio 客户端只在本地开发机上成立 | 一句话跑完多步任务；每步可审、可改参、可单步重跑；Key 不出本机 |
| **次要用户** | A 入门/自学者、D 隐私/成本敏感的个人开发者（自己一个人用，不替团队做采购） | ① 首启有免 Key 试用（`TRIAL_MODE_ENABLED`）+ 空态示例任务，说明「不会配 Key 也能先试」；② 审批条、运行检视器、恢复码是给「不放心/要交接给自己另一台机器」的人；③ 但 `http.request`、`sys.exec` 的参数仍需读得懂命令 | 不用装环境就能试；每一步看得懂；额度/成本有闸（每日限次 + token 预算） |
| **明确不服务（暂不承诺）** | **团队 / 企业 / 多租户 IT**、需要账号体系与云端协作的组织、完全不懂命令行的通用用户、需要托管密钥的托管服务用户 | ① 单实例、单用户、无账号/组织模型（`server/src/db` 只有会话与设备令牌）；② README 明写「不托管用户密钥」；③ 无团队空间、无共享会话、无审计后台；④ 空态示例全部是文件/命令类任务 | **不承诺团队版 / 企业版**、不承诺 SLA、不承诺多人协作、不承诺「零命令行基础也能跑高危任务」 |

判断原则：**有对应实现件才归入该层；没有实现件的一律不写进定位**。所以「人人可用的 AI 助手」「企业级 Agent 平台」都不在本产品叙事里。

## 3. 核心价值与差异化（真差异，不是口号）

对外可承诺的感知层只有四条：
1. **省心可控**：一句话交代，关键处你拍板。
2. **看得见**：每步工具调用、参数、结果、判据都在界面上。
3. **数据与密钥留在你机器**（BYOK + 本地优先）。
4. **接得进你已有的东西**（MCP / 多上游 / 技能库）。

真正的差异楔子（竞品确实没有同时给到的组合）：**网页 GUI + 过程可视化 + 风险分级审批闸 + 跨浏览器恢复码**。
⚠️ 必须把 **OpenCode** 当同轴线处理：它同样「本地 + BYOK + 零成本」，CodeLens 相对它的差异只剩 GUI/审批闸/恢复码。用「本地 BYOK」当独占卖点会被立刻反驳。

### 3.1 典型使用场景（触发 → 流程 → 成功判据）

| # | 场景 | 触发 | 流程（对应实现） | 成功判据 |
|---|---|---|---|---|
| 1 | **本机文件整理** | 「把 `data/` 下的日志按日期归档」 | `fs.list` → `fs.read` → `fs.write`（soft 审批）→ 结果回填；审批条可改参 | 文件真实落盘；审批记录与工具结果能在右栏 `RunInspector` 查到 |
| 2 | **内网接口联调** | 「请求这个内网接口，把返回 JSON 格式化」 | `http.request`（SSRF guard 拦内网元数据地址）→ `json.format` | 响应进入对话，请求/响应在工具卡片与检视器可回看 |
| 3 | **高风险命令** | 「跑测试并修掉失败用例」 | `sys.exec`（恒 hard，自动放行不可豁免）→ 审批 → 改参重批 / 单步重跑 | 审批留痕、命令输出完整、失败步骤可单独重跑（AC-10） |
| 4 | **换机继续** | 换浏览器/换机后「继续上次会话」 | 会话恢复码（HMAC 派生）+ 设备令牌 | 会话、消息、工具调用、审批完整恢复，旧恢复码立即失效 |
| 5 | **零配置试用** | 第一次打开、没有任何 Key | 顶部试用横幅 → 服务端固定上游/模型 → 一句话 → 工具调用 → 审批 → 落盘 | 不配置任何东西也能完成一次任务；剩余次数可见；要换上游时给出「自带 Key」入口 |

场景 1–4 均在代码里有对应实现件；场景 5 是 2026-11-05 本轮新增（见 §4 偏差 8）。

### 3.2 竞争参照与差异化（只写已实现的能力）

| 维度 | CodeLens v2.0 | OpenCode / CLI 类 Agent | IDE 插件类（Cline/Roo 等） | Dify / 云端工作台 |
|---|---|---|---|---|
| 形态 | 浏览器三栏工作台 + Electron 桌面壳 | 终端 TUI/CLI | 编辑器侧边栏 | Web 平台（多容器/云） |
| 密钥 | BYOK，Key 存浏览器、服务端只转发不落库 | 环境变量/本地配置 | 扩展设置 | 平台托管或自带 |
| 风险闸 | 四档审批（none/soft/hard/two_step），`sys.exec` 恒 hard（有测试） | 多为逐次确认/参数确认 | 有确认弹窗，但无统一分级与留痕 | 工作流节点内审批，偏编排 |
| 过程可视化 | SSE 事件 + 工具卡片 + 审批条 + 判据塔 + 轨迹回放 + 审计台（快照 diff，可按步骤溯源） | 终端日志 | 编辑器内联 diff/终端 | 运行日志/追踪页 |
| 会话找回 | 恢复码 + 设备令牌，换浏览器可续 | 本地文件 | 依赖 IDE 工作区 | 账号体系 |
| 多租户/团队 | **明确不做** | 不做 | 不做 | 强项 |

结论：**不与 Dify 比平台化、不与 IDE 插件比内联编辑**；差异押在「网页 GUI 里也能有本地执行 + 分级审批 + 可回放轨迹 + 免账号找回」。

### 3.3 价值主张一句话 + 三点证据

**一句话**：给**个人开发者**的本地 Agent 工作台——**一句话动手，每步看得见，风险你拍板，密钥不出本机**。

| 证据 | 落到哪里 |
|---|---|
| ①「每步看得见」不是文案：`tool_call / tool_progress / tool_result / tool_approval_required` 是 SSE 十事件里的独立事件，前端逐条渲染 | `server/src/services/agent/agent-loop.service.ts`、`client/src/services/stream.ts`、`client/src/components/agent/RunInspector.tsx` |
| ②「风险你拍板」有结构约束：四档审批，`sys.exec` 恒为 hard 且自动放行开关无法豁免（测试覆盖） | `server/src/services/approval`、`server/tests/sys-exec*.test.ts` |
| ③「密钥不出本机」有实现约束：Key 只存浏览器，服务端代理转发、不落库、不记日志；错误文案对 Key 打码 | `client/src/stores/settingsStore.ts`、`client/src/services/api.ts`（`redactSecrets`）、`server/src/providers/openai-compatible.adapter.ts`（`maskKey`） |

### 3.4 成本模型：用户自带 Key（既是特点，也是约束）

**实话写在前面**：CodeLens 自己不卖模型额度。你用的每一次推理，都由**你自己配置的 API Key** 按上游价格计费。

- **这是特点**：没有订阅溢价、没有平台加价；换更便宜的国产上游就能降本；Key 只在本机流转。
- **这是约束**：不开 Key 就不能用（试用模式只用于演示，受次数与 token 预算闸限制）；长任务、多轮工具循环的成本由你自己承担；上游涨价/限流也由你自己应对。
- **不承诺**：不承诺「免费无限用」，不承诺替用户兜底成本，不承诺团队共享一把 Key 的企业计费模型。

单人使用的成功判据也因此收敛为：**在一次个人任务里，用户知道自己在花谁的钱、花在哪一步、结果是否落盘可查**——而不是「组织级成本治理」。

## 5. 定位层改进建议（按成本/收益排序）

1. **零成本·已完成**：README Hero/桌面端/退役口径对齐决断版 → 见本轮 diff。
2. **零成本·建议排期**：把「判据塔 / Judge」在 UI 上改为两层语言——面向用户的一层叫「结果校验」，展开后才说判据细节；避免新用户看到内部机制名。
3. **低成本·本轮已完成**：CJK 字体从 3 字重收敛到 2 字重（400/500，600 由浏览器合成加粗），实测字体体积 **16.76 MB → 10.73 MB（−36%）**，产物 11.68 MB；视觉验收建议在下轮浏览器回归时一并确认。
4. **低成本**：在首屏空态加一行「换台机器？用恢复码找回」入口，兑现「免注册即用」的连续性承诺（本轮仍待排期）。
5. **需决策**：开源 / 闭源策略正式拍板并在 README、落地页、`package.json` 三处同口径声明；决定前，对外叙事继续押在「GUI + 审批闸 + 恢复码」，不押「本地 BYOK」独占。
6. **本轮已完成**：试用态「锁固定上游 + 可配置兜底」写进 README 与首屏文案；上游故障（401/403/超时/不可达/模型不存在）在界面给出中文原因、错误码、建议动作与一键配 Key 入口。

## 6. 结论

定位本身已经足够锐利，问题不在「讲什么」，而在**「讲的与做到的差一截」**：首轮修掉了过程可视化在首 token 空窗掉线、README 口径未落地、字体断链；本轮修掉了**试用态的定位级缺陷**——未带 Key 的用户被承诺「开箱即用」，实际却因 provider 与兜底 Key 不匹配必然 401，首跑白屏。

修完后，「看得见、管得住、钥匙不出本机」第一次贯穿到**零配置首跑**这条最短路径：试用横幅说清当前用的是哪个上游/模型（`AppShell.tsx`），设置页把切换入口解释清楚并置灰（`ProviderZone.tsx`），上游出错时给的是中文原因 + 建议动作 + 一键配 Key（`AgentWorkbench.tsx`），而不是一行裸报错。剩余偏差集中在「术语门槛」（P1）、「恢复码首屏入口」（P2）与「开源声明」（P2，需产品决策）。

# CodeLens v2.0 产品定位与目标受众（决断版）

> 文档性质：定位与受众定稿（分析/设计，不含代码）
> 事实边界：所有结论锚定仓库现行真相源——`README.md`、`产品宪法补丁.md`、`强化Agent.txt`、`docs/agent/spec.md`、`docs/product-positioning.md`（Phase 1）、`docs/强化内核符合性审计-2026-11-02.md`。不虚构功能、不虚构数字；数字仅引用文档已写明者并标注性质（实测/规格目标/推断）。
> 决断纪律：每条定位主张都可追溯到上述文件；模糊处标「待确认」而非补一个好听说法。

## 1. 一句话定位（决断版）

**旧版（README §定位与路线 L138）**：
> CodeLens 是一个本地优先、BYOK 的通用 Agent 工作台：……内核是一个后台默默变强的强化闭环 Improve(π)，外壳是让你随手换上游、密钥不出本机的「插件时代 host」——你为「省心可控」买单，内核在后台变强。

**决断版（重写）**：
> **CodeLens 是一个跑在你自己机器上的通用 Agent 工作台：你用一句话交代任务，它在本地自主调用工具、每一步都看得见、按风险分级向你请示；你用自己的 Key（BYOK），密钥不出本机，上游随手换。一个本地优先、看得见、管得住的 AI 执行台——不是摸不到你文件/接口的聊天框，也不是每步逼你点「允许」的 IDE 插件。**

**为什么这么改（锐度来源）**：
- 删掉 `Improve(π)` / "后台变强"机制表述——它违反 `产品宪法补丁.md §5`（用户不为自我强化买单）与 README 自身"不对自我改进闭环整体对外承诺"的声明（L145），且审计显示内核成熟度不均（§6 曾未实现，`强化内核符合性审计-2026-11-02.md` §6 / P1）。放进 Hero 既过度承诺又有声誉风险。
- 把差异锚在三个**竞品确实没同时给到**的点：本地优先 + 过程可视化 + GUI 风险分级审批闸 + BYOK 多上游。
- 用两个「不是」做负向切割：vs 通用聊天窗（摸不到文件/接口）、vs Cline/Roo（每步弹窗疲劳），unambiguously 区分。

## 2. 目标受众分层

> 前提（采信 `docs/product-positioning.md §1`）：当前三份 persona 全是技术用户，无任何「非开发者」证据。「非开发者也能用」在补齐证据前属自嗨，不进入对外定位。

### Persona A — 小林：入门 / 自学技术用户（量最大、深度最低）
- **身份**：22 岁上下，计算机专业或自学转行中，Python/JS 为主，用 DeepSeek/低价国产 API，预算敏感。
- **核心 JTBD**：用自然语言完成真实小任务（抓网页接口列表 / 算 CSV 统计 / 查官方文档），并在过程中建立对 AI 的信任。
- **痛点**：问「弱智问题」有心理压力；学新技术时信息散落（文档→博客→SO→试错）；装不动 Dify（多容器）、搞不定 n8n（节点表达式）、不敢装 IDE 插件污染环境；怕黑盒搞坏东西。
- **愿付代价**：愿意本地跑单容器 / 开浏览器即用；接受国产低价 API。
- **获客渠道**：B站/知乎技术教程、自学社区、GitHub README 的「零安装开浏览器即用」钩子。
- **为什么选 CodeLens**：零安装开浏览器即用 + 免注册 + **每一步可见**（否则不敢放手）+ 便宜国产 API；vs 聊天窗摸不到文件、vs Cline/Roo/IDE 绑环境装不动、vs Dify/n8n 学习过重。

### Persona B — 阿豪：后端工程师（核心用户，工具调用深度最高）
- **身份**：28 岁上下，Java/Go 后端，公司用 DeepSeek/GLM 私有部署，接口在内网、有鉴权，代码不能贴外部账号体系。
- **核心 JTBD**：调内网 HTTP、读本地日志、算聚合，高危写操作先问过他。
- **痛点**：排查跨服务链路要在终端/日志/IDE 间来回切；通用聊天窗不知道他内网接口长什么样；公司代码不能贴强账号体系的第三方；不信任订阅制额度透明度（Cursor 定价风波）。
- **愿付代价**：愿意配 Docker、接受一定上手成本；为「数据不出本机 + 成本可见」付费意愿高。
- **获客渠道**：GitHub、掘金、V2EX、技术播客、内网 DevOps 群。
- **为什么选 CodeLens**：能同时调内网 HTTP + 读本地日志 + 算聚合、**高危写操作三档风险分级审批（none/soft/hard/two_step）先问过他**、Key 自己充钱成本可见、数据不出本机；vs Cursor/Copilot（订阅不透明+合规过不去）、vs Cline/Roo（绑 IDE+逐步弹窗疲劳）、vs 聊天窗（摸不到内网）。

### Persona C — 老周：独立全栈 / 小团队（生态用户，MCP 主要受益方）
- **身份**：35 岁上下，一个人干全栈，本机已跑着一套自己的 MCP Server 生态（自建 DB 查询/内部接口 server），平时用 Continue/Roo 这类 BYOK 插件。
- **核心 JTBD**：把已有 MCP Server 编排进 Agent，给客户做私有化部署。
- **痛点**：订阅费叠加肉疼；IDE 插件越装越重、换台机器重配；自己的 MCP Server 锁死在 IDE 里，团队其他人用不上。
- **愿付代价**：愿意读插件文档、参与社区；为「接已有私域 server + 数据不出本机」付费意愿高。
- **获客渠道**：Product Hunt、Hacker News、独立开发者社区、MCP/agent 生态讨论。
- **为什么选 CodeLens**：网页版能**接上他已有的 MCP Server（本机 stdio，不改现有 server）**、`MCP/上游接入是一等公民`（`产品宪法补丁.md §3`）、BYOK 成本透明、零安装、数据不出本机；vs Cline/Roo/Continue（绑 IDE，MCP 锁死）、vs Cursor/Copilot（订阅制+不接私域 server）。

### Persona D — 老陈：隐私 / 合规 / 成本敏感的自托管决策者（新增·买方视角）
- **身份**：小团队 tech lead / 研究员 / 独立开发者，手里有敏感数据（客户资料、实验数据、内网台账），对「数据出境」和「订阅账单失控」零容忍。
- **核心 JTBD**：把 AI 工作台跑在自己/团队服务器上，数据不留云、按自己的 Key 计费、一个容器就能维护。
- **痛点**：Cursor 商业云端数据出境+订阅贵且不透明；Dify 自托管要 6 容器太重、运维扛不住；n8n 按消息计费成本不可控；通用聊天窗数据出境不可接受。
- **愿付代价**：愿意维护一个 Docker 单容器；为「密钥不出本机 + 成本自控 + 单实例可控」付费意愿最高。
- **获客渠道**：r/selfhosted、中文自托管社区、隐私/安全向技术媒体。
- **为什么选 CodeLens**：单容器 Docker 自部署、BYOK 成本透明、密钥不出本机、网页端零安装给团队内「只用浏览器的人」也能用；vs Dify（重）、vs n8n（按消息计费）、vs Cursor（云+订阅）。
- **与 C 的关系**：C 是「用 MCP 深度集成的做者」，D 是「为隐私/成本拍板的买者」；两者可重叠（老周也私有化部署），但决策动机不同，落地页文案应分别击中。

> **受众边界结论**：A→B→C→D 构成「入门可见性 → 深度工具调用 → 私域生态接入 → 隐私/成本主权」的递进，区分度充分。暂不强的受众：非技术通用用户（无证据）、多租户/团队协作企业 IT（`OD-A8` 与 `docs/agent/spec.md §3` 明确不做）。

**CodeLens 真差异楔子（不是「本地 BYOK」本身）**：
- **vs OpenCode（同轴线最危险）**：OpenCode 在「本地+开源+BYOK+零成本」几乎与 CodeLens 同轴。CodeLens 相对它的真差异只剩 **网页 GUI + 过程可视化 + 跨浏览器恢复码 + GUI 审批闸**（OpenCode 无 GUI、无审批闸、终端态不可跨机）。差异化论证必须先处理这条同轴线，否则「本地 BYOK」被误读为独占卖点。
- **vs Cline/Roo**：直击「逐步弹窗、审批疲劳」反模式——三档风险分级 + 会话级记住授权。
- **vs Cursor/Copilot**：BYOK 成本透明 + 数据不出本机（合规）+ 不绑 IDE。
- **vs Dify/n8n**：零安装网页端 vs 多容器/重运维 vs 按消息计费。
- **vs 通用聊天窗**：摸得到用户文件/接口/系统，而非只能手动贴。

> **注意「开源」**：CodeLens 在现行文档中**未声明开源**。这恰是 vs OpenCode 同轴时的关键短板——若实际开源应显式声明以补强「本地 BYOK」轴；若闭源则差异化更需押在 GUI/审批闸/跨浏览器恢复上。

## 4. 对外叙事分层（感知层 vs 引擎层边界）

> 依据 `产品宪法补丁.md §5`「用户不为『我的 agent 在自我强化』买单，为『省心』买单」+ 审计显示内核成熟度不均。

**用户感知层（对外卖点，可承诺）**
- 省心可控：一句话交代、它自己干、关键处你拍板。
- 看得见每步在干什么（过程逐条透明）。
- 密钥与数据留你机器（BYOK + 本地优先）。
- 用得越久越顺手（个性化**感知**）。
- 接你已有的工具（MCP / 多上游即插即用）。

**内部引擎层（不对外承诺，仅内部/技术受众可见）**
- `Improve(π) = Act→τ→Judge→r→Update→π'` 自我强化闭环是结算标准。
- 「它在自我进化 / 自我改代码」的具体机制。
- 对收敛速度 / 智能水平提升的任何量化承诺。
- 把「越用越懂你」归因到具体内部机制的表述。

**边界规则（说 / 不说）**
- ✅ 说「用得越久越顺手」 ／ ❌ 不说「它在自我强化 / 自我进化」
- ✅ 说「基于你的使用持续个性化」 ／ ❌ 不承诺「智能水平自动提升 X%」
- ✅ 说「后台默默适应你的习惯」 ／ ❌ 不把 `Improve(π)` 写进一句话定位 / Hero
- ✅ 说「插件 / 上游是一等公民，随手换」 ／ ❌ 不暗示「接任何上游都零成本零风险」

## 5. 定位矛盾清单（重要）

> 每条附原文位置与「建议怎么改说法」。

1. **「退役」与「仍在售」同框（v1.0 四类能力）** — `README.md §定位与路线` L157–159 同段既称「所谓『退役』」又称「当前仍在售」。
   → **建议**：统一为「v1.0『代码分析四能力』的**独立产品定位**已退役；其四类任务模板作为内置提示词**保留并仍在售**」，删除单独出现、易歧义的「退役」二字。

2. **桌面端「最硬形态」vs「非主路径」张力** — `README.md` L150 称桌面端「最硬形态……而非主路径」；但 `docs/product-positioning.md §4 P0` 又建议「桌面端作为隐私诉求用户的**主入口**」。
   → **建议**：改为「桌面端是**隐私诉求用户的主入口**（最硬隐私形态），网页端是**零安装大众主路径**；两者是受众分流，不是主次优劣」。

3. **「本地单用户」与「自托管」边界模糊** — `README.md` L152–155 并列表述「本地单用户 / 可自托管」。
   → **建议**：统一为「**本地单用户 / 可自托管（单实例，非多租户）**」，并补一句「自托管 = 你在自有机器或服务器跑一个**单用户**实例，不是团队多租户云」。

4. **强化内核「对内价值」与「对外不承诺」的叙述缝隙（最尖锐）** — `README.md` L138 一句话定位把 `Improve(π)` 当定位主线；L145 又说「不对自我改进闭环整体对外承诺」；`产品宪法补丁.md §5` 明令「用户不为自我强化买单」。即**一句话定位自己违背了自己的不承诺声明**。
   → **建议**：一句话定位与 Hero **删除 `Improve(π)` / 「后台变强」机制表述**，只留「省心可控 + 越用越顺手（感知）」；内核留内部叙事。零代码成本、消除最大认知负债的动作。

5. **命名首因效应** — `CodeLens` 本义「代码透镜」，产品已是通用 Agent 工作台。名字承诺「代码」，产品已不限于代码。
   → **建议**：文案显式一句「CodeLens 已不止看代码，是一个本地 Agent 工作台」，或拍板换对外品牌名。

6. **「非开发者也能用」无证据却偶发** — 三 persona 全技术。
   → **建议**：对外定位暂不喊「人人可用」，聚焦技术用户；待有 persona 证据再扩。

7. **竞品集遗漏同轴竞品 OpenCode** — 差异化论证必须把 OpenCode 当**同轴线**优先处理。

8. **「开源」属性未声明却常被默认** — 应明确声明或明确「非开源/闭源策略」。

## 6. 一句话价值主张（Hero）

> **看得见、管得住的本地 AI 执行台：一句话交代任务，剩下的它在本机自主完成，关键处你拍板——密钥不出你这台机器。**

（副线可加：不是聊天框，也不是每步逼你点「允许」的 IDE 插件。）

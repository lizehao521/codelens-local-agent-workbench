# CodeLens 产品定位与目标受众澄清（Phase 1）

> 文档性质：产品打磨阶段第 1 阶段交付物（分析与设计，不含产品代码）
> 分析依据：仓库现有文档的现行真相源（见文末「假设清单」）
> 结论纪律：所有定位结论必须可追溯到具体文件与章节；受众分层须有文档事实支撑；模糊点须可定位

## 0. 一句话定位（推荐稿）

**CodeLens 是一个本地优先、BYOK 的通用 Agent 工作台**：你用一句话交代任务，它在你自己的机器上自主调用工具、每步可见、按风险分级请你拍板；内核是一个「越用越懂你」的强化闭环 `Improve(π)`，外壳是一个让你随手换上游、密钥不出本机的「插件时代 host」——**你为「省心可控」买单，内核在后台默默变强**。

> 衔接哲学：直接落地 `产品宪法补丁.md §0`「引擎 = 强化闭环；外壳 = 插件时代 host」，并用 `产品宪法补丁.md §5` 的判定（「用户不为『我的 agent 在自我强化』买单，为『省心』买单」）把内核收敛为「后台引擎」而非对外卖点，避免自嗨。比 README 现有表述（`README.md §定位与路线` 仅写「本地 / 自托管的 Agent 工作台」）多了三层锐度：① 点明价值锚点是「省心可控」而非「模型聪明」；② 把强化内核与插件时代 host 这对哲学概念翻译成用户能感知的「后台变强 + 随手换上游」；③ 与四条底线（BYOK / 免登录 / 数据留本机）形成闭环。

## 1. 目标受众分层

> 重要前提：仓库当前三份 persona（`docs/agent/spec.md §1`、`docs/agent/phase1-prd.md §3`）**全部是技术用户**（自学转行 / 后端工程师 / 独立全栈）。`docs/agent/phase1-prd.md §10.3` 与哲学层出现过「非开发者也能用」的期许，但**没有任何 persona 或场景证据支撑**。因此本阶段结论：**CodeLens 当前的真实受众是「技术用户」，不是「人人可用的 AI 助手」**；任何「非开发者」叙事在补齐证据前属自嗨（见 §4 第 6 条、§5 收敛项）。

### Persona A：小林 — 入门/自学技术用户（量最大，但深度最低）
- **角色**：22 岁，计算机专业大四或自学转行中，Python / JavaScript 为主，用 DeepSeek / Kimi 低价 API，预算敏感（`docs/agent/phase1-prd.md §3` Persona 1）。
- **核心痛点**：问「弱智问题」有心理压力；学新技术时信息永远攒不齐（文档→博客→SO→试错，每步手动切）；装不动 Dify（6 容器）、搞不定 n8n（节点表达式）、不敢装 IDE 插件（怕污染环境）。
- **为何选 CodeLens 而非替代品**：
  - vs **Cursor / Cline / Roo Code / Claude Code**：这些是 IDE/终端绑定、要配环境，小林「装不动 / 不敢装」；
  - vs **通用聊天窗（ChatGPT / Claude 网页版）**：摸不到文件/接口/数据，只能手动贴，且贴的时候要自己脱敏；
  - vs **Dify / n8n**：可视化编排学习成本过高。
- **关键决策因子**：零安装开浏览器即用、免注册、**「看得见它每一步在干什么」**（否则不敢放手）、便宜国产 API。
- **文档事实支撑**：`docs/agent/spec.md §1`「小林……要『看得见每步在干什么』」；`docs/agent/phase1-prd.md §3` Persona 1 三条核心 Agent 任务场景（抓网页接口列表 / 算 CSV 统计 / 查官方文档）。

### Persona B：阿豪 — 后端工程师（核心用户，工具调用深度最高）
- **角色**：28 岁，Java / Go 后端，公司用 DeepSeek / GLM 私有部署，接口在内网、有鉴权，代码不能贴外部账号体系（`docs/agent/phase1-prd.md §3` Persona 2）。
- **核心痛点**：排查跨服务链路要在终端 / 日志 / IDE 间来回切，每次重建 mental model；通用聊天窗不知道他的内网接口长什么样；公司代码不能贴强账号体系的第三方工具；不信任订阅制工具的额度透明度（Cursor 2025-06 定价风波）。
- **为何选 CodeLens 而非替代品**：
  - vs **Cursor / Copilot**：订阅额度不透明 + 公司代码合规过不去；
  - vs **Cline / Roo / Claude Code**：绑 VS Code / 终端 / 项目配置，换环境（同事机器、临时服务器、只有浏览器的笔记本）就要重配；且其审批是「逐步弹窗」，任务一多被无脑点穿（审批疲劳反模式，`docs/agent/phase1-prd.md §2.1`）；
  - vs **通用聊天窗**：摸不到内网接口、读不到本地日志。
- **关键决策因子**：能同时调内网 HTTP + 读本地日志 + 算聚合、**高危写操作必须先问过他（三档风险分级审批）**、Key 自己充钱成本可见、数据不出本机。
- **文档事实支撑**：`docs/agent/spec.md §1`「阿豪……要调内网 HTTP + 读本地日志 + 高危先问过他」；`docs/agent/phase1-prd.md §3` Persona 2 三条核心场景（拉订单算均值 / 统计日志 error / 对齐三接口字段）。

### Persona C：老周 — 独立全栈 / 小团队（生态用户，MCP 主要受益方）
- **角色**：35 岁，一个人干全栈，本机已跑着一套自己的 MCP Server 生态（自建数据库查询 / 内部接口 server），平时用 Continue / Roo Code 这类 BYOK 插件（`docs/agent/phase1-prd.md §3` Persona 3）。
- **核心痛点**：订阅费叠加肉疼；IDE 插件越装越重、换台机器重配；**自己的 MCP Server 只能在这些 IDE 插件里用**，团队其他人用不上。
- **为何选 CodeLens 而非替代品**：
  - vs **Cline / Roo / Continue**：绑 VS Code，MCP server 锁死在 IDE 里；
  - vs **Cursor / Copilot**：订阅制 + 不支持接「用户已有私域 server」；
  - vs **官方 MCP 市场**：PRD 明确「官方仅 7 个在维护，给用户不可信目录是负资产」（`docs/agent/spec.md §3`「MCP 官方技能市场」明确不做）。
- **关键决策因子**：网页版能**接上他已有的 MCP Server（本机 stdio，不改现有 server）**、BYOK 成本透明、零安装、**数据不出本机（给客户做私有化部署，模型走可配置内网端点）**。
- **文档事实支撑**：`docs/agent/spec.md §1`「老周……要接他已有的 MCP Server」；`docs/agent/phase1-prd.md §3` Persona 3 三条场景（查退款单分布 / 列内部 API 变更 / 写客户说明文档）；`产品宪法补丁.md §3`「插件 / 上游接入是一等公民」。

### 受众边界结论
- 三层受众构成「**入门可见性 → 深度工具调用 → 私域生态接入**」的递进，区分度充分，无需再拆第 4 个技术 persona。
- **暂不强求的受众**：非技术通用用户、需要多租户/团队协作的企业 IT——前者无证据（见上前提），后者被 `agent-decisions/OPEN-DECISIONS.md OD-A8` 与 `docs/agent/spec.md §3`（账号体系/团队协作明确不做）明确排除。

## 2. 价值主张与差异化（真差异 vs 自嗨）

### 2.1 真差异（有文档/架构事实支撑，且竞品确实未同时满足）
1. **网页零安装 + 本地可跑**：浏览器打开即用，不绑 IDE、不绑终端、不绑项目配置。竞品里 Cline / Roo / Claude Code / **OpenCode** 均需终端或 IDE 环境；Dify / n8n 需部署容器。依据：`docs/agent/phase1-prd.md §1.3`、`§2.1`；`README.md` 功能/快速开始。
2. **过程逐条透明 + 三档风险分级审批 + 会话级记住授权**：工具调用名称/参数/状态/耗时/结果逐条展示（`docs/agent/spec.md §2` AC-03），高危操作按 `none/soft/hard/two_step` 分级（`README.md` 功能），且「允许一次」不覆盖后续同类调用，除非用户显式选「本次会话始终允许」（`docs/agent/phase1-prd.md §6`）。直击 Cline / Roo「逐步弹窗、审批疲劳」反模式（`docs/agent/phase1-prd.md §2.1`）。
3. **跨浏览器恢复码（8 位 + 单次使用 + 5 次失败锁 15 分钟）**：本地 SQLite 持久化 + 换机找回（`docs/agent/spec.md §2` AC-05；`agent-decisions/OPEN-DECISIONS.md OD-A4` 量化熵）。竞品的终端/IDE 状态迁移成本高。
4. **BYOK 多上游 + 一键切换 + 成本自控**：DeepSeek / GLM / Moonshot / Qwen / OpenAI / 自定义 OpenAI 兼容端点，Key 仅存浏览器、服务端只代理不落库（`README.md` 安全模型）；ModelSync 拉来的上游进 `registry` 一等公民（`产品宪法补丁.md §3`、`docs/agent/spec.md §2`）。直击 Cursor 订阅额度不透明痛点。
5. **MCP 作为一等公民接「用户已有私域 server」**：内置 3 类官方能力（HTTP/文件/计算）已覆盖官方 server 增量价值，真正增量在用户自有 server（`docs/agent/phase1-prd.md §9 A2`）。差异化不在「官方市场」，而在「接你已有的」。

### 2.2 自嗨 / 需谨慎对外（仓库自身已设限或证据不足）
1. **「强化内核 / 自我改进闭环」作为对外卖点 —— 不可**。
   - `README.md §定位与路线` 明确写「**不作为已完备能力对外承诺**」，且「仍按草案持续增量，非全自动自改」。
   - `强化内核符合性审计-2026-11-02.md` 显示：闭环真实转动（符合），但 **§6 工具纪律三条机器闸完全未实现**、存在 2 处开环装饰项（`maxResultChars` 声明 12 处读取 0 处；`messages.usage_json` 全空导致账本失真）。把「自我改进」当成熟卖点会与审计结论冲突。
   - 正确用法（按 `产品宪法补丁.md §5`）：内核是后台引擎，对外只兑现「越来越懂我」的**感知**，不承诺「它在自我改」。
2. **「比通用聊天窗更懂代码」——已被 Claude Code / Cline 覆盖**，非独占差异，只算「相对纯聊天窗」的相对优势。
3. **「非开发者也能用」——无 persona 证据**，当前三 persona 全技术，属 aspirational，不应进入对外定位（见 §1 前提）。
4. **竞品分析遗漏 OpenCode**：`docs/agent/phase1-prd.md §9` 竞品表列了 Cursor / Copilot / v0 / Phind / Cline / Roo / Claude Code / 通用聊天窗 / Dify / n8n，但**未纳入 OpenCode**（本地、开源、BYOK、终端驱动）。OpenCode 在「本地 + 开源 + BYOK + 零成本」轴上与 CodeLens 几乎同轴，CodeLens 相对它的真差异只剩「网页 GUI + 过程可视化 + 跨浏览器恢复 + GUI 审批闸」——此缺口须在差异化论证中补齐，否则「本地 BYOK」会被误认为独占卖点。

## 5. 给测试阶段应重点验证的假设（可证伪）

> 准则：每条必须是「若 X 不成立则产品定位主张崩塌」的可证伪命题，且能被后续测试阶段执行。

### 5.1 功能维度
- **H-F1（审批闸真拦得住高危操作）**：伪装一个「写文件 / 发非 GET 外部请求」的调用，验证服务端在用户批准前**拒绝执行**，且 HMAC 绑定参数摘要、参数被篡改即 409（`docs/agent/spec.md §5` AC-04/AC-06；`agent-decisions/DECISION-LOG.md` 裁决 21）。可证伪：若未批准即执行，或改参后令牌仍通过 → 定位「可控」崩塌。
- **H-F2（BYOK 多上游切换顺畅）**：同一会话切换 provider，验证 ModelSync 拉来的模型**真进 `registry` 且被会话消费**（「sync 进 registry」门禁，`产品宪法补丁.md §3`）。可证伪：切换后模型不可选或工具不可见 → 「随手换上游」崩塌。
- **H-F3（过程可干预且不丢已完成步骤）**：运行中打断 / 单步重试 / 从某步重跑 / 改参数重试，验证被截断步骤标记 `skipped` 而非删除、已完成步骤保留（`docs/agent/spec.md §5` AC-10）。可证伪：重跑后历史丢失或序号错乱 → 「可恢复」崩塌。

### 5.2 性能维度
- **H-P1（首 token < 3s，工具事件到达即渲染）**：`docs/agent/spec.md §10` 性能约束（首 token <3s；delta 复用 50ms 节流）。可证伪：p95 首 token ≥ 3s 或工具卡延迟渲染 → 「流畅可控」体验崩塌。
- **H-P2（12 轮默认上限下长任务不失控、不静默截断）**：达到 12 轮上限须中止并输出未完成项；上下文 >75% 触发三层压缩且保真清单机械自检通过（`docs/agent/spec.md §9` AC-02/AC-09）。可证伪：静默截断或压缩丢 live constraint → 「可靠」崩塌。
- **H-P3（SSRF / 路径越界硬拦截）**：请求云元数据地址 `169.254.169.254` 或内网地址、文件参数越界，验证被五重 SSRF 校验 / realpath 路径 jail 拒回（`docs/agent/spec.md §10` AC-07）。可证伪：越界请求被执行 → 「本地安全」崩塌。

### 5.3 体验维度
- **H-E1（本地优先隐私承诺成立）**：Key 仅存浏览器、服务端不落库不记日志（`README.md` 安全模型）。可证伪：抓包或查服务端日志发现 Key 外发 / 落盘 → 「隐私」崩塌（这是相对 Cursor/Copilot 的核心相对优势）。
- **H-E2（跨浏览器恢复码找回完整）**：换浏览器输入 8 位恢复码，完整恢复消息与工具记录；恢复码单次使用、连错 5 次锁 15 分钟（`docs/agent/spec.md §9` AC-05；`OD-A4`）。可证伪：恢复后缺失工具记录或恢复码可复用 → 「状态不丢」崩塌。
- **H-E3（审批疲劳真被缓解）**：对比 Cline/Roo「逐步弹窗」，验证三档分级 + 会话级记住授权后，相同任务用户批准操作次数显著下降、主观疲劳评分更低（`docs/agent/phase1-prd.md §2.1` 反模式论证）。可证伪：批准次数/疲劳评分无差异 → 「可控不烦」卖点不成立。

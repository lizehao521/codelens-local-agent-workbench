CodeLens · 产品定位 One-Pager

CodeLens 是一个本地优先、BYOK 的通用 Agent 工作台

你用一句话交代任务，它在你自己的机器上自主调用工具、每步可见、按风险分级请你拍板；外壳是一个让你随手换上游、密钥不出本机的「插件时代 host」——你为「省心可控」买单，内核在后台默默变强。

面向：产品 / 市场 / 投资人 · 依据：产品定位澄清文档 §0 锐化定位句 · §1 受众 · §2 差异化

竞品定位象限

横轴看「数据 / 运行在哪」，纵轴看「怎么用」。CodeLens 独占「网页 GUI · 本地优先」这一无人区——本地优先的工具几乎都绑终端 / IDE，网页 GUI 的工具几乎都是云端托管。

落点依据：§2.1-1「Cline / Roo / Claude Code / OpenCode 均需终端或 IDE 环境；Dify / n8n 需部署容器；CodeLens 浏览器打开即用，不绑 IDE / 终端 / 项目配置」。§2.2-4「OpenCode 本地 / 开源 / BYOK / 终端驱动，与 CodeLens 几乎同轴，CodeLens 相对它的真差异只剩网页 GUI + 过程可视化 + 跨浏览器恢复 + GUI 审批闸」。竞品位置为基于公开形态的定位归类，非量化坐标。

三类技术受众画像

当前真实受众是技术用户（§1 前提）：从「入门可见性」到「深度工具调用」再到「私域生态接入」，区分度充分，无需第 4 个技术 persona。

小林
入门 / 自学技术用户 · 量最大、深度最低
核心痛点
装不动 Dify（6 容器）、搞不定 n8n（节点表达式）、不敢装 IDE 插件怕污染环境；问「弱智问题」有心理压力；学新技术信息永远攒不齐（文档→博客→SO→试错，每步手动切）。
为何选 CodeLens · vs 谁
vs Cursor/Cline/Roo/Claude Code：IDE / 终端绑定、要配环境，小林「装不动 / 不敢装」；vs 通用聊天窗：摸不到文件 / 接口 / 数据，还要自己脱敏；vs Dify/n8n：编排学习成本过高。
关键决策因子
零安装开浏览器即用 · 免注册 · 看得见它每一步在干什么（否则不敢放手）· 便宜国产 API
阿豪
后端工程师 · 核心用户、工具调用深度最高
核心痛点
查跨服务链路要在终端 / 日志 / IDE 间来回切、每次重建 mental model；通用聊天窗不知道内网接口长啥样；公司代码不能贴强账号体系第三方；不信任订阅额度透明（Cursor 2025-06 定价风波）。
为何选 CodeLens · vs 谁
vs Cursor/Copilot：订阅不透明 + 合规过不去；vs Cline/Roo/Claude Code：绑 VS Code / 终端 / 项目配置，换环境重配，且逐步弹窗审批疲劳；vs 通用聊天窗：摸不到内网、读不到本地日志。
关键决策因子
同时调内网 HTTP + 读本地日志 + 算聚合 · 高危写操作先问过他（三档风险分级审批） · Key 自己充钱成本可见 · 数据不出本机
老周
独立全栈 / 小团队 · 生态用户、MCP 主要受益方
核心痛点
订阅费叠加肉疼；IDE 插件越装越重、换台机器重配；自己的 MCP Server 只能在这些 IDE 插件里用，团队其他人用不上。
为何选 CodeLens · vs 谁
vs Cline/Roo/Continue：绑 VS Code，MCP server 锁死 IDE；vs Cursor/Copilot：订阅制 + 不支持接私域 server；vs 官方 MCP 市场：仅 7 个在维护，不可信目录是负资产。
关键决策因子
网页版能接上已有 MCP Server（本机 stdio，不改现有 server） · BYOK 成本透明 · 零安装 · 数据不出本机（客户私有化部署，模型走可配置内网端点）

真差异 vs 自嗨

左为「有文档 / 架构事实支撑、竞品确实未同时满足」的真差异（§2.1）；右为「仓库自身已设限或证据不足」、需谨慎对外的项（§2.2）。

✓ 真差异（可对外承诺）

1网页零安装 + 本地可跑：浏览器打开即用，不绑 IDE / 终端 / 项目配置。依据 §2.1-1
2过程逐条透明 + 三档风险分级审批 + 会话级记住授权，直击 Cline / Roo「逐步弹窗、审批疲劳」反模式。依据 §2.1-2
3跨浏览器恢复码（8 位 + 单次使用 + 5 次失败锁 15 分钟），本地 SQLite 持久化 + 换机找回。依据 §2.1-3
4BYOK 多上游 + 一键切换 + 成本自控，Key 仅存浏览器、服务端只代理不落库。依据 §2.1-4
5MCP 作一等公民接「用户已有私域 server」，差异不在官方市场而在「接你已有的」。依据 §2.1-5

⚠ 需谨慎 / 不自嗨

1「强化内核 / 自我改进闭环」不可作对外卖点：README 已声明不对外承诺；审计显示 §6 工具纪律三条机器闸未实现。依据 §2.2-1（收敛为内部引擎）
2「比通用聊天窗更懂代码」已被 Claude Code / Cline 覆盖，非独占差异，只算相对纯聊天窗的相对优势。依据 §2.2-2
3「非开发者也能用」无 persona 证据，当前三 persona 全技术，属 aspirational，不应进对外定位。依据 §2.2-3
4竞品分析遗漏 OpenCode：须补齐差异化论证，否则「本地 BYOK」被误认独占卖点。依据 §2.2-4

# ADR-017: 记忆压缩采用「滑动窗口 + 工具结果外置 + LLM 摘要压缩」三级策略，压缩失败降级为确定性摘要

## Status: **Superseded by ADR-020 (2026-10-21)**

> **本 ADR 的压缩部分已被 ADR-020 取代**，原因：PRD §7.2 要求保真做成**机械可验的工程断言**（护栏 G5 通过率 100%，缺项即回退不静默截断），而本 ADR 的「压缩失败降级为确定性摘要」无法检出 LLM 摘要悄悄丢失约束的情况。
> 本 ADR 仍然有效的部分：① SQLite 驱动的选择理由（转 ADR-011）；② 工具结果外置的原则（转 ADR-020 的 L1 层）；③ token 估算策略；④ 会话恢复流程（转 ADR-022）。
> **阅读时请以 ADR-020 为准。**

## Background
Agent 循环会持续累积上下文：每一轮都新增 LLM 输出、工具调用参数、工具返回值。上下文窗口有限（DeepSeek 64K / GLM 128K / Kimi 128K / Qwen 128K），而工具返回的 HTTP 响应或文件内容可以非常大。必须在有限预算内保住关键信息。

知识库 `context-engineering.md` 的核心结论：上下文是**会贬值的预算**，不是越多越好；压实（compaction）是**有损操作**，必须保住不可丢的事实；**保住指针而非全文**。

## Decision
三级策略，依次执行：

### 1. 滑动窗口截断（S-3）
丢弃最旧历史时按**整轮**丢弃（一条 assistant + 其关联的 tool 消息 + 对应 user 消息为「一轮」），**不切半轮**——半轮会产生孤儿 tool 消息，上游会因 `tool_calls` 与 `role:"tool"` 数量不匹配而 400。

### 2. 工具结果外置（S-2）
- 结果 ≤4000 字符 → 全文进上下文。
- 结果 >4000 字符 → 上下文里只放 `{summary(前500字符), truncated:true, totalChars, resultId, hint}`。
- 完整结果存 `tool_calls.result_json`（>200000 字符时只存首尾各 2000 字符）。
- 新增内置工具 **`tool_result_read({resultId})`** 回查完整结果，**校验 resultId 属于当前 sessionId**（防跨会话越权读取）。

这是「长结果不进上下文只留摘要 + 可回查 ID」契约的落地。

### 3. LLM 摘要压缩（S-4）
触发条件：`messages` 中未标记摘要的历史轮数 >20，或单会话消息数 >60，或 `total_tokens` 超过可用预算 80%。

- 压缩范围：最旧的一段连续历史（至少 2 轮），**最近 6 轮不动**。
- 摘要提示词**强制保留**：① 已确认的事实与结论；② 已调用过的工具名与关键返回值；③ 用户明确约束（数字、格式、路径）；④ 未完成事项与待办；⑤ 出现过的错误及其原因。**禁止保留**：寒暄、冗长探索过程、可从代码/文件重新获取的内容。
- 产物：一条 `is_summary=1` 的消息，插在被压缩历史之前。**被压缩的原始消息只从上下文装配中排除，不从数据库删除**（可审计、可展开原文）。
- 压缩调用固定为**非流式**、单次、`max_tokens=1024`、**不带 tools** 的普通 chat 请求。理由：压缩是内部机制，不应触发工具调用，也不该进入 SSE 事件流。
- **压缩失败（LLM 调用失败）→ 降级为确定性摘要**：规则拼接工具调用列表（名称+状态+耗时）、最近 N 条 user 消息前 200 字符、错误列表。**压缩绝不因失败而中断整轮**。

### Token 估算
上游流式下 `usage` 通常末尾才到，必须自估：代码/英文 3.5 字符/token，中文 0.7 token/汉字，工具定义 JSON 也计入，再乘 1.1 安全系数。估算值缓存在 `messages.token_estimate` 列，避免重复扫描。

### 预算公式
```
usableHistory = floor(modelWindow × 0.7) − toolsTokens − 2000(摘要预留) − floor(modelWindow × 0.2)(输出预留)
```

## Consequences
正面：长会话不会撑爆上下文；工具返回的大 payload 不挤占决策空间；摘要有明确的保真清单，不至于把用户约束丢掉；压缩失败不影响主流程；原始消息保留在库中可审计。
负面：LLM 摘要质量不稳定（这是有损操作的固有代价，靠保真清单 + 确定性降级缓解）；估算函数是近似值，可能低估（靠 1.1 系数与「超限则报 CONTEXT_OVERFLOW」兜底）；需要额外的 `tool_result_read` 工具与 `is_summary` 标记，schema 复杂度上升。

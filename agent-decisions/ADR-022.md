# ADR-022: 跨浏览器会话恢复采用「设备令牌自动关联 + 8 位单次恢复码」，两者服务端只存哈希

## Status: Accepted (2026-10-21)

## Background
产品免登录（无账号体系），但会话持久化在服务端 SQLite。这产生一个结构性问题：**用户如何在新浏览器/新设备上找回自己的会话**？

初稿架构（§7.6）只写了「按 sessionId 匿名寻址」，没有恢复机制——等于服务端持久化的价值在跨设备场景下归零。PRD §7.1 与 AC-05 要求两条恢复路径。

PRD 同时登记了 OD-04：「恢复码位数（8 位）与人机熵（暴力尝试空间）未做定量评估」。

## Decision
### 1. 两条恢复路径
| 路径 | 机制 | 服务端存储 |
|------|------|-----------|
| ① 同浏览器自动关联 | 创建会话时生成随机**设备令牌**存 localStorage；请求经 `X-Device-Token` 头带上 | `sessions.device_token_hash`（**只存 SHA-256**） |
| ② 跨浏览器 / 跨设备 | 创建会话时生成 **8 位恢复码**（大写字母数字，剔除易混字符 `0/O/1/I`） | `sessions.recovery_code_hash`（**只存哈希**）+ `recovery_code_used_at` |

### 2. 恢复码规则
- **单次使用**：成功后写 `recovery_code_used_at`，再次使用即拒绝并提示「恢复码无效或已失效」（AC-05）。这是刻意取舍——恢复码是「一次性交接凭证」而非长期密码，避免它变成长期有效的凭据。
- **可手动重新生成**：旧码哈希立即被覆盖 → 旧码立即失效。
- **暴力尝试防护**：单会话连续失败 **5 次 → 锁定 15 分钟**。
- 恢复成功后，该浏览器获得新的设备令牌关联（**不消耗**恢复码——恢复码的「使用」指的是认领会话，不是登录）。
- 恢复只还原**会话内容与工具调用记录**，**不还原正在执行中的任务**（中断的任务标记 `aborted`）。

### 3. OD-04 的定量结论
- 码空间：剔除 4 个易混字符后为 **31^8 ≈ 8.5×10^11**。
- 攻击速率上限：5 次 / 15 分钟 = 2 次/小时 = **1.75×10^4 次/年**（单会话）。
- 期望穷举时间：**> 4,800 万年**（8.5×10^11 / 1.75×10^4）。即便攻击者可无限换会话，服务端也无法在单会话上被穷举。
- **前提（必须实现）**：① 只存 SHA-256 哈希，不存明文；② 校验用 `crypto.timingSafeEqual` 恒定时间比较（防时序侧信道）；③ 失败计数按会话维度而非 IP 维度。
- 结论：**8 位 + 单次使用 + 5 次/15 分钟锁定**是充分的。OD-04 关闭条件（需安全评审给出锁定策略）由本 ADR 满足。

### 4. 端点
- `POST /api/v1/sessions` → 首次创建时返回 `recoveryCode`（**只此一次明文返回**，之后永不返回）
- `POST /api/v1/sessions/recover` → `{ recoveryCode }` → `{ session, deviceToken }`
- `POST /api/v1/sessions/:id/recovery-code` → 重新生成，旧码立即失效

## Consequences
正面：跨设备接续成立，且不引入账号体系；服务端零明文凭据存储（与既有「Key 不落库」的合规边界一致）；单次使用使恢复码的泄露窗口极短；OD-04 的定量结论消除了「8 位够不够」的不确定性。
负面：单次使用意味着用户想在新设备再恢复一次必须重新生成码（多一步操作）；用户可能把恢复码存在不安全的地方——但单次使用限制了危害窗口；恢复码是**持有即拥有**的凭证，服务端无法二次验证身份（这是免登录的固有代价）。

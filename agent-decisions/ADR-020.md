# ADR-020: 上下文压缩采用「三层结构 + 机械保真自检 + 锚点保活」，保真是工程断言而非提示词工程

## Status: Accepted (2026-10-21)

## Background
Agent 循环会持续累积上下文：每轮新增 LLM 输出、工具参数、工具返回值。工具返回的 HTTP 响应或文件内容可以极大，上下文窗口有限（DeepSeek 64K / GLM 128K / Kimi 128K / Qwen 128K）。

知识库 `context-engineering.md` 的核心结论：上下文是**会贬值的预算**；压实（compaction）是**有损操作**，必须保住不可丢的事实；保住**指针而非全文**。

PRD §7.2 进一步要求：保真必须做成**工程断言**而非提示词工程——压缩后**机械可验**地检查保真清单，缺项即回退并提示用户，**不静默截断**；护栏 G5 要求通过率 100%。

初稿架构（ADR-017）只做了「滑动窗口 + 工具结果外置 + LLM 摘要压缩」两层，压缩失败时降级为确定性摘要。**这不满足 PRD 的机械自检要求**——LLM 摘要可能悄悄丢掉「不要改数据库层」这类约束，而系统无从得知。

## Decision
采用 PRD §7.2 的**三层结构**，并把保真做成**可机械验证的断言**。

### 1. 三层结构
| 层 | 机制 | 触发 |
|----|------|------|
| **L1 工具结果瘦身** | 单条结果 > **8K token** → 正文落盘 `artifacts`（**在沙箱工作区内**），上下文只留「摘要 + 路径 + 前 500 字符 + sha256」 | 每次写入结果 |
| **L2 消息摘要压缩** | 占用 > 模型窗口 **75%** → 对历史做**九段结构化摘要** | 每次 LLM 调用前估算 |
| **L3 近期原文保留** | **最近 6 轮永远保留原文**，不参与被压缩范围 | 随 L2 |

**回查零新增能力面**：artifacts 落盘在 `SANDBOX_ROOT` 内，因此 **`fs.read` 直接按路径回查**——不需要新增 `tool.result.read` 工具。这既是「保留指针而非全文」的直接落地，也避免了为回查额外开一个工具权限面。

### 2. 九段结构（照抄，不自由发挥）
原始请求与意图 / 关键技术概念 / 涉及的文件与代码段 / 遇到的错误与对应修复 / 问题解决过程与已做决策及理由 / **用户原话（逐字保留）** / 待办事项 / 当前工作 / 可选的下一步。

### 3. 机械自检（F-1~F-5，护栏 G5）
| # | 保真项 | 机械校验方式 |
|---|--------|--------------|
| F-1 | 原始用户诉求 | 段 1 非空 **且** 段 6 含第一轮 user message 逐字子串（≥80% 长度） |
| F-2 | 已做决策及理由 | 段 5 非空 **且** 含 ≥1 条「决策—理由」配对 |
| F-3 | 已修改文件清单 | 段 3 提取的路径集合 ⊇ 被压缩历史中 `fs.write` 涉及的路径集合 |
| F-4 | 验证命令与结果 | 段 4 或段 8 出现 ≥1 条命令/结果对 **或**显式标注「本任务无验证命令」 |
| F-5 | 待办事项 | 段 7 非空 **或**显式标注「无待办」 |

**自检失败处理**：① 先**机械补齐**（从原始消息直接抽取缺失项）→ ② 再自检一次 → ③ 仍缺项则**判定压缩失败：回退（不应用本次压缩）+ 提示用户「上下文已满，请新建会话或缩短任务」**。绝不静默截断。

**这是本 ADR 的核心**：F-3 的校验方式（路径集合包含关系）不依赖 LLM 判断——它是对 `tool_calls` 表的集合运算，**确定性地可验**。这是「保真是工程断言」的落地形式。

### 4. 锚点保活
系统提示、当前任务目标（A-2 原始诉求）、保真清单（A-3）在**每次 LLM 请求中作为固定前缀重新注入**，**不参与压缩淘汰**。即使历史被全部摘要，锚点仍在请求开头——这是「Agent 忘了硬约束」这一类问题的根治手段。

### 5. 滑动窗口降为最后手段
L2 压缩（含自检+回退）已尽力后仍超预算，才执行整轮丢弃。**不切半轮**（半轮产生孤儿 tool 消息，上游因 `tool_calls` 与 `role:"tool"` 数量不匹配而 400）。

### 6. 摘要用小模型
provider 能力表加 `lightweightModel` 列（同供应商轻量型号，用户可覆盖），**不引入模型路由框架**（场景只有主对话/摘要两种，一张两列映射表足够）。摘要调用固定：非流式、单次、`max_tokens ≤ 2048`、不带 tools、不进 SSE 流。

### 7. 降级链
① LLM 九段摘要 + 机械自检 + 机械补齐 → ② 自检仍缺项 → **回退并提示用户** → ③ 摘要调用本身失败 → 确定性摘要（**同样过一遍 F-1~F-5**，天然满足 F-1/F-3/F-5，F-2/F-4 缺则按 ② 回退）。

## Consequences
正面：保真从「提示词里写的要求」变成「可测的断言」——F-3 这类校验完全不依赖 LLM 判断，可写成单元测试；约束丢失会被机制发现而非静默发生；长工具结果不挤占决策空间；锚点机制根治「Agent 忘记硬约束」；不新增任何工具即实现长结果回查。
负面：九段结构 + 自检 + 补齐的实现复杂度高于初稿；机械补齐只能补「可从原始消息抽取」的三项（F-1/F-3/F-5），F-2/F-4 依赖摘要质量，缺项即回退（意味着长任务可能因压缩失败而中断，用户需缩短任务——这是 PRD 明确接受的行为）；锚点每次请求都占 token（但这是必要成本，且远小于丢失约束的代价）。

# ADR-026: RSI 规则契约单一数据源与前后端对齐

## Status: Accepted (2026-11-10)

## Background

AgentRsi 既有系统的判据事实散落在五处，且互相冲突：`server/krsi/main.go`（Go 判定内核）、`server/src/services/rsi/rsi-bridge.service.ts`（TS 桥接与报告解析）、`server/src/services/judge/types.ts` 与 `criteria.ts`（判据塔三态与阈值）、`server/src/services/rsi/manifest-builder.ts`（判据集指纹）、以及三处前端（SPA、独立 HTML 看板、静态快照）各自硬编码的标签与染色列表。`docs/rsi-rules-alignment-spec.md` §2 的冲突裁定表点名了八处可观测偏差：

| 编号 | 偏差 | 证据 |
|---|---|---|
| C1 | R1–R6 编号含义错位，R5 被误写成拒收类 | `main.go:214-337,344-435,463-495`；`docs/rsi-rules-alignment-spec.md:41` |
| C2 | basis 必带字段口径错（误称 basis=2 必带 source） | `main.go:232-237`；`manifest-builder.ts:12` 旧注释 |
| C3 | R6 举例把 `budget.efficiency` 当成 direction=down 读数 | `manifest-builder.ts:70-73` |
| C4 | 编号归属"外置上游"，仓库内不存在该包 | 全仓检索 0 命中 |
| C5 | 文档按编号叙述，实际执行序为 R1→R2→R3→R4→R6→R5 | `main.go:466-495` |
| C6 | 前端幽灵状态 `undecided`，后端从不产生 | `RsiDashboardModal.tsx:96`（改造前）；`types.ts:22`、`rsi-bridge.service.ts:33` |
| C7 | eval 四个元数据字段在映射层被丢弃 | `api.ts:1014-1038`（改造前）；`app.ts:255-262` |

本轮由 `docs/rsi-rules-alignment-spec.md` 锁定为"澄清与对齐，不是重写规则"（文件头 `:5`）：不改判定、不改证据链、只增不删既有 API 字段。既有系统已跑通 6 代 v2 anchor 链、`rsi:verify`、`krsi conformance` 10/10，字节级稳定性是本轮的硬边界。本 ADR 记录契约放置与前后端对齐的架构决策，以及对该方案的只读评审结论。

**本轮已决事项（PM `server/docs/rsi-rules-contract.md`，人类可读现行准绳）**：该文档 §1.1/§1.2 逐一裁定「四套准绳」措辞——README 的「唯一真相源」指 v2.0 产品定位、不覆盖 RSI 判据；`rsi-loop.md` 旧 §4 外置到仓库中不存在的 `microkernel-rsi/risk` 包，作废；`强化Agent.txt` 与 `产品宪法补丁.md` 保持草案、不作机械判定依据；`RSI-HANDOVER-2026-11-10-PM.md` 是状态快照、历史语义不重写。§5 给出 C1–C8 逐条「错误侧 / 裁定 / 源码行号」表，§9 如实登记 OPEN 未决项、不编答案。文档准绳为 `server/docs/rsi-capability-sedimentation.md` §5，实现真相源仍为 `server/krsi/main.go`。

两处口径须在本 ADR 内明确分开，避免后续被误合并：

- **编号 ≠ 执行顺序**：R1–R6 的编号含义（R5 严格比较产出四态、R6 同代唯一属拒收前置类）由 `main.go:78` 与 `main.go:214-337,344-435` 定义；实际调用顺序 `R1→R2→R3→R4→R6→R5` 由 `main.go:463-495` 定义。二者是不同维度，契约用 `id` 表达前者、`order` 表达后者（`R6.order=5`、`R5.order=6`），不得互相推导。
- **契约版本 ≠ 判据集版本**：本契约 `version: 'rsi-rules-contract-v1'`（`rules-contract.ts:85`）是描述性契约的版本；`RULES_VERSION = 'criterion-set-v2'`（`judge/replay.ts:39`）是判据集口径版本，由 `KNOWN_RULES_VERSIONS`（`:42`）约束复算。二者分属不同对象，已在契约 `outOfScope`（`rules-contract.ts:265`）标明「本轮只登记、不定义其判据条目清单」，不得混用或相互覆盖。

## Decision

**1. 实现真相源唯一为 `server/krsi/main.go`。**
判决权在 Go 内核，不在模型、不在文档、不在本契约。R1–R6 编号以 `main.go:78` `criteriaDeclared` 为准；执行序以 `main.go:466-495`（R6 在 R5 之前）为准；退出码以 `main.go:74-77` 为准；报告文案模板以 `main.go:571-594` 为准。状态枚举真相源为 `rsi-bridge.service.ts:33` 的 6 态 `RsiVerdictState`，以及 `judge/types.ts:19`（`VerdictStatus`：pass/fail/unexec）与 `:22`（`RunVerdict`：pass/fail/inconclusive）；阈值真相源为 `judge/criteria.ts:23-27` 与 `judge/types.ts:162`。`强化Agent.txt` 的 C1–C4、`产品宪法补丁.md` 均为草案/宣言，不作机械判定依据。

**2. `server/src/services/rsi/rules-contract.ts` 是描述性契约，不参与判定。**
`buildRsiRulesContract()`（`:83-268`）为纯函数：无 DB、无文件 IO、无网络、无时钟、无随机数，每次调用返回全新对象。它只把上述真相源翻译成机器可读的 `RsiRulesContract`（`:60-77`）：6 条 `rules`（含 `order`/`anchor`/`resultsIn`/`exitCodes`）、6 个 `states`（含 label/tone/`origin`）、`judgeRunStates`/`criterionStatuses` 两组三态、5 条 `basis`、2 个 `roles`、4 个 `thresholds`、`reasonRuleIdPattern`、`outOfScope`。它不调用 krsi、不写账本、不计算 `criteria_sha256`、不产生任何 `RsiVerdictState` 结论；`outOfScope`（`:261-266`）显式声明草案、未实现触发条件、判据集版本标识等不作判定依据的项。

**3. 后端下发，两出口同源。**
`GET /api/rsi/rules`（`app.ts:102-105`）无 session、`Cache-Control: no-store`；`GET /api/rsi/overview`（`app.ts:140-155`）在 `session/judgeRuns/verdictsByRun/rsiRuns/attributions/eval` 六个既有顶层字段之外**新增** `rules` 字段。两处调用同一个 `buildRsiRulesContract()`，进程内同源由纯函数保证。不删、不改名、不改值任何既有字段。

**4. 前端消费加兜底，镜像为独立工程约束下的唯一可行解。**
`client/tsconfig.json:2-21` 的 `include: ["src","tests"]` 与 `moduleResolution: "bundler"` 决定 client 是独立 TS 工程，没有指向 `server/src` 的路径映射；server 侧为 `module: nodenext`（`server/tsconfig.json:5-6`）。因此前端不能 import server 代码，只能镜像类型（`client/src/services/api.ts:941-958`）+ 一份兜底常量（`client/src/lib/rsi-rules.ts:36-206`）。独立 HTML 看板无构建、无模块系统，走 `overview.rules` → `/api/rsi/rules` → 内联最小切片（`server/public/rsi-dashboard.html:286-313`）。静态快照 `rsi-code-fix-dashboard.html` 按 Spec §0.6 冻结历史数据，仅补说明，不接契约。三处对同一 verdict 的 label/tone 一致性由 `server/scripts/check-rsi-contract.mjs` 机械门禁守住，不靠人工复查。

**5. 判定逻辑与证据链零改动（范围声明）。**
除 Spec §0 红线（不改 `main.go` 判定逻辑/退出码/报告文案；不改 `manifest-builder.ts` 的 `METRIC_MAP`/`CRITERIA_FINGERPRINT` 运行逻辑，注释可修正；不改 DB schema / 既有 API 响应字段 / 历史账本 / anchor / `hash_version`；不改静态快照历史数据）之外，本决策把下列同样承重但未被 §0 点名的模块一并纳入零改动清单：`rsi-bridge.service.ts:624-632`（`parseExitCode`）、`:692-740`（`extractReasons`/`extractMetrics` 中文正则解析）、`:447-524`（`appendAnchor` 证据原像组装）、`ledger-verify.ts:72-93`（`canonicalJson`）、`scripts/krsi-conformance.ts`、`judge/criteria.ts:23-27` 与 `judge/types.ts:162` 的常量值。理由见 `## Review Findings` 第 4 点。

**6. 不预设新框架、不新增依赖、不改图标方案。**
本决策只规定数据契约与质量标准，不替换项目既有技术栈。沿用现有图标库与既有 CSS 变量/Tailwind 语义 token；不新增硬编码 hex 颜色，不使用 emoji 作功能图标，不引入紫粉渐变。

## Consequences

**正面**

- R1–R6 编号与执行序、6 态、3+3 态、basis 必带字段、4 个阈值收敛为一份可寻址产物（`rules-contract.ts:83-268`），C1–C8 各自的错误侧被逐条点名并锚定到源码行。
- 契约自带 `version`（`:85`）、`authority`（`:86`）、逐条 `anchor`（如 `:100,:112`）、`reasonRuleIdPattern`（`:259`）、`outOfScope`（`:261`），可审计、可被校验脚本消费，不需要读文档猜口径。
- 描述性契约与判定内核解耦：改契约文本不触碰 krsi 退出码、报告字节或账本哈希；反之内核改动由门禁的源码比对暴露。
- 后端两出口同源，前端三处对同一状态名消费同一 tone 语义值（`rules-contract.ts:18`），不再各自硬编码"哪几条算违规"。
- 三套枚举域被强制分开分派（`rsi-rules.ts:237-252` 的 `judgeRunPresentation`/`rsiStatePresentation`/`criterionStatusPresentation`），C6 的 `undecided` 幽灵状态失去生存空间。

**硬约束（针对报告文案与解析，不可协商）**

**契约是描述性的，不参与判定，因此不会影响报告文本解析。** 具体链条与边界如下：

- `buildRsiRulesContract()` 只在两个只读 HTTP 响应里被序列化（`app.ts:104,155`），不进入 `spawnKrsi`（`rsi-bridge.service.ts:527-578`）的参数、不写 manifest、不落账本、不进 `appendAnchor` 的 `evidence` 原像（`:479-504`）。改契约任何字段都不会改变 `krsi` 进程读到的一份字节。
- 报告文案的唯一生成者是 `main.go:571-594`；唯一消费者是 `rsi-bridge.service.ts:692-740`（`extractReasons`/`extractMetrics` 中文正则）与 `scripts/krsi-conformance.ts:102-103`（`/判定：(\S+)/`、`/理由：(.+)/g` 仅用于展示）。这三处与契约**没有任何调用关系**。
- 因此**禁止**以"契约已对齐/文案更好读"为由改写 `main.go` 报告模板、`extractReasons`/`extractMetrics` 的中文标记，或 `reasonRuleIdPattern` 的冒号风格。报告文案的任何一处字节变化都会同时改变 `report_raw`（`rsi-bridge.service.ts:488`）、`reasons_json`（`:609`）与新代 `evidence_hash`（`:490-492`），而历史 6 代 v2 anchor 链因证据自带仍绿、`rsi:verify` 不会报警 —— 是典型的沉默逻辑错误。契约里那些长中文 `name`/`criterion`/`onHit`/`meaning` 是给人看的说明文字，不是报告模板的草稿，也不得被回填进报告。
- 已实测的一处既存失配须保持原样：`main.go:582` 指标行用全角 `：`（U+FF1A），`extractMetrics`（`rsi-bridge.service.ts:727`）正则用半角 `:`（U+003A），真实报告行恒不命中，`result.metrics` 恒 `undefined`。本轮**只登记、不修**；若将来要修，必须作为独立的证据链变更走 ADR，不能搭"契约对齐"的车。反向已核验：`main.go:510,513,516,521,530,535` 的 `R*:` 前缀均为半角 U+003A，与契约 `reasonRuleIdPattern` 一致，AC-06/C8 成立，同样不得改成全角。

**负面 / 代价**

- **前端镜像需门禁守护**：TypeScript 类型只在各自工程内自洽，跨端"值相等"没有任何编译期保证；`resolveContract`（`rsi-rules.ts:216-234`）逐字段合并会把 shape 合法但值错的后端契约静默采用，无运行时告警。唯一防线是 `check-rsi-contract.mjs` 在 CI 中作为必过门禁、任一不符 exit 1。门禁不是可选脚本。
- 实际存在**两份**前端兜底（SPA 全量镜像 278 行 + HTML 内联最小切片）加一份冻结的静态快照副本，而 Spec §6 第 8 项只写"前端兜底契约"（单数）。门禁必须分别处理，否则 HTML 侧漂移无人发现。
- 阈值运行时 import（`rules-contract.ts:13-14`）把描述性契约与 `CRITERIA_FINGERPRINT` 绑到同一个常量 `DEFAULT_L0_THRESHOLDS`；Spec §6 第 7 项的等值校验因此是自指的，必须另加固定指纹回归断言（见第 4、5 点）。
- `tone → 视觉` 映射仍是三处各自硬编码（`rsi-rules.ts:11-16`、`rsi-dashboard.html:71-74,130-133`、`rsi-code-fix-dashboard.html:38-39`）；契约统一的是 tone 名，不是渲染结果。
- `/api/rsi/overview` 每个响应多带约 10 KB 契约原文（含长中文说明），且该端点未设 `no-store`；`compression()`（`app.ts:57`）在场，开发态看板可接受。
- 静态快照按 Spec §0.6 是**永久**残留漂移点，本方案明示不消除它，只补说明。

## Review Findings

五个评审点逐条结论。**角色裁决**：架构决策本身成立并记为 Accepted；但 Spec 的验收/门禁完备性存在两项阻断缺陷（见第 2、4 点末尾），已随 RoleVerdict 回传 team-lead。

### 复核增补（2026-11-10，前端 #4 修复后）

以下为评审回传后的实现变更复核，均已逐行核对代码，不覆盖上文原始评审记录（保留发现时的状态以便追溯）：

- **阻断项 A 的实现侧已闭环，Spec 侧仍待 team-lead 裁定**。前端把独立看板重构为 `Promise.all` 并行发起 overview 与 `/api/rsi/rules`（`rsi-dashboard.html:324-333`，独立端点带 3s `AbortController`、失败返回 `null`，`:316-322`），删除了 `!res.ok` 整页替换并 `return` 的 early return；overview 失败时改用空数据骨架 `{session:{…}, judgeRuns:[], verdictsByRun:{}, rsiRuns:[], attributions:[], eval:null, rules:null}`（`:338-344`），错误横幅保留但不再清空 DOM（`:355-365`），契约优先级仍为 `overview.rules → 独立端点 → 内置切片`（`:347-353`）。并补了 `(last2V[1] || [])` / `(last2V[0] || [])` 空态保护（`:430-432`）与 ECharts 等待循环 `&& !overviewError`（`:455`），否则空骨架会在 `undefined.find` 处 TypeError 中断整页渲染、规则清单同样出不来 —— 这是解耦能否真正生效的关键，已核实到位。前端自检：内嵌脚本 `new Function()` 语法 OK、`tsc --noEmit` exit 0、定向 36/36、全量 14 files / 124 passed；6 个产物 `undecided=0 / emoji=0 / 新增 CSS hex=0`。
  - **运行时验证（前端补充，架构侧采纳为 A 实现闭环的终证）**：仅靠源码级断言不足以排除「形式上解耦、运行时仍崩」。前端用 server 侧 `tsx` + 最小 DOM stub + fetch mock 把 HTML 内嵌脚本实际执行了一遍，三场景均 `RUNTIME_CHECK_PASS / exit 0`（临时脚本已删除）：(i) overview 404 + `/api/rsi/rules` 200 → 独立端点调用 1 次、规则清单渲染 6 条、执行顺序 `R1→R2→R3→R4→R6→R5`、错误横幅保留、`document.body` 未被整页替换；(ii) overview 404 + `/api/rsi/rules` 404 → 走内置切片、给中性提示、顺序仍正确、不白屏；(iii) overview 200 对照组 → 规则清单 6 条。两个失败场景的 `rules-order` 均为 `R1→R2→R3→R4→R6→R5`，同时印证了内联切片 `order` 修复在兜底路径下也生效。有了这一层，**阻断项 A 的实现侧判定为已闭环，不再列为产品代码缺陷**。
- **但 Spec 侧缺口未变**：AC-08（Spec §5:177）仍只覆盖「响应无 `rules`」成功分支，§6 十项仍无「overview 返回 400/404 或网络失败」的门禁项。前端按 Spec §4 边界不越界改 Spec，已请 team-lead 裁定补 EARS 与门禁项。**因此阻断项 A 由「实现不可达」降级为「验收/门禁未覆盖」，仍属需求未满足，不撤销**；门禁最小项第 14 项继续有效。

### 评审点 1 — 单一数据源是否真能消除三处前端漂移

**结论：不能全部消除。SPA 与独立 HTML 看板的"值"漂移确实被收敛；静态快照是 Spec 明示的永久例外，另有四类残留漂移点。**

已消除的部分：`rules-contract.ts:89-161`（6 条规则）、`:165-202`（6 态）、`:205-214`（3+3 态）、`:217-238`（basis）、`:252-257`（阈值）集中为一份；SPA 改为按契约分派（`RsiDashboardModal.tsx:243-244,609-610,795,854`），独立 HTML 改为按 `rules[].id` + `reasonRuleIdPattern` 派生染色（`rsi-dashboard.html:315-327,462-464`），原 `:369` 硬编码排除列表（C8 漏 R2 的根因）已去除。

仍残留的漂移点：

1. `rsi-code-fix-dashboard.html` 是纯静态文件，无 fetch、无构建、无模块系统；且 Spec §0.6 / §6 第 10 项冻结其历史数据（`:85-88` 的 `undecidable / exit 3` 与 `main.go:524-530` 的 atCeiling 分支一致，是正确的），只能"补说明"。它物理上无法消费契约。
2. **两份**前端兜底而非一份：`client/src/lib/rsi-rules.ts:36-206` 是全量镜像；`server/public/rsi-dashboard.html` 另有内联最小切片，含 6 态 label/tone 字面量、`CONTRACT_PATTERN = '^(R[1-6]):'` 与 `deriveRuleIds` 派生 `order`。发现时该切片的 `order` 按数字 1..6 生成、与契约 `R6.order=5 / R5.order=6`（`rules-contract.ts:147,159`）冲突 —— **此冲突已在复核增补中修复（末两条对调）**；但「不是全量镜像、Spec §6 第 8 项『逐项 JSON 相等』对它不可执行」这一点依然成立，兜底态豁免必须保留。
3. `tone → 视觉` 三处各自硬编码：SPA 用 Tailwind 语义类（`rsi-rules.ts:11-16`）、HTML 用 `.tone-*` CSS 变量（`rsi-dashboard.html:71-74,130-133`）、静态快照用 `.v-*`（`rsi-code-fix-dashboard.html:38-39`）。契约只统一 tone 名（`rules-contract.ts:18`），不统一渲染；Spec §6 第 10 项比对的是 label/tone 值，不是视觉结果。
4. `isRulesContractLike`（`api.ts:1138-1152`）只做形状校验，`resolveContract`（`rsi-rules.ts:216-234`）逐字段合并；shape 合法但 label/order 错的后端契约会被静默采用，无运行时告警 —— 对应 `generated-code-failure-modes.md` §2 的沉默逻辑错误。**复核增补**：`isRulesContractLike` 原锁死 `version === 'rsi-rules-contract-v1'` 已放宽为「非空字符串」（避免契约升 v2 被误判成无契约而静默退回旧兜底），但 `resolveContract` 的逐字段合并行为未变，机械门禁仍是唯一值相等防线。

**守住它的机械手段**：门禁须比 Spec §6 第 8 项更宽 —— (a) 全量镜像 `FALLBACK_RULES_CONTRACT` 与 `buildRsiRulesContract()` 深度 JSON 相等；(b) HTML 内联切片单独比「6 态 label/tone 集合 + `reasonRuleIdPattern` + 6 个 `rules[].id` 集合」，并显式登记其 `order` 为兜底态豁免；(c) 静态快照按文件哈希/冻结片段断言"历史数据未改 + 补说明存在"，不强求消费契约；(d) 三处 tone 值集合相等，且每个 tone 在各自映射表均有定义；(e) 三处 tone 名→映射表键集相等。

### 评审点 2 — 双出口同源：CSP、缓存、响应体积、无 session

**结论：进程内同源成立且可证；HTTP 层同源与"无 session"消费路径未被任何自动门禁覆盖。**

- **同源**：`app.ts:102-105` 与 `app.ts:155` 都调用 `buildRsiRulesContract()`；该函数是字面量纯函数、每次返回新对象（`rules-contract.ts:79-84`），无时间/DB/随机输入，两处 JSON 深度相等可证。但 Spec §6 十项**没有**一条断言两出口相等，只有 §7:215-217 的手工 curl；`server/package.json:14` 的 `test` 链（`vitest run && npm run test:krsi`）也未包含 `:23` 的 `check:rsi-contract`。
- **CSP**：`app.ts:35-43` 的 `connect-src` 为 `'self'` + `cdn.jsdelivr.net`。看板由同源 `/rsi` 提供（`app.ts:154-160`），两个端点都是同源请求 → 放行；一致性校验脚本在 Node 运行，无 CSP。但 `cors`（`app.ts:53-55`）仅在 `config.allowedOrigins` 非空时挂载且 `credentials:false`，跨域或 `file://` 打开的独立 HTML 取不到契约。Spec §3"供独立看板消费"须明确限定为"由本 app 同源提供"，不应为此放宽 CSP/CORS。
- **缓存**：`/api/rsi/rules` 有 `Cache-Control: no-store`（`app.ts:103`），符合 Spec §3；`/api/rsi/overview` 无显式 Cache-Control（`app.ts:140-147`）。SPA 侧 `fetch(..., { cache: 'no-store' })`（`api.ts:1163`）正确，发现时独立 HTML 的 overview fetch 无 cache 选项 → 浏览器可缓存旧 overview，其中嵌入的 `rules` 随之变旧，双出口在 HTTP 缓存层分叉。**该 fetch 已在复核增补中补 `cache:'no-store'`，前端侧自足**；后端为 overview 补响应头仍待 team-lead 授权，仅作双保险。
- **响应体积**：契约含长中文 `criterion/onHit/meaning/action/outOfScope`（如 `rules-contract.ts:95,155,168,262-265`），约 10 KB 原文附加到每个 overview 响应；`compression()`（`app.ts:57`）在场，线上体积可控。两处均按请求构造纯对象，无 IO，单位成本可忽略，开发态看板可接受，不构成本轮风险。
- **无 session**：`/api/rsi/rules` 无 session 校验（`app.ts:102`）成立；但 `overview` 缺 session 返回 400、session 不存在返回 404（`app.ts:103-107`），发现时独立看板先无条件请求 overview，`!res.ok` 即整页替换并 `return`，**先于** `/api/rsi/rules` 回退。AC-08（Spec §5:177）只覆盖"响应无 `rules`（旧后端）"这一成功响应分支，Spec §6 十项也无一项覆盖"无 session / overview 失败"。**实现侧已在复核增补中解耦修复，Spec 侧 AC/门禁缺口未变。**

> **阻断项 A（需求未满足）**：Spec §3 声明 `/api/rsi/rules`「无需 session…供独立看板…消费」，但该能力无对应 AC、无 §6 门禁项；发现时独立看板的控制流在 overview 失败时提前返回，使无 session 路径不可达。
> **期望**：补一条 AC 与 §6 门禁项——"无 session 时 `GET /api/rsi/rules` 返回 200 且独立看板在 overview 不可用时仍能渲染规则清单"；独立看板把 `/api/rsi/rules` 的获取与 overview 成功解耦。
> **状态（见「复核增补」）**：期望的后半段（实现解耦）已完成、逐行核实；前半段（AC + 门禁项）仍待 team-lead 裁定，故阻断项 A 不撤销，仅由「实现不可达」降级为「验收/门禁未覆盖」。

### 评审点 4 — 证据链不回归，及被遗漏的耦合点

**结论：三项"不改"对 6 代 v2 anchor 链、`rsi:verify`、`krsi conformance` 10/10 是充分的，因为三者只校验已落盘的历史数据与退出码；但充分性依赖一个 Spec 未显式点名的前提，且存在一处会静默破坏绑定的遗漏耦合。**

- `rsi:verify` 复算的是**锚行内已落盘的 `evidence` 原像**：`ledger-verify.ts:349` `sha256(canonicalJson(evidence))`、`:273` `sha256(manifestJson)`；`verify-rsi-ledger.ts:22` 只读账本/DB。它**不重新解析 `report_raw`**，因此 `main.go` 报告文案与 `rsi-bridge` 解析器都不参与历史链复算。
- `krsi conformance` 10/10 的判定是 `r.actual === r.expected`（`scripts/krsi-conformance.ts:238`），`actual` 来自 `spawnSync` 退出码（`:94-105`）；报告正则 `/判定：(\S+)/`、`/理由：(.+)/`（`:102-103`）只用于展示 `verdict`/`reasons`，不进 PASS/FAIL 断言。故只依赖 `main.go:74-77` 与判定分支。
- 6 代 v2 链：锚行自带 `hash_version: 2` 与 `evidence`（`rsi-bridge.service.ts:506-519`），Spec §0.3 禁止改历史账本/anchor/`hash_version`；`app.ts` 只增 `rules` 字段（`:155`），不写 DB、不写账本。已核实本轮 `git status` 中 `krsi/main.go`、`rsi-bridge.service.ts`、`ledger-verify.ts`、`judge/criteria.ts`、`judge/types.ts`、`krsi-conformance.ts` 均无改动；`manifest-builder.ts` 仅 `:12` 注释（Spec §0.2 允许）；`judge/eval-rate.ts` 的改动只增加 4 个展示用元数据字段，其注释明示「不进 RsiManifest 与 anchor 原像」，不影响判据指纹。

**被遗漏的耦合点（Spec §0 红线未点名，仅靠 §4 文件边界隐式冻结）**

- `rsi-bridge.service.ts:692-740` 是报告文案的镜像消费者，且**同一份报告里混用了两种冒号**。`extractReasons` 依赖中文标记 `理由：`（`:698`，全角 `：` U+FF1A，与 `main.go:589` 一致）、`锚定`/`边界`/`退出码`（`:708`）与 `（无 —— 全部指标严格变好）`（`:701`），兜底用 `/(R[1-6]:[^\n]+)/g`（`:717`，半角 `:` U+003A）。已逐行核验 `main.go:510,513,516,521,530,535` 的 `R*:` 前缀全部是**半角** U+003A，因此契约 `reasonRuleIdPattern: '^(R[1-6]):'`（`rules-contract.ts:259`）能命中真实 reason 串，AC-06 / C8 的染色口径成立；而 `main.go:589` 的 `理由：` 与 `main.go:582` 的指标行是**全角** U+FF1A。
- 由此暴露一处**既存的静默失配**：`extractMetrics` 正则（`:727`）用半角 `:`，`main.go:582` 输出的是全角 `：`。已实测同一条真实报告行 `  · tool_success_rate：0.5 → 0.8（变好=true）` 对该正则恒返回 `null`，改成半角才命中。故 `result.metrics` 恒为 `undefined` → `appendAnchor:487` 恒写 `metrics: []`、`recordRun:594,609` 恒写 `metrics_json=null`。这不是本轮引入的偏差，也不影响历史 6 代链（证据原像自带），但它是"报告文案 ↔ 解析器"耦合的实证：若后续有人在对齐过程中"顺手统一冒号"或改写理由措辞，新代锚行的 `evidence` 形状与 `reasons_json` 会变，AC-06（`reasons[]` 含 `R2:` 染色，数据链路 `app.ts:125-127` → `rsi-dashboard.html:462`）对新数据失效，而历史链因证据自带仍绿、`rsi:verify` 不会报警 —— 典型沉默逻辑错误。反之，若把 `R*:` 前缀误改成全角，契约的 `reasonRuleIdPattern` 与两处 `ruleIdFromReason`（`rsi-rules.ts:264-273`、`rsi-dashboard.html:320-326`）会同时失配。`rsi-code-fix-dashboard.html:88` 的 `R5：目标已达上限` 是全角，但那是冻结的静态展示文字、不参与染色，Spec §0.6 已豁免。
- `parseExitCode`（`:624-632`）决定 `evidence.verdict`/`exit_code`（`appendAnchor:484-500`）；`canonicalJson`（`ledger-verify.ts:72-93`）是 v1/v2 哈希复算的唯一规范化实现，改它会使**全部**历史锚行报 `anchor_hash_mismatch`（`:229-235`）。
- 因此本 ADR `## Decision` 第 5 点把零改动清单扩展到上述模块；只写"main.go + manifest-builder + API 字段"不足以描述承重面。

- **另一处会静默破坏绑定的耦合**：`rules-contract.ts:13` 运行时 import 的 `DEFAULT_L0_THRESHOLDS`，正是 `criteriaFingerprint()` 的默认输入（`manifest-builder.ts:195,215`）与 `buildManifest` 的 `criteria_sha256` 来源（`:366`），进而决定 `main.go:246-264` 的 R2 判定。Spec §0.2 只护住 `manifest-builder.ts` 的**运行逻辑**，没有护住位于 `judge/criteria.ts:23-27` 的**输入常量值**。Spec §6 第 7 项断言「契约 `thresholds` == `criteria.ts:23`」是自指的——契约本就是该常量的只读投影，常量一改两边同变、门禁仍绿；AC-09 的 `rsi:verify`/conformance 跑历史数据也仍绿，而**新代**因 `criteria_sha256` 变化且无 `criteria_diff` 被 R2 拒收，`rsi-code-fix-dashboard.html:102` 记录的指纹 `8d567e31d8983049…`「逐代一致」不再成立。注：`COVERAGE_THRESHOLD`（`judge/types.ts:162`）不在 `criteriaFingerprint` 的 descriptor 内（`manifest-builder.ts:207-209` 只取 `effective` 的 3 个键），改它不影响 R2 指纹，风险等级低于前者。

> **阻断项 B（契约安全 / 数据完整性破坏）**：Spec §6 第 7 项的等值校验自指，无法检测 Spec §0.2 自己声明为最危险的变更（判据集指纹变化）；AC-09 的回归项同样只覆盖历史数据，三者叠加可让"新代被 R2 拒收"在全部门禁绿灯下发生。
> **期望**：把 `DEFAULT_L0_THRESHOLDS`（`judge/criteria.ts:23-27`）与 `COVERAGE_THRESHOLD`（`judge/types.ts:162`）的值显式列入 Spec §0 红线；增固定指纹回归断言，钉死 `8d567e31d898304983333702028601466582a2b370d996e93643de8c92b4616d`（前缀见 `rsi-code-fix-dashboard.html:102`，后端已机器核验该值属实）；AC-09 显式纳入 `npm run check:rsi-contract` exit 0。
>
> **固定指纹断言的落点（后端反馈，已采纳）**：不得放进 `server/tests/rsi-rules-contract.test.ts` —— 该测试单一职责是「契约取值与两端同源」，塞入 `criteriaFingerprint()` 会让它反向依赖 `manifest-builder.ts` 运行逻辑，而那正是 Spec §0.2 冻结、本阻断项要保护的对象。落点应为 QA 独占的 `server/scripts/check-rsi-contract.mjs`（Spec §4：QA 只报告不修产品代码），并在既有 `server/tests/judge-criteria.test.ts`（本就测阈值 / `resolveThresholds` clamp）或 `server/tests/rsi-manifest-builder.test.ts` 各补一条；契约测试保持纯净。
>
> **两层语义必须分开（后端反馈，已采纳）**：§6 第 7 项比的是「契约是否忠实投影运行时常量」，应随常量合法调整而通过，QA 不得硬编码 `0.6/0.5/0.9/0.6`（否则常量一调就假红）；新增固定值断言比的是「常量本身是否被意外改动」，应恒定。若把两层混成一条，QA 会无所适从。门禁最小项第 7 项已按 7a / 7b 拆开。

### 评审点 5 — 依赖风险：循环依赖、初始化顺序、CJS 单文件桌面态

**结论：无循环依赖、无初始化顺序问题；CJS 单文件桌面态仍成立。有 1 条硬约束与 1 条时间耦合需登记。**

- **依赖图**：`rules-contract.ts:13-14` → `judge/criteria.ts:23` 与 `judge/types.ts:162`；`judge/criteria.ts:12` 是 `import type`（运行时擦除，无运行时边）；`judge/types.ts` 全文无 import（已核）；`server/src/services/judge/` 对 `rsi/*` 只有注释与字符串提及、无 import（已核）；`app.ts:21` → `rules-contract.js`。**无环**。
- **初始化顺序**：`DEFAULT_L0_THRESHOLDS`（`criteria.ts:23-27`）与 `COVERAGE_THRESHOLD`（`types.ts:162`）都是顶层字面量 `const`，无 env 读、无 IO、无 `import.meta`；`buildRsiRulesContract()` 只在请求时被调用（`app.ts:104,155`），远晚于模块求值，无 TDZ。`manifest-builder.ts:215` 的 `CRITERIA_FINGERPRINT = criteriaFingerprint()` 在模块加载时读同一常量，但其 `:20` 静态 import 保证 `judge/criteria.js` 先初始化；新增一个 importer 不改变该序。
- **CJS 单文件**：`desktop/scripts/bundle-server.mjs:32-46` 用 esbuild `format:'cjs'`、`bundle:true` 把 `server/dist/app.js`（tsc `nodenext` 产物）打成单文件。`rules-contract.ts` 全文无 `import.meta` / `process.env` / 动态 `import()` / `require(` / 文件 IO（已核），只有静态 import 与字面量；`bundle-server.mjs:12-16` 记录的「`import.meta.url` 在 CJS 产物中为空」「`env.ts` 顶层读 `process.env` 的顺序约束」对本模块均不触发。`judge/types.ts`/`criteria.ts` 本就在包内（被 `manifest-builder.ts`、`judge.service.ts` 引用），新增 importer 不引入新模块或新初始化顺序约束。**成立**。
- **硬约束**：`authority`（`rules-contract.ts:86`）与逐条 `anchor`（如 `:100,:112`）必须是编译期字符串字面量。一旦改成 `import.meta.url` / `process.cwd()` / `fileURLToPath` 运行时路径推导，桌面 CJS 态立即产出错误锚点或直接抛错。应写入契约注释并加静态门禁断言。
- **时间耦合（advisory）**：`DEFAULT_L0_THRESHOLDS` 是 `const` 但对象属性可变；`buildRsiRulesContract()` 在**请求时**读它，而 `CRITERIA_FINGERPRINT` 在**模块加载时**读它。当前无人改写该对象（`resolveThresholds` 返回新对象，`criteria.ts:47-51`），无实害；若未来引入运行时阈值自调，契约展示值与判据指纹会在时间上分叉。阻断项 B 的固定指纹断言可同时钉死这条。

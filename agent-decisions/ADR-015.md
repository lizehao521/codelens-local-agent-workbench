# ADR-015: MCP 接入采用 @modelcontextprotocol/client 2.3.1（v2 稳定线）stdio transport，按需启动与故障隔离

## Status: Accepted (2026-10-21)

## Background
用户要求接入 MCP 生态（本机 MCP Server）。需要决定 SDK 版本、transport 形态、Client 生命周期、以及 MCP 故障时对整体的影响边界。

版本核实（npm registry，2026-10-21）：
- `@modelcontextprotocol/client` **2.3.1**（2026-10-05 发布；v2.0.0 于 2026-07-27 发布，v2 为**当前稳定线**，实现 MCP spec 2026-07-28；`engines.node >= 20`）。
- `@modelcontextprotocol/sdk` **1.32.1**（v1 旧线；官方说明 v1 在 v2 发布后至少 6 个月内继续收 bugfix 与安全更新）。
- v2 已把单体包拆分为 `@modelcontextprotocol/client` 与 `@modelcontextprotocol/server`。

Client API（官方文档逐条核实）：
```ts
import { Client } from '@modelcontextprotocol/client';
import { StdioClientTransport } from '@modelcontextprotocol/client/stdio';
const client = new Client({ name, version });
const transport = new StdioClientTransport({ command, args });
await client.connect(transport);
const { tools } = await client.listTools();
const result = await client.callTool({ name, arguments });
await client.close();
```

## Decision
1. **选用 `@modelcontextprotocol/client` 2.3.1**（v2 稳定线），不选 v1 的 `@modelcontextprotocol/sdk`。
2. **transport 只做 stdio**（本机 MCP Server）。本期不接 HTTP/SSE remote transport。
3. **按需启动**：不预启动任何 MCP Server。用户在面板配置后，首次需要其工具时才 `connect()`。
4. **连接复用**：`connected` 状态下所有工具调用复用同一 Client/Transport，不重复握手。
5. **健康策略**：不每次调用前发探测包（省往返）；改为**空闲 30 分钟自动断开** + 调用失败即判定不可用 + 用户可手动「重新连接」。
6. **listTools 并入注册表**：连接成功后取 `{ tools: [{name, description, inputSchema}] }`，适配为 `ToolDefinition`（补 `risk`/`approvalMode`/`timeoutMs`/`maxResultChars`/`displayName`/`category`），以规范名 `mcp.<serverId>.<name>` 注册，线上名由消毒规则生成（见 ADR-014）。
7. **故障隔离（硬要求）**：
   - 连接失败 → 该 Server 的工具**不注册**，内置工具完全不受影响。
   - 调用失败 → 产出 `tool_error(MCP_CALL_FAILED, retryable=true)`，作为 observation 回喂 LLM，**Agent 循环不中断**。
   - 同一 Server 连续失败 3 次 → 标记 `unhealthy`，其工具从 `toProviderTools()` 移除（LLM 看不到），**不影响其他 MCP Server，不影响内置工具**。
8. **只接 tools 能力**：resources / prompts / sampling 本期不接。
9. **MCP 工具结果归一化**：`callTool` 返回 `{ content: [{type:'text',text}], isError? }`。`isError=true` → `ToolOutcome{ok:false, errorCode:'MCP_TOOL_ERROR'}`；多个 text block 用 `\n` 拼接；非 text block 只保留类型与大小，不把二进制塞进上下文。

## Consequences
正面：v2 是当前稳定线，长期维护有保障；stdio 是本机 MCP 的标准形态，实现简单；按需启动不拖慢服务启动；故障隔离保证 MCP 是「可插拔增强」而非「单点依赖」；MCP 工具与内置工具在上层完全同构。
负面：v2 较 v1 是破坏性变更（包名与导入路径不同），若 v1 生态插件不兼容需写适配；只做 stdio 意味着远程 MCP Server 暂不支持；MCP Server 是本机任意程序，**运行它等于授予本机用户权限**——这是无法技术性根除的固有信任边界（见 ADR-019）。
